# Morimens.Info.kr 디자인 시스템

이 문서는 사이트 전반의 시각 언어와 상호작용 규칙을 정의한다. UI 작업 전 반드시 함께 읽어야 하는 반응형 규칙은 [`responsive-design.md`](responsive-design.md)에 있다.

## 1. 제품 원칙

1. **사용자의 질문을 먼저 답한다.** 화면은 저장된 필드를 나열하는 곳이 아니라, 사용자가 비교하고 결정하도록 돕는 곳이다.
2. **핵심 정보는 즉시, 세부 정보는 요청 시 제공한다.** 이름·등급·핵심 효과·현재 선택은 먼저 보이고, 긴 표와 기록은 공통 disclosure 안에 둔다.
3. **서로 다른 성장축을 섞지 않는다.** 강화, 돌파, 레벨, 연구 깊이처럼 계산 방식이 다른 개념은 별도 제목과 조작부로 구분한다.
4. **강조는 희소하게 사용한다.** 한 정보 묶음에서 강조색은 현재 선택 또는 가장 중요한 결과 하나에만 사용한다.
5. **같은 행동은 같은 모양으로 보인다.** 접기, 탭, 단계 선택, Dialog 닫기 등은 페이지가 달라도 같은 상태 표현과 키보드 동작을 사용한다.

## 2. 정보 위계

상세 화면의 기본 읽기 순서는 다음과 같다.

1. 정체성: 이미지, 이름, 등급
2. 핵심 판단 정보: 주옵션, 대표 수치, 현재 선택
3. 투자 비교: 강화 표 또는 돌파 단계
4. 상세 설명: 효과, 조건, 획득처
5. 보조 정보: 추천 대상, 태그, 출처

같은 내용을 요약과 본문에서 반복하지 않는다. 양끝 정렬로 관련된 라벨과 값을 멀리 떼어놓지 않는다.

주옵션 요약은 `옵션명 수치`를 같은 줄에 붙여 표시한다. `0강`, `15강`, `풀강` 같은 성장 단계 표기는 요약에 섞지 않고 단계별 표 안에서만 제공한다.

## 3. 색과 강조

- 기본 배경은 기존 어두운 surface 토큰을 사용한다.
- 본문은 `--color-text-primary`, 보조 설명은 `--color-text-muted`를 사용한다.
- 강조색 `--color-accent`는 현재 선택, 최종 핵심값, 주요 링크에만 사용한다.
- 선택 상태를 누런 면으로 채우지 않는다. 기본 표면을 유지하고 강조색 글자, 테두리 또는 2px 표시선으로 표현한다.
- 표의 모든 숫자를 강조하지 않는다. 비교의 종착점처럼 실제로 중요한 셀만 강조한다.
- 포커스 링과 선택 표시는 구분한다. 키보드 포커스는 항상 별도의 외곽선으로 남긴다.

## 4. 간격과 표면

- 기본 간격 단위는 4px이며, 주로 8·12·16·24·32px를 사용한다.
- 같은 표면 안에 의미 없는 중첩 카드를 만들지 않는다.
- 테두리는 정보 묶음이나 조작 가능한 영역을 구분할 때만 사용한다.
- 관련된 라벨과 값은 시선이 한 번에 묶을 수 있는 거리 안에 둔다.
- 모서리 반경은 기존 `--radius-sm`, `--radius-md`, `--radius-lg` 토큰을 사용한다.

## 5. 타이포그래피

- 페이지 제목, 섹션 제목, 항목 이름, 본문, 보조 설명의 순서로 크기와 명도를 낮춘다.
- 숫자만 불필요하게 크게 만들지 않는다. 비교 대상끼리는 같은 크기와 기준선에 둔다.
- 본문은 줄임표로 숨기지 않으며 `word-break: keep-all`과 안전한 줄바꿈을 함께 고려한다.
- 용어는 사용자 언어를 따른다. 명륜 효과는 `명함·1돌·2돌·3돌`, 주옵션 성장은 `0강~15강`으로 구분한다.

## 6. 선택기와 탭

- 서로 배타적인 2~5개 선택에는 segmented control을 사용한다.
- 선택 버튼은 `aria-pressed` 또는 적절한 탭 시맨틱을 사용한다.
- 최소 터치 높이는 44px을 우선하며, 공간이 제한되어도 40px 아래로 줄이지 않는다.
- 선택 상태는 강조색 글자와 테두리/표시선으로 나타내며 면 채우기에 의존하지 않는다.
- 선택기 외곽선과 항목 구분선이 이미 경계를 설명한다면, 선택 상태에는 글자색만 사용하고 별도 밑줄이나 내부 테두리를 더하지 않는다.
- 선택이 콘텐츠 수치를 변경한다면 조작부 바로 아래에 무엇이 바뀌는지 짧게 설명한다.

연속적이거나 단계가 많은 숫자를 빠르게 탐색할 때는 현재 값을 함께 보여 주는 슬라이더를 사용한다. 모든 단계의 정확한 비교가 필요하면 표를 병행하되, 슬라이더는 즉시 노출하고 전체 표만 접을 수 있다.

## 7. 접기와 펼치기

- 모든 native `details/summary`에는 `site-disclosure` 클래스를 사용한다.
- 닫힘은 오른쪽을 향하는 꺾쇠, 열림은 아래를 향하는 꺾쇠로 표시한다.
- summary 전체가 클릭 영역이며 최소 높이는 44px이다.
- 브라우저 기본 marker, `+/-`, `▶/▼` 등 별도 표현을 섞지 않는다.
- 핵심 정보는 접지 않는다. 긴 표, 과거 기록, 고급 설정처럼 보조적인 내용만 접는다.

## 8. 표

- 정확한 단계별 값처럼 행과 열 비교가 필요한 데이터만 표로 표시한다.
- 열 제목은 짧고 반복 가능한 용어를 사용한다.
- 좁은 화면에서는 먼저 열 수를 줄이고, 불가피할 때만 표 컨테이너 내부 가로 스크롤을 허용한다.
- 행 머리글에는 `scope="row"`, 열 머리글에는 `scope="col"`을 사용한다.
- 핵심값 하나를 제외한 셀은 기본 본문색을 사용한다.

## 9. Dialog와 모바일 바텀시트

- Dialog 상단은 이미지, 이름, 등급만 담는다.
- 정체성 정보는 이미지 옆에 이름과 등급을 가까이 묶어 한 번에 읽히게 한다. 빈 공간을 채우기 위해 관련 정보를 양끝으로 벌리지 말고, 정보량이 적다면 헤더 자체의 높이와 너비를 줄인다.
- 본문은 핵심 판단 정보부터 배치하고 긴 보조 정보는 아래로 보낸다.
- 닫기 버튼은 최소 44×44px이며 항상 같은 우측 상단 위치를 사용한다.
- 닫기 버튼의 터치 영역과 보이는 크기는 분리할 수 있다. 터치 영역은 44×44px을 유지하되 원형 테두리와 X는 주변 정보보다 강하게 시선을 끌지 않도록 작게 표현한다.
- 좁은 화면에서는 동일한 Dialog를 하단 정렬 바텀시트로 전환하되 DOM 순서와 기능은 유지한다.
- 내부 스크롤만 허용하고 페이지 수준 가로 스크롤은 만들지 않는다.

## 10. 구현 전 점검

- 사용자가 이 화면에서 답을 얻으려는 질문을 한 문장으로 썼는가?
- 가장 먼저 보여야 할 정보가 실제로 첫 화면에 있는가?
- 같은 개념을 중복 표시하거나 서로 다른 개념을 한 선택기에 섞지 않았는가?
- 기존 공통 컴포넌트와 토큰을 재사용했는가?
- 강조색을 한 묶음에 둘 이상 남발하지 않았는가?
- 키보드, 터치, 200% 확대와 필수 반응형 너비를 검증했는가?
