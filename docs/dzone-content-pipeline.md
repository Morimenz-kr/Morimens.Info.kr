# 융재금구 데이터 갱신하기

생성 도구와 원본 참조·계산식의 세부 유지보수 문서는 개인 도구 묶음에서 관리한다. 먼저 [비공개 데이터 도구 사용하기](private-data-tools.md)에 따라 도구와 원본 자료를 준비한다.

1. 개인 도구 묶음의 동일 이름 문서를 읽고 실제 Skill/State/Cmd 참조를 기준으로 데이터를 재생성한다. 생성 JSON을 직접 보정하거나 한국어 이름만으로 효과를 연결하지 않는다.
2. 생성 진단과 경고를 검토하고, 검증된 전투 구성·능력치를 보존한다. 해당 시즌의 원본과 비교하고 비공개 도구의 회귀 검사를 실행한다.
3. 공개 저장소의 테스트·데이터 검사·배포 아티팩트 생성을 실행한다. 화면이나 툴팁을 변경했다면 화면 및 반응형 검증도 수행한다.
4. 검증된 결과만 반영한다. 원본과 도구를 공개 커밋이나 배포 폴더에 포함하지 않는다.

## 단계 컨텍스트가 몬스터 행동을 바꾸는 경우

- `StageGroup.StageChapterState`에서 시작해 `State → TriggerCmd → BEAddState`를 추적한 뒤 몬스터의 `Judgement`와 명령 `Cond`를 판정한다.
- `ShowType: Hide`인 단계 상태는 사이트에 별도 효과로 노출하지 않는다. 대신 그 상태 때문에 확정되는 실제 의도, 최초 발동 턴, 반복 여부를 표시한다.
- 현재 단계에서 거짓이 되는 대체 의도는 표시하지 않는다.
- 파동 번호, 몬스터 TID, 한국어 이름으로 예외 처리하지 않는다. 참조 그래프, 대상(`PlayerRole` 등), 상태 스택 조건, 트리거 시점으로 판정한다.
- 시즌 전체의 모든 파동과 소환 몬스터까지 같은 검사를 실행하고, 미해석 조건은 생성 진단에서 0건인지 확인한다.

## 시즌 교체 시 몬스터 행동 누락 감사

새 융재금구 데이터로 교체할 때는 표시된 스킬 목록만 비교하지 말고, 모든 파동의 일반·엘리트·보스·소환 몬스터를 대상으로 원본 참조 그래프와 생성 결과를 대조한다.

1. `MonsterConfig.InitSkillList`와 모든 `CycleSkillListN`의 순서·중복·반복 구성이 생성 결과와 정확히 일치하는지 검사한다.
2. 각 몬스터의 최초 상태와 패턴 스킬에서 `State → TriggerCmd → Cmd → Skill/State` 참조를 끝까지 추적한다.
3. 다음 행동 유형을 별도 감사한다.
   - 조건부 의도·스킬 변경: `BEMonsterChangeSkill`, `BEMonsterChangeSkillList`
   - 즉시 행동·후속 행동: `BEForceExecSkill`, `BEAttachPostAction`
   - 상태 부여로 시작되는 추가 규칙: `BEAddState`
   - 소환·부활·단계 전환: `BESummonMonster`, `BEPVERebirth`
4. 발동 조건, 최초 발동 턴, 지속·반복 여부, 대상, 교체되는 의도와 후속 행동이 사이트 본문 또는 연결된 키워드 툴팁 중 한 곳에 실제 인게임 문구로 제공되는지 확인한다.
5. 상위 스킬·상태 설명이나 키워드 툴팁에 같은 의미가 이미 있으면 중복 표시하지 않는다. 이름이 있다는 이유만으로 설명이 제공된 것으로 간주하지 않는다.
6. 단계 상태와 명령 조건을 실제 `StageGroup` 컨텍스트로 판정하여 현재 시즌에서 거짓인 분기는 제외한다. 한국어 이름이나 특정 몬스터 TID로 예외 처리하지 않는다.
7. 검사 결과는 최소한 다음 조건을 만족해야 한다.
   - 패턴 순서 불일치 0건
   - 활성 조건부 행동의 미표시 0건
   - 미해석 조건 0건
   - 소환 대상과 교차 대상 행동의 미연결 0건

비공개 데이터 도구 묶음의 시즌 행동 감사 도구를 실행해 후보를 생성한 뒤, 후보마다 원본 상태 설명과 명령 조건을 확인하여 `실제 누락`, `상위 설명·툴팁에 포함`, `현재 단계에서 비활성`, `내부 표식`으로 분류한다. 후보 수가 0이라는 사실만으로 검사를 끝내지 말고 위 통과 조건을 생성 진단과 회귀 테스트로 보장한다.
