# 스테이지별 전투 구성 화면

사용자가 요청한 방향은 진행 중인 융재금구 정보의 전투 구성처럼 다른 콘텐츠의 전투도 확인하는 것이다. 사용자가 콘텐츠와 난이도, 스테이지를 고르면 그 장소에 등장하는 적 편성과 상세 정보를 보여준다. 아래 탐색과 표시 방식은 구현 전 구성안이다. 데이터 범위와 현재 확인된 수치는 [전투 콘텐츠별 적 정보 범위](enemy-content-scope.md)를 따른다.

## 콘텐츠에서 전투로 이동

기본 탐색 순서는 콘텐츠 선택, 장·이벤트·시즌 선택, 난이도 선택, 스테이지 선택, 전투 구성 확인이다. 콘텐츠에 존재하지 않는 선택 단계는 생략한다.

| 콘텐츠 | 선택 단계 |
|---|---|
| 스토리 | 편과 장 → 난이도 → 스테이지 |
| 개인 스토리 | 캐릭터와 외전 → 난이도 → 스테이지 |
| 이벤트 | 이벤트 → 실제 제공되는 난이도 또는 도전 단계 → 스테이지 |
| 융재금구 | 시즌 → 금지구역 → 경보 단계 |
| 환몽 심잠 | 실제 모드 → 스타일 또는 난이도 → 구간과 출현 후보 |
| 재료와 장비 | 던전 → 단계 |
| 주간 보스 | 보스 → 난이도 또는 단계 |
| 무광의 영역 | 층과 계역 → 구간 |
| 체험과 훈련 | 대상 각성체 또는 훈련 → 전투 |

진행 중인 융재금구 정보는 현행 시즌으로 바로 들어가는 기존 진입점으로 유지하는 안이다. 다른 콘텐츠까지 모두 융재의 시즌·경보 구조에 맞추지 않는다. 새 페이지 이름과 메뉴 위치는 아직 정하지 않았다.

## 전투 구성과 적 상세

현재 융재 화면은 일반·엘리트·보스 전투별로 적 카드를 묶는다. 적 카드에는 초상과 이름, 분류와 종족, HP와 여러 체력바, 상성 각성체, 고유 규칙, 행동 순서, 조건부 행동과 소환 정보를 표시한다. 다른 콘텐츠도 같은 읽기 순서를 사용하되 상세 값은 선택한 스테이지의 조건에서 생성한다.

표시 구조의 예시는 다음과 같다. 실제 게임 데이터를 넣은 예시가 아니다.

```text
콘텐츠 / 장 또는 이벤트 / 난이도 / 스테이지

스테이지 공통 규칙

일반 전투 구성 1
  적 A × 2
    초상과 이름, HP, 고유 규칙, 행동 순서
  적 B × 1
    초상과 이름, HP, 고유 규칙, 행동 순서

엘리트 전투 구성 1
  적 C
    조건부 행동
    소환되는 적과 등장 조건

보스 전투
  보스 D
    체력바, 페이즈 전환, 행동과 소환
```

같은 종류의 적 여러 개체를 묶어 표시할 때는 개체 수를 명시한다. 능력치나 상태가 다른 개체는 별도 카드로 표시한다. 초기 배치 적과 소환으로 등장하는 적을 구분하고, 소환 적은 소환 주체 아래에서 확인할 수 있게 한다.

동일한 스테이지의 여러 노드가 같은 편성을 쓰면 전투 구성은 한 번 보여주고 해당 노드들을 연결하는 안이다. 무작위 콘텐츠는 가능한 편성을 각각 표시하며, 출현 조건과 확률이 확인되기 전에는 모든 편성이 확정 등장한다고 표현하지 않는다.

## 공통 표시와 콘텐츠별 계산

융재의 적 카드와 전투 구성 표현은 공통화 후보지만, 현재 코드의 시즌·파동·경보 조회를 다른 콘텐츠의 수치 계산에 그대로 사용하면 안 된다. 스테이지별 기본 능력치, 난이도 선택, 초기 상태, 전투 중 보정과 소환 시점의 수치를 계산한 뒤 표시 계층에 전달한다.

HP, 행동 패턴과 조건부 행동을 융재 수준으로 제공하는 것이 상세 정보의 목표다. 공격력·방어력·레벨의 추가 표시는 계산 검증과 읽기 밀도를 함께 확인한 뒤 결정한다. 표시 근거가 없는 수치를 0이나 기본값으로 채우지 않는다.

기존 융재의 검증된 능력치와 설명은 유지한다. 효과와 툴팁의 공통화는 실제 Skill·State·Cmd 참조를 기준으로 하며 [콘텐츠 갱신 규칙](dzone-content-pipeline.md)과 [게임 키워드 규칙](game-keywords.md)을 따른다.

## 좁은 화면에서의 읽기 순서

모바일은 선택 컨트롤, 스테이지 규칙, 전투 구성, 적 상세 순서로 읽는다. 전투 목록은 접고 펼칠 수 있게 하며 긴 적 설명을 잘라내지 않는다. 적 카드의 열 수를 먼저 줄이고 화면 폭 때문에 글자를 지나치게 작게 만들지 않는다. 지도는 전투 정보를 찾는 보조 탐색으로 두고, 지도 없이도 모든 편성에 접근할 수 있게 한다.

실제 화면 구현에는 [반응형 지침](responsive-design.md)을 적용한다. 320px, 360px 또는 390px, 768px, 1024px, 1280px 및 변경한 분기점 전후를 확인하고, 200% 확대와 터치·키보드 조작을 검증한다. 이 구성안은 렌더링된 화면이나 반응형 검증 완료 결과가 아니다.

## 출시 범위와 검증 단계

전체 설정을 추출 대상으로 두되 공개 목록은 한국 서비스의 실제 출시·개방 여부를 판정한 뒤 구성한다. 미출시와 테스트 설정은 사용자 목록에서 제외한다. 현재 클라이언트만으로 과거 등장 이력을 입증할 수 없는 콘텐츠는 보관 자료와 대조한다.

진행 순서는 전체 콘텐츠 연결 색인, 누락된 이벤트·무작위·소환 경로, 스테이지별 능력치와 행동 검증, 공통 전투 표시, 콘텐츠별 화면 검증이다. 첫 화면 검증은 구조가 단순한 재료 던전과 스토리 일반·하드의 대표 스테이지부터 시작하는 안이다. 대표 사례 통과와 전체 콘텐츠 검증 완료를 구별해서 기록한다.
