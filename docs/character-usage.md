# 각성체 사용 현황 데이터 규격

각성체 공략의 ‘사용 현황’은 수집된 출전 기록을 탐색하는 화면이다. 수동 추천 세팅을 통계로 변환하거나 누락된 장비를 추천 값으로 채우지 않는다.

## 수집 경계

게임 연결, 클리어 원본 수집, 중복 제거와 공개 ID 매핑은 비공개 `morimens-data-extractor`의 책임이다. 공개 저장소는 정제된 익명 구성의 수신·검증·조회·표시를 담당한다. 인증 토큰·UID·닉네임·리플레이 코드·원본 응답은 공개하지 않는다.

클리어 1건의 장비·옵션·완성도 연결 검증을 마친 뒤, 현재 기수의 5구역 × 7난이도 공개 목록 전체로 수집 범위를 확장했다. 초기 구역·난이도별 10건 제한은 적용하지 않는다. 무작위 표본이라고 부르지 않는다. 최신순으로 수집했다면 `source`에 ‘최신 클리어 표본’이라고 표시한다. 같은 유저의 다른 클리어는 별도 건이며, 유저 사용률 또는 승률로 해석하지 않는다.

## 조회·수신

- `GET /api/dzone/character/{characterId}/usage`: 가장 최신 기수와 사용 가능한 `periods`.
- `GET /api/dzone/character/{characterId}/usage?period=71`: 지정 기수.
- `POST /api/dzone/character/{characterId}/usage`: `Authorization: Bearer <DZONE_INGEST_TOKEN>`으로 인증한 해당 기수 스냅샷 교체. 증분 가산이 아니다.
- 데이터 미수집은 404, 저장소 미설정은 503. 브라우저는 둘을 구분한다.
- 기존 `RESOURCE_LINK_STATE`의 별도 `dzone:character-usage:v1:` 접두사를 사용한다. 기존 채용률·제한 클리어 API는 변경하지 않는다.

## 구역별 편성과 세팅 연결

- 융재 정보의 파티별 ‘세팅 보기’는 기수·구역·난이도·각성체 4명의 stable ID를 `links.html`로 전달한다. 캐릭터별 파티 카드도 같은 클리어 세팅 목록으로 연결한다.
- 클리어 세팅은 네 명의 명륜·계약이 공개된 기록을 기본으로 보여준다. 미공개 기록도 필터를 해제하면 확인할 수 있다. 펼치기 전 잠재력·지원 여부·공개 장비 인원·계약 완성도를 표시한다.
- ‘파티 잠재력’의 명함~3돌 이하 필터는 네 명 전원의 수집값이 해당 범위에 있는 기록만 남긴다. 4단계 이상 값을 임의의 돌파로 환산하지 않으며, 미수집도 제외한다. 명륜 돌파는 현재 수집되지 않았다. 강화와 돌파를 구별한다.
- 계약 완성도 90%는 옵션 분포의 집계 기준이다. 클리어 세팅 선택·보관의 필수 조건으로 적용하지 않는다.
- `morimens_dzone_plan_v1` 로컬 저장소는 한 기수의 구역별 실제 클리어 세팅을 보관한다. 다른 구역의 각성체·명륜 중복은 허용하지 않으며 비밀계약 중복은 허용한다. 기존 구역 교체는 별도 확인을 거친다. 다른 기수 편성이 남으면 먼저 비워야 한다.
- ‘다른 구역에 담은 각성체·명륜 제외’는 클리어 세팅 목록의 대안을 찾는 필터다. 각 구역을 따로 저장한 기록이므로 5개 파티가 동일 유저의 연속 클리어였다는 뜻은 아니다.
- ‘편성기에서 보기’는 기존 `party_builder.js` 페이지·팀 렌더러와 선택기를 사용한다. 기존 페이지를 유지하고 기수별 페이지에 구역 1~5를 배치한다. 페이지가 가득 차면 덮어쓰지 않는다. 편성기에서 수정한 각성체·명륜을 가져온 세팅으로 바꿀 때는 기존 시스템 확인창을 사용한다.
- 명륜 ID와 각성체 ID는 편성기 카탈로그에 대조한다. 계약·옵션 원본은 각 팀의 `usageSource`에 함께 저장한다. 새로고침 시 같은 검증기를 통과한 원본만 복원한다. 은열쇠는 수집하지 않았으며 사용자가 따로 선택한다.
- 편성기에서 장비를 바꾼 경우 계약·옵션은 원본 클리어 기록임을 표시한다. 사용자가 바꾼 장비에 맞춰 옵션을 자동 추천하지 않는다.

공유 구현: `js/usage-plan.mjs`는 저장·중복 검사·원본 링크, `js/character-usage-view.mjs`는 네 명의 장비·계약·옵션 렌더링, `js/usage-plan-builder.mjs`는 기존 편성기 어댑터를 담당한다. 별도 선택기나 복제한 편성기를 만들지 않는다.

## 스냅샷 필드

| 필드 | 형식과 의미 |
|---|---|
| `schemaVersion` | 기본 형식 `1`, 반복 구성을 공유하는 전송 형식 `2` |
| `characterId` | manifest의 stable ID |
| `period` | 실제 수집 기수, 양의 정수 |
| `collectedAt` | 집계 기준 Unix 초. 이 시각 이후 새 기록은 제외하며 표시 갱신 시각으로 덮어쓰지 않음 |
| `coverage` | `sample` 또는 수집 범위 전체인 `complete` |
| `source` | 수집 범위·선정 방식을 설명하는 공개 문구 |
| `rows` | 최대 100,000개 익명 구성. 전체 요청 최대 24MB |

각 row는 `wave`(1~5), `difficulty`(`1`~`7` 또는 기존 `normal/hard/nightmare/madness`), `count`(같은 구성인 클리어 수), `members`(1~4명)를 가진다. 화면에서는 wave를 ‘금지구역’, 값을 ‘1구역’으로 표시한다. 상세는 ‘제1금지구역’이다.

각 member는 다음을 가진다.

| 필드 | 의미 |
|---|---|
| `characterId` | manifest ID. 매핑이 확인되지 않으면 송신 전 중단 |
| `enlightenment` | 수집한 실제 돌파 단계 정수, 미확인은 `null` |
| `borrowed` | 실제 지원 여부, 미확인은 `null` |
| `wheels` | 실제 장착한 0~2장의 `[{id, level}, ...]`. 미수집은 `null`. level 미확인은 `null` |
| `covenant` | `{completion, parts}` 또는 미수집 `null` |

`completion`은 **게임에서 확인한 완성도 백분율**(0~100), 미확인은 `null`이다. 옵션을 보고 임의의 완성도 공식을 만들지 않는다. 여섯 `parts`는 slot(1~6), setId(covenant_list의 english_name), main, subs를 가진다. 모든 옵션은 `{id, label, value, unit}` 형식이며 unit은 `%`, `pt`, 빈 문자열 중 하나다. 부옵이 없는 부위는 빈 배열이다. 옵션 원본이 일부만 내려오면 완전한 계약처럼 보내지 않고 covenant를 null로 둔다.

## 집계 의미

- 팀: 각성체 ID 집합으로 묶는다. 배치 순서 차이는 합친다.
- 명륜: 실제 장착한 명륜의 ID 조합으로 묶고 강화 단계는 실제 구성에 보존한다.
- 계약: 여섯 부위의 세트별 개수 조합. 3+3 등 혼합 세트도 보존한다.
- 팀·명륜·계약 비율의 분모: 선택한 구역·난이도·돌파 등 조건의 각성체 출전 건수. 미수집 장비는 분모에서 몰래 제거하지 않는다.
- 특정 팀·장비 선택은 다른 모든 영역에도 적용한다. 현재 영역에서는 자기 필터만 풀어 다른 선택지를 비교할 수 있다.
- 옵션 분포의 분모: 현재 선택에 해당하며 완성도 90% 이상이고 6부위 옵션이 확인된 계약 건수. 90%는 포함, 미확인/89%는 제외한다.
- 부옵 비율: 그 부위에 해당 부옵을 가진 계약의 비율. 여러 종류를 가지므로 합계가 100%를 넘을 수 있다. 범위·평균은 count로 가중한다.
- 동일 부위에 같은 부옵이 여러 줄 들어올 수 있다. 원래 줄과 순서는 보존하고 분포에서는 그 계약을 한 번만 센다. 같은 종류·단위의 수치는 부위 안에서 합산한다.
- 사용 구성에는 90% 미만도 그대로 표시한다. 주옵·부옵의 합계는 같은 옵션 ID·단위끼리만 더한다.

원본 클리어 키는 비공개 수집기에서 stage+안정적인 battle ID로 중복 제거한다. 공개 row는 팀원 전원의 돌파·지원·장비·옵션과 구역·난이도가 완전히 같을 때만 count를 합친다. 이 데이터로 개별 유저 수나 승률을 계산하지 않는다.

## 기존 UI 재사용

진입점은 `links.html?category=character&id=...#usage`이다. `js/links.js`가 기존 캐릭터 탭과 도감 상세 다이얼로그(`openDictionaryDialog`, `#dictionary-detail-dialog`)를 유지하며 `js/character-usage.js`에 manifest·도감 데이터를 전달한다. 별도 장비 상세 팝업을 복제하지 않는다.

`usageDemo=1`은 명시적으로 선택하는 가상 데이터 모드다. 실제 GET·POST와 분리되고 페이지 전체에 예시임을 표시한다. 예시는 `js/character-usage-demo.mjs`에서만 생성하며 운영 `data/*.json`에 넣지 않는다.


## 연결 전 검사

수집기가 만든 익명 후보는 `node tools/validate-character-usage.mjs <후보.json>`으로 검증한다. 서버도 동일한 스키마와 현재 도감 ID를 검사한다. 게임 원본을 이 검증기에 직접 넣지 않는다. 비공개 수집기가 현재 클라이언트 필드와 공개 ID 사이의 검증된 어댑터를 제공하기 전까지 수집 완료로 간주하지 않는다.

동일 각성체·기수의 송신은 한 게시기에서 직렬 실행한다. 수신기는 전체 스냅샷을 교체하며 오래된 수집 시각은 거부한다. 인증·형식 검사 실패 시 마지막 정상 스냅샷을 유지한다.

## 실제 1건 연결 검증

2026-10-23, 게임 서버가 반환한 71기 제5금지구역 S등급의 저장된 클리어 구성 1건으로 검증했다. 기록의 팀에는 침식 · 로탄, 라이커, 릴리, 타비가 포함된다. 각성체 4명·명륜 8장·계약 24부위·주옵 24줄·부옵 72줄을 익명 구성으로 변환했다. 네 각성체의 조회용 스냅샷은 **같은 클리어 1건의 다른 관점**이며 서로 다른 4건이 아니다.

원본에는 완성도 필드가 직접 들어 있지 않았다. 부위 점수 24개를 게임 함수와 대조한 뒤, 전체 완성도는 `AwakerTrinketDataUtils.GetTrinketSuitCompletionRate`로 90% 경계를 포함한 실제 구성 12건을 다시 검증했다. 게임은 여섯 부위의 원점수를 합친 뒤 132로 나누고 소수 첫째 자리까지만 남긴다. 부위별 표시값을 먼저 버림 처리한 뒤 더하지 않는다. 침식 · 로탄의 검증용 계약은 97.3%로, 90% 이상 옵션 집계에 1건 포함된다. 나머지 세 각성체는 각각 65.5%, 60.2%, 77.6%이며 옵션 분포에서는 제외되고 실제 구성에는 남는다. 89.8% 또는 89.9%로 잘못 계산됐던 실제 90.1% 사례도 이 방식으로 포함된다. 잠재력 원본 단계 4 이상을 일반 ‘N돌’로 바꾸지 않는다. 난이도 원본 4는 현재 기수의 `gameGrade` S와 대조했다.

`workers/character-usage-preview.mjs`는 같은 조회 함수를 사용하는 읽기 전용 QA Worker다. 저장 키 앞에 `character-usage-qa:`를 붙여 운영 키와 분리한다. POST는 허용하지 않는다. `wrangler.character-usage-preview.jsonc`로 배포하며 실제 익명 스냅샷만 별도 KV 키에 게시한다. 원본 응답과 계정·장비 UID는 Git이나 Pages 아티팩트에 포함하지 않는다.

`links.html`은 QA Pages 호스트에서만 해당 읽기 전용 Worker를 사용한다. 운영 호스트는 기존 수신·조회 API를 사용한다. 이 단계는 1회 수집·게시 연결의 검증이며 자동·예약 수집이나 전체 클리어 수집 완료를 뜻하지 않는다.

## 전체 기수 전송과 화면 표시

스키마 2는 각성체·명륜·세트·옵션의 사전과 `members` 구성 풀을 둔다. `rows`는 `[wave, difficulty, count, [memberIndex, ...]]`이며, 구성 풀의 각 member는 `[characterIndex, enlightenment, borrowed, wheels, covenant]`다. wheels는 `[wheelIndex, level]`의 배열, covenant는 `[completion, parts]`다. parts는 부위 순서 Ⅰ~Ⅵ의 `[setIndex, main, subs]`, 옵션은 `[attributeIndex, value]`다. attributes 사전 항목은 `[id, label, unit]`이다. 수신기와 브라우저는 같은 검증기를 사용하며, 기존 스키마 1의 의미를 그대로 보존한다. 반복된 구성은 한 번만 검증·복원한다.

첫 화면은 명륜·비밀계약 조합, 부위별 주옵·부옵, 함께 사용된 팀 순으로 표시한다. 조합과 팀은 상위 3개, 옵션은 여섯 부위의 주옵 상위 1개·부옵 상위 2개와 사용률을 보여준다. 구역·난이도만 기본 필터로 표시하며 시즌·잠재력·지원 여부는 기존 `site-disclosure` 상세 조건에 둔다. 수집 범위·확인률과 옵션 전체 순위·수치 범위·평균은 펼쳐서 확인한다. 옵션 요약은 현재 선택의 완성도 90% 이상 계약 전체를 분모로 계산한다. 전체 목록에서는 팀·장비·실제 구성을 20개씩 펼친다. 비율과 옵션 통계는 표시한 20개가 아닌 선택 조건 전체를 분모로 계산한다. 페이지를 펼쳐도 필터와 실제 구성 연결은 유지한다.

일반 도감에 없는 실제 장착 명륜은 검증된 `js/character-usage-equipment.mjs` 보충 레코드로 조회한다. 기존 도감 상세 렌더러를 그대로 사용하며, 등록되지 않은 장비 때문에 출전 기록을 제거하지 않는다. `wheel_ramona_n`은 클라이언트 아이템 129628과 `Weapon_Full_N02`, `wheel_unsent_flower_n`은 아이템 73582와 `Weapon_Full_N01` 원본 일러스트에 대응한다.

전체 수집은 수집 시작 시각을 기준으로 5구역 × 7난이도의 공개 클리어 목록을 끝까지 읽고 stage+battle ID로 중복 제거한다. 수집 중 새 기록은 다음 스냅샷에서 다룬다. 공개되지 않은 상세 정보는 건수와 팀 정보에 남기고 장비·옵션은 미확인으로 표시한다. 따라서 수집 범위 전체와 장비 상세 확인률은 서로 다른 수치다.

## 73기 실전 추천 세팅과 조합 검색

### 보유 조건과 실제 대체 조합

2026-11-21 `codex/dzone-clear-recommendations`에서 보유 조건·대체 후보와 UI를 추가했다. 운영 배포는 하지 않았다.

**주 진입점은 각성체의 추천 세팅 탭**이다. 여기에서 보유 조건→파티 조합→한 명을 바꾼 실제 조합→
해당 조합의 네 명 장비·옵션까지 같은 탭 안에서 확인한다. 보고 있는 각성체는 대체하지 않는다.
보유 조건을 켜면 이 탭의 세팅·옵션·파티·클리어 기록을 모두 같은 보유 조건으로 집계한다.
보유 현황 편집과 계정 로그인/가져오기/로그아웃도 이 흐름과 연결했다.
`dzone_clears.html`은 여러 각성체의 포함/제외를 한꺼번에 지정하는 보조 탐색 화면이다.

- `dzone_clears.html`의 **보유한 각성체만**은 현재 계정 기록 또는 비로그인 브라우저 기록의
  `owned: true`인 ID를 읽어 네 명 모두 보유한 조합만 남긴다. 구형 보유 키도 기존 계정 저장 어댑터로 읽는다.
  빈/손상 기록을 임의의 전체 보유로 간주하지 않는다. 빈 결과에서 보유 편집으로 이동할 수 있다.
- 보유 여부만 제한한다. 육성 수치, 명륜 보유, 실제 기록의 지원 여부까지 충족한다고 판정하지 않는다.
  다른 탭에서 게스트 보유를 수정하거나 계정 로그인/가져오기/로그아웃이 발생하면 조건을 다시 적용한다.
- **한 명을 바꾼 실제 조합**은 나머지 세 명이 같은 다른 4인 조합 중 원래 결과와
  동일한 `wave+difficulty` 버킷에 클리어가 있는 것만 보여준다. 다른 구역·등급의 건수를 섞지 않는다.
  건수는 공통 버킷의 합, 세팅 링크는 그중 실제 확인된 대표 버킷으로 연결한다.
- 포함·제외·보유 조건은 대체 후보에도 유지한다. 포함 네 명을 모두 고정했다면 한 명을 해제하도록 안내한다.
  대체 후보는 해당 멤버의 독립적인 실제 기록이며 성능·역할 동일성이나 성공 가능성을 추정하지 않는다.
- 후보는 펼칠 때 계산하고 5개씩 더 본다. 추가 Worker/API 요청이나 새 원본 수집 없이 익명 시즌 집계만 사용한다.
- PC는 필터/결과 2열, 모바일은 위아래 배치. 초상화 선택기에서 포함/제외를 전환하고 이름으로 검색한다.
  긴 각성체 목록은 내부 세로 스크롤로 제공한다. 초기화는 검색 모드·포함·제외·보유·구역·등급을 초기화한다.
  `owned=1`은 조건 활성화만 URL에 보관하고 보유 ID 목록은 URL에 담지 않는다.
- 추천 세팅 첫 화면은 실제 명륜+계약 조합을 먼저 표시한다. 중복되던 명륜/계약 개별 통계는
  전용 버튼으로 이동하며, 옵션/파티 상세와 실제 기록 연결은 유지한다.

UI 참고로 [Eremora의 Find clears](https://eremora.com/meta/dzone/clears)와
[D-Zone Meta 설명](https://eremora.com/changelog/2026-09-24)을 직접 확인했다.
필터와 결과의 분리, 초상화 선택, 실제 세팅으로 이어지는 흐름을 참고했다.
Eremora는 순위표 플레이어 표본이고 이 사이트는 자체 수집된 클리어 건수이므로 사용률과 분모는 가져오지 않았다.
시각 기준은 저장소 디자인 시스템을 우선하고 `awesome-design-library`의 Linear 참고 문서에서
단순한 표면·구분선·절제된 강조 원칙만 적용했다. 브랜드 색·서체·콘텐츠를 복제하지 않는다.

`npm run recommendations:owned-test`는 로컬 73기 실제 집계로 보유 검색·대체 후보의 건수와
세팅 연결, 포함/제외/초기화, 외부 탭 갱신, 반응형을 검사한다.
Auth/Firestore Emulator 실행 중에는 `npm run recommendations:owned-test -- --with-account`로
계정 생성→게스트 가져오기→계정 보유 조건→로그아웃 후 게스트 복원을 추가 검증한다.

로그인 기능을 운영에서 활성화하면 추천 세팅 페이지도 방문 시 계정 상태를 복원한다.
현재 공용 동기화 드라이버의 초기 읽기는 프로필 1개+roster/parties 2개(정상 경로 약 3읽기)다.
여러 각성체 페이지를 연 방문도 기존 무료량 계산의 방문 횟수에 합산해야 한다.
이후 대체 후보 계산·펼치기에는 서버 요청이 없으며 실시간 리스너/주기 폴링을 추가하지 않는다.

추가 검증은 전체 테스트 567개, 추천 세팅/보조 검색 화면 33개(320/390/479/480/481/767/768/769/
1023/1024/1025/1280px, 200% 글자 확대, 가로 화면)와 계정 기존 브라우저 검사 38개를 통과했다.
추천 세팅 안에서 실제 대체 세팅 열기, 보유 수정 반영, 계정 가져오기·게스트 복원 및 양쪽 Pages 빌드도 확인했다.

`dzone_clears.html?period=73`에서 포함할 각성체(최대 4명), 제외할 각성체, 금지구역, 위험 등급을 선택한다. 결과는 각성체 네 명의 ID 집합으로 묶고, 조건에 맞는 실제 클리어 건수 순서로 표시한다. 캐릭터별 스냅샷을 합산하면 한 클리어가 네 번 계산되므로, 검색은 원본 기록을 스테이지와 전투 키로 중복 제거한 별도 시즌 집계를 사용한다. 화면에서 조합을 열면 같은 시즌·구역·등급의 클리어 세팅으로 이동한다. 각성체를 열면 명륜과 계약 세트가 **같은 기록에서 함께 쓰인 횟수**로 정렬한 추천 세팅과 주·부옵 분포가 표시된다. 기존 수동 공략은 추천 세팅 탭 하단에서 열 수 있다.

`tools/build-dzone-clear-snapshots.mjs <review-archive-dir> <private-catalog-dir> 73`은 비공개 리뷰 보관본과 검증된 클라이언트 ID 매핑을 읽어 `.generated/dzone-recommendations/73`에 익명 조합 집계와 각성체별 상세 스냅샷을 만든다. 원본 전투·아이템·계정 식별자와 요청 메타데이터는 공개 스키마에서 제외한다. 수집분이므로 검색 결과의 건수는 해당 보관본의 범위를 뜻한다. 매핑을 검증하지 못한 장비는 미확인으로 남긴다. 완성도는 확인된 6부위 원점수 합에 게임의 소수 첫째 자리 버림을 적용하며, 옵션 순위의 분모는 완성도 90% 이상이다.

로컬 Pages에서 볼 때는 생성된 73기 폴더를 사이트 산출물 `data/dzone-meta/73/` 경로로 제공한다. 정식 Worker의 `GET /api/dzone/clears?period=73`은 조합 집계를 읽는다. `POST`에 같은 기수의 `teams.json` 내부 `data` 객체를 보내면 인증과 카탈로그 검증을 거쳐 저장한다. 각성체 상세는 기존 각성체 경로에 각 파일의 `data` 객체를 게시한다. 실제 서비스 공개는 Worker 배포, 익명 상세 스냅샷 게시, 조합 집계 게시 순서로 확인한다.

2026-11-19 로컬 점검에서 73기 5구역 × 7등급 보관본 65,154건을 검증했다. 각성체 62명, 서로 다른 4인 조합 22,000개가 집계됐다. 네 명의 명륜과 계약이 모두 연결된 클리어는 61,348건이며, 각성체 출전 260,616건 중 계약 옵션·완성도 253,757건, 90% 이상 옵션 집계 대상 27,533건을 확인했다. 카탈로그에서 확인되지 않은 명륜 Item ID 155077 및 장비 상세가 빠진 사례는 미확인으로 남겼다.

### 추천 세팅과 내 파티를 먼저 보여주는 구성 (2026-11-21 후속)

각성체 추천 세팅 첫 화면은 **추천 세팅 선택 → 해당 명륜·계약을 실제로 사용한 내 보유 파티** 순서다.
기존 건수·사용률·그래프·필터·세부 통계 탭은 하단 `통계·필터·클리어 기록 자세히 보기` 안에 유지하며 기본은 닫힌다.
계정 조작도 첫 화면을 가리지 않도록 아래로 옮겼다. 특정 실제 기록 링크로 진입하거나 세팅 보기를 누르면
해당 영역을 열고 요청한 실제 기록부터 보여준다. 전체 기록을 한꺼번에 펼치지 않는다.

`js/usage-recommendations.mjs`는 한 각성체의 검증된 기록에서 명륜 조합과 계약 세트를 함께 묶는다.
네 명 모두 보유한 파티가 있는 구성을 먼저, 그 안에서 관측 건수 순서로 최대 세 가지를 제시한다.
성능 점수·승률·최적 세팅을 생성하지 않는다. 사용자가 고른 세팅은 유지하되, 명시적으로 고르기 전에는
보유 정보가 갱신되면 새 보유 조건에서 먼저 쓸 수 있는 구성을 선택한다.

- 세팅 1/2/3 중 하나만 펼쳐 장비 이름·이미지·세트 수를 비교한다.
- 주옵·부옵 예시는 실제 한 클리어의 같은 각성체가 장착한 6부위를 그대로 사용한다.
  부위별 인기 값·평균·다른 기록을 섞어 새 세팅을 만들지 않는다. 해당 원본은 `실제 세팅 보기`로 확인한다.
- 내 파티는 선택한 명륜·계약에 해당하는 실제 기록 중 네 명 모두 보유한 조합만 나온다.
  보유 미등록/미보유/기록 없음은 별도 안내하며 전체 파티로 대체하지 않는다. 추가 파티는 더 보기로 제공한다.
- 대체 조합도 현재 세팅·보유·동일 구역/등급 조건을 유지한다. 세팅을 바꾸면 내 파티와 대체 후보도 바뀐다.
- 하단 통계의 파티/장비별 상세 선택은 추천 세팅의 선택 상태와 구분한다. 구역·등급·투자/지원 조건은 함께 적용된다.

검증은 추천 순서와 실제 옵션 출처에 대한 단위 테스트, 실제 73기 데이터로 첫 화면 순서·기본 접힘 상태·
보유 파티·대체 세팅·계정 가져오기/복원, 320~1280px·200% 확대·가로 화면의 반응형을 포함한다.
이번 후속 검증은 단위·회귀 570개, 보유/대체 화면 36개와 실제 기록→편성기 흐름 9개,
전체·별도 보유 현황 Pages 빌드를 통과했다. 운영 설정·배포는 변경하지 않았다.

### 로컬 추천 세팅 미리보기

`npm run recommendations:preview`는 127.0.0.1:9357에서 사이트와
`.generated/dzone-recommendations/{period}/`의 익명 자료를 함께 제공한다.
`links.html?category=character&id=doll_inferno#usage`에서 추천 세팅,
`dzone_clears.html?period=73`에서 조합 검색을 확인한다.
생성된 자료가 없으면 먼저 위 빌드 명령으로 준비해야 한다. 가상 데이터로 대체하지 않는다.

이전 계정 테스트 서버는 사이트 파일만 제공해 `data/dzone-meta/73/characters/*.json`이 404였다.
추천 세팅 코드가 있어도 로컬 실제 자료를 읽지 못하는 상태였으며, 공유 미리보기 서버로 연결을 고쳤다.
새 서버는 teams/characters 고정 경로만 허용하고 공개 스키마로 다시 검증·직렬화한다.
리뷰 원본, diagnostics, 다른 `.generated` 파일은 제공하지 않는다. 운영 Worker에는 게시하지 않는다.

`npm run recommendations:test`는 로컬 73기 자료로 manifest의 모든 각성체 추천 세팅 화면,
실전 세팅→구역 담기→편성기 저장/새로고침을 검사한다. 명륜 0~1장 장착도
편성기의 2개 슬롯 중 빈칸으로 보존하며 원본 명륜/계약 정보는 유지한다.

2026-11-21에는 manifest의 62명 모두 실제 73기 자료와 추천 세팅 카드 표시를 확인했다.
브라우저 전체 탐색 후 편성기 검사에서 테스트 선택자가 여러 summary를 동시에 가리켜 실패한 부분은
대상 선택자를 고쳐 해당 흐름을 분리 재검증했다. 세팅→구역 담기→편성기 저장/새로고침이 통과했다.
320/390/767/768/769/1024/1280px, 844×390 가로, 200% 글자 확대 9개 검사에서 가로 넘침이 없었다.
계정 브라우저 검사 38개, 전체 회귀 563개와 양쪽 Pages 빌드도 통과했다. 운영 배포 완료를 뜻하지 않는다.


### 스크롤과 세부 기록 분리 (2026-11-21)

초기 2열 배치는 아래 시각 개편으로 교체했다. 추천 세팅 뒤에 보유 파티를 표시하며,
파티는 처음 2개, 추가 요청마다 2개씩 표시한다. 상세 기록은 아래 별도 창 동작을 유지한다.

추천 세팅의 실제 기록, 내 보유 파티의 세팅, 대체 조합의 실제 기록은 네이티브
`dialog`에서 한 건씩 탐색한다. 기존 선택 세팅·필터·통계 펼침 상태를 변경하지 않는다.
이전/다음 기록, 구역에 담기, 장비 상세를 사용할 수 있고, 닫기/Escape 후 원래 버튼과
페이지 스크롤 위치로 돌아온다. 펼친 대체 후보 목록도 유지한다. 직접 기록 링크로
들어오는 경로와 하단 통계의 전체 기록 탐색은 유지한다.

이 변경은 표현과 탐색 방식만 바꾸며, 실제 클리어·보유·세팅·구역/등급 일치 조건과
파티 중복 검사, 원본 옵션 수치는 그대로 사용한다. 새로운 서버 요청을 추가하지 않는다.


### 장비·파티의 시각적 묶음 개편 (2026-11-21)

Eremora 각성체별 화면과 Find clears의 DOM 및 화면을 다시 확인했다. 참고 화면의
이름은 주로 14px/20px, 항목 간격은 8px/12px이며, 장비 썸네일 영역은 44px였다.
추천 세팅과 내 파티를 좌우로 나누던 구조를 없애고, 추천 장비 한 묶음 아래에
네 명의 파티 카드를 배치한다. 장비 이름은 14~16px, 장비 이미지 너비와 파티
초상화는 48~56px로 사용한다. 원본 이미지 비율은 object-fit:contain으로 유지한다.
세팅 선택에는 실제 명륜·계약의 미리보기와 전체 구성의 접근 가능한 이름을 제공한다.

파티 카드는 네 명의 초상화·이름 다음에 실제 클리어 구역, 세팅 보기, 대체 조합을
같은 표면 안에서 제공한다. 640px 이상에서는 파티 카드 2열, 아래에서는 1열이다.
주옵·부옵 펼침 버튼과 실제 기록 버튼은 장비 묶음 안의 공통 도구 행으로 정리했다.
본문을 덮던 중복 피드백 버튼은 이 화면에서 숨기고 기존 하단 제보 경로를 유지한다.
