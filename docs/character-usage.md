# 각성체 사용 현황 데이터 규격

각성체 공략의 ‘사용 현황’은 수집된 출전 기록을 탐색하는 화면이다. 수동 추천 세팅을 통계로 변환하거나 누락된 장비를 추천 값으로 채우지 않는다.

## 수집 경계

게임 연결, 클리어 원본 수집, 중복 제거와 공개 ID 매핑은 비공개 `morimens-data-extractor`의 책임이다. 공개 저장소는 정제된 익명 구성의 수신·검증·조회·표시를 담당한다. 인증 토큰·UID·닉네임·리플레이 코드·원본 응답은 공개하지 않는다.

클리어 1건의 장비·옵션·완성도 연결 검증을 마친 뒤, 현재 기수의 5구역 × 7난이도 공개 목록 전체로 수집 범위를 확장했다. 초기 구역·난이도별 10건 제한은 적용하지 않는다. 무작위 표본이라고 부르지 않는다. 최신순으로 수집했다면 `source`에 ‘최신 클리어 표본’이라고 표시한다. 같은 유저의 다른 클리어는 별도 건이며, 유저 사용률 또는 승률로 해석하지 않는다.

## 조회·수신

- `GET /api/dzone/character/{characterId}/usage`: 가장 최신 기수와 사용 가능한 `periods`.
- `GET /api/dzone/character/{characterId}/usage?period=71`: 지정 기수.
- `POST /api/dzone/character/{characterId}/usage`: `Authorization: Bearer <DZONE_INGEST_TOKEN>`으로 인증한 해당 기수 스냅샷 교체. 증분 가산이 아니다.
- 데이터 미수집은 404, 저장소 미설정은 503. 브라우저는 둘을 구분한다.
- 기존 `RESOURCE_LINK_STATE`의 별도 `dzone:character-usage:v1:` 접두사를 사용한다. 기존 채용률·제한 클리어 API는 변경하지 않는다.

## 구역별 편성과 세팅 연결

- 융재 정보의 파티별 ‘세팅 보기’는 기수·구역·난이도·각성체 4명의 stable ID를 `links.html`로 전달한다. 캐릭터별 파티 카드도 같은 클리어 세팅 목록으로 연결한다.
- 클리어 세팅은 네 명의 명륜·계약이 공개된 기록을 기본으로 보여준다. 미공개 기록도 필터를 해제하면 확인할 수 있다. 펼치기 전 잠재력·지원 여부·공개 장비 인원·계약 완성도를 표시한다.
- ‘파티 잠재력’의 명함~3돌 이하 필터는 네 명 전원의 수집값이 해당 범위에 있는 기록만 남긴다. 4단계 이상 값을 임의의 돌파로 환산하지 않으며, 미수집도 제외한다. 명륜 돌파는 현재 수집되지 않았다. 강화와 돌파를 구별한다.
- 계약 완성도 90%는 옵션 분포의 집계 기준이다. 클리어 세팅 선택·보관의 필수 조건으로 적용하지 않는다.
- `morimens_dzone_plan_v1` 로컬 저장소는 한 기수의 구역별 실제 클리어 세팅을 보관한다. 다른 구역의 각성체·명륜 중복은 허용하지 않으며 비밀계약 중복은 허용한다. 기존 구역 교체는 별도 확인을 거친다. 다른 기수 편성이 남으면 먼저 비워야 한다.
- ‘다른 구역에 담은 각성체·명륜 제외’는 클리어 세팅 목록의 대안을 찾는 필터다. 각 구역을 따로 저장한 기록이므로 5개 파티가 동일 유저의 연속 클리어였다는 뜻은 아니다.
- ‘편성기에서 보기’는 기존 `party_builder.js` 페이지·팀 렌더러와 선택기를 사용한다. 기존 페이지를 유지하고 기수별 페이지에 구역 1~5를 배치한다. 페이지가 가득 차면 덮어쓰지 않는다. 편성기에서 수정한 각성체·명륜을 가져온 세팅으로 바꿀 때는 기존 시스템 확인창을 사용한다.
- 명륜 ID와 각성체 ID는 편성기 카탈로그에 대조한다. 계약·옵션 원본은 각 팀의 `usageSource`에 함께 저장한다. 새로고침 시 같은 검증기를 통과한 원본만 복원한다. 은열쇠는 수집하지 않았으며 사용자가 따로 선택한다.
- 편성기에서 장비를 바꾼 경우 계약·옵션은 원본 클리어 기록임을 표시한다. 사용자가 바꾼 장비에 맞춰 옵션을 자동 추천하지 않는다.

공유 구현: `js/usage-plan.mjs`는 저장·중복 검사·원본 링크, `js/character-usage-view.mjs`는 네 명의 장비·계약·옵션 렌더링, `js/usage-plan-builder.mjs`는 기존 편성기 어댑터를 담당한다. 별도 선택기나 복제한 편성기를 만들지 않는다.

## 스냅샷 필드

| 필드 | 형식과 의미 |
|---|---|
| `schemaVersion` | 기본 형식 `1`, 반복 구성을 공유하는 전송 형식 `2` |
| `characterId` | manifest의 stable ID |
| `period` | 실제 수집 기수, 양의 정수 |
| `collectedAt` | 집계 기준 Unix 초. 이 시각 이후 새 기록은 제외하며 표시 갱신 시각으로 덮어쓰지 않음 |
| `coverage` | `sample` 또는 수집 범위 전체인 `complete` |
| `source` | 수집 범위·선정 방식을 설명하는 공개 문구 |
| `rows` | 최대 100,000개 익명 구성. 전체 요청 최대 24MB |

각 row는 `wave`(1~5), `difficulty`(`1`~`7` 또는 기존 `normal/hard/nightmare/madness`), `count`(같은 구성인 클리어 수), `members`(1~4명)를 가진다. 화면에서는 wave를 ‘금지구역’, 값을 ‘1구역’으로 표시한다. 상세는 ‘제1금지구역’이다.

각 member는 다음을 가진다.

| 필드 | 의미 |
|---|---|
| `characterId` | manifest ID. 매핑이 확인되지 않으면 송신 전 중단 |
| `enlightenment` | 수집한 실제 돌파 단계 정수, 미확인은 `null` |
| `borrowed` | 실제 지원 여부, 미확인은 `null` |
| `wheels` | 실제 장착한 0~2장의 `[{id, level}, ...]`. 미수집은 `null`. level 미확인은 `null` |
| `covenant` | `{completion, parts}` 또는 미수집 `null` |

`completion`은 **게임에서 확인한 완성도 백분율**(0~100), 미확인은 `null`이다. 옵션을 보고 임의의 완성도 공식을 만들지 않는다. 여섯 `parts`는 slot(1~6), setId(covenant_list의 english_name), main, subs를 가진다. 모든 옵션은 `{id, label, value, unit}` 형식이며 unit은 `%`, `pt`, 빈 문자열 중 하나다. 부옵이 없는 부위는 빈 배열이다. 옵션 원본이 일부만 내려오면 완전한 계약처럼 보내지 않고 covenant를 null로 둔다.

## 집계 의미

- 팀: 각성체 ID 집합으로 묶는다. 배치 순서 차이는 합친다.
- 명륜: 실제 장착한 명륜의 ID 조합으로 묶고 강화 단계는 실제 구성에 보존한다.
- 계약: 여섯 부위의 세트별 개수 조합. 3+3 등 혼합 세트도 보존한다.
- 팀·명륜·계약 비율의 분모: 선택한 구역·난이도·돌파 등 조건의 각성체 출전 건수. 미수집 장비는 분모에서 몰래 제거하지 않는다.
- 특정 팀·장비 선택은 다른 모든 영역에도 적용한다. 현재 영역에서는 자기 필터만 풀어 다른 선택지를 비교할 수 있다.
- 옵션 분포의 분모: 현재 선택에 해당하며 완성도 90% 이상이고 6부위 옵션이 확인된 계약 건수. 90%는 포함, 미확인/89%는 제외한다.
- 부옵 비율: 그 부위에 해당 부옵을 가진 계약의 비율. 여러 종류를 가지므로 합계가 100%를 넘을 수 있다. 범위·평균은 count로 가중한다.
- 동일 부위에 같은 부옵이 여러 줄 들어올 수 있다. 원래 줄과 순서는 보존하고 분포에서는 그 계약을 한 번만 센다. 같은 종류·단위의 수치는 부위 안에서 합산한다.
- 사용 구성에는 90% 미만도 그대로 표시한다. 주옵·부옵의 합계는 같은 옵션 ID·단위끼리만 더한다.

원본 클리어 키는 비공개 수집기에서 stage+안정적인 battle ID로 중복 제거한다. 공개 row는 팀원 전원의 돌파·지원·장비·옵션과 구역·난이도가 완전히 같을 때만 count를 합친다. 이 데이터로 개별 유저 수나 승률을 계산하지 않는다.

## 기존 UI 재사용

진입점은 `links.html?category=character&id=...#usage`이다. `js/links.js`가 기존 캐릭터 탭과 도감 상세 다이얼로그(`openDictionaryDialog`, `#dictionary-detail-dialog`)를 유지하며 `js/character-usage.js`에 manifest·도감 데이터를 전달한다. 별도 장비 상세 팝업을 복제하지 않는다.

`usageDemo=1`은 명시적으로 선택하는 가상 데이터 모드다. 실제 GET·POST와 분리되고 페이지 전체에 예시임을 표시한다. 예시는 `js/character-usage-demo.mjs`에서만 생성하며 운영 `data/*.json`에 넣지 않는다.


## 연결 전 검사

수집기가 만든 익명 후보는 `node tools/validate-character-usage.mjs <후보.json>`으로 검증한다. 서버도 동일한 스키마와 현재 도감 ID를 검사한다. 게임 원본을 이 검증기에 직접 넣지 않는다. 비공개 수집기가 현재 클라이언트 필드와 공개 ID 사이의 검증된 어댑터를 제공하기 전까지 수집 완료로 간주하지 않는다.

동일 각성체·기수의 송신은 한 게시기에서 직렬 실행한다. 수신기는 전체 스냅샷을 교체하며 오래된 수집 시각은 거부한다. 인증·형식 검사 실패 시 마지막 정상 스냅샷을 유지한다.

## 실제 1건 연결 검증

2026-10-23, 게임 서버가 반환한 71기 제5금지구역 S등급의 저장된 클리어 구성 1건으로 검증했다. 기록의 팀에는 침식 · 로탄, 라이커, 릴리, 타비가 포함된다. 각성체 4명·명륜 8장·계약 24부위·주옵 24줄·부옵 72줄을 익명 구성으로 변환했다. 네 각성체의 조회용 스냅샷은 **같은 클리어 1건의 다른 관점**이며 서로 다른 4건이 아니다.

원본에는 완성도 필드가 직접 들어 있지 않았다. 부위 점수 24개를 게임 함수와 대조한 뒤, 전체 완성도는 `AwakerTrinketDataUtils.GetTrinketSuitCompletionRate`로 90% 경계를 포함한 실제 구성 12건을 다시 검증했다. 게임은 여섯 부위의 원점수를 합친 뒤 132로 나누고 소수 첫째 자리까지만 남긴다. 부위별 표시값을 먼저 버림 처리한 뒤 더하지 않는다. 침식 · 로탄의 검증용 계약은 97.3%로, 90% 이상 옵션 집계에 1건 포함된다. 나머지 세 각성체는 각각 65.5%, 60.2%, 77.6%이며 옵션 분포에서는 제외되고 실제 구성에는 남는다. 89.8% 또는 89.9%로 잘못 계산됐던 실제 90.1% 사례도 이 방식으로 포함된다. 잠재력 원본 단계 4 이상을 일반 ‘N돌’로 바꾸지 않는다. 난이도 원본 4는 현재 기수의 `gameGrade` S와 대조했다.

`workers/character-usage-preview.mjs`는 같은 조회 함수를 사용하는 읽기 전용 QA Worker다. 저장 키 앞에 `character-usage-qa:`를 붙여 운영 키와 분리한다. POST는 허용하지 않는다. `wrangler.character-usage-preview.jsonc`로 배포하며 실제 익명 스냅샷만 별도 KV 키에 게시한다. 원본 응답과 계정·장비 UID는 Git이나 Pages 아티팩트에 포함하지 않는다.

`links.html`은 QA Pages 호스트에서만 해당 읽기 전용 Worker를 사용한다. 운영 호스트는 기존 수신·조회 API를 사용한다. 이 단계는 1회 수집·게시 연결의 검증이며 자동·예약 수집이나 전체 클리어 수집 완료를 뜻하지 않는다.

## 전체 기수 전송과 화면 표시

스키마 2는 각성체·명륜·세트·옵션의 사전과 `members` 구성 풀을 둔다. `rows`는 `[wave, difficulty, count, [memberIndex, ...]]`이며, 구성 풀의 각 member는 `[characterIndex, enlightenment, borrowed, wheels, covenant]`다. wheels는 `[wheelIndex, level]`의 배열, covenant는 `[completion, parts]`다. parts는 부위 순서 Ⅰ~Ⅵ의 `[setIndex, main, subs]`, 옵션은 `[attributeIndex, value]`다. attributes 사전 항목은 `[id, label, unit]`이다. 수신기와 브라우저는 같은 검증기를 사용하며, 기존 스키마 1의 의미를 그대로 보존한다. 반복된 구성은 한 번만 검증·복원한다.

첫 화면은 명륜·비밀계약 조합, 부위별 주옵·부옵, 함께 사용된 팀 순으로 표시한다. 조합과 팀은 상위 3개, 옵션은 여섯 부위의 주옵 상위 1개·부옵 상위 2개와 사용률을 보여준다. 구역·난이도만 기본 필터로 표시하며 시즌·잠재력·지원 여부는 기존 `site-disclosure` 상세 조건에 둔다. 수집 범위·확인률과 옵션 전체 순위·수치 범위·평균은 펼쳐서 확인한다. 옵션 요약은 현재 선택의 완성도 90% 이상 계약 전체를 분모로 계산한다. 전체 목록에서는 팀·장비·실제 구성을 20개씩 펼친다. 비율과 옵션 통계는 표시한 20개가 아닌 선택 조건 전체를 분모로 계산한다. 페이지를 펼쳐도 필터와 실제 구성 연결은 유지한다.

일반 도감에 없는 실제 장착 명륜은 검증된 `js/character-usage-equipment.mjs` 보충 레코드로 조회한다. 기존 도감 상세 렌더러를 그대로 사용하며, 등록되지 않은 장비 때문에 출전 기록을 제거하지 않는다. `wheel_ramona_n`은 클라이언트 아이템 129628과 `Weapon_Full_N02`, `wheel_unsent_flower_n`은 아이템 73582와 `Weapon_Full_N01` 원본 일러스트에 대응한다.

전체 수집은 수집 시작 시각을 기준으로 5구역 × 7난이도의 공개 클리어 목록을 끝까지 읽고 stage+battle ID로 중복 제거한다. 수집 중 새 기록은 다음 스냅샷에서 다룬다. 공개되지 않은 상세 정보는 건수와 팀 정보에 남기고 장비·옵션은 미확인으로 표시한다. 따라서 수집 범위 전체와 장비 상세 확인률은 서로 다른 수치다.
