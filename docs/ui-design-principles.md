# UI 설계 원칙과 판정 규칙

이 문서는 Morimens.Info.kr의 UI를 설계·수정·검토할 때 쓰는 프로젝트 기준이다. 정보가 존재하거나 레이아웃 검사에 통과했다는 사실만으로 보기 좋고 쓰기 편하다고 판단하지 않는다. 사용자가 무엇을 함께 보고 판단하는지, 선택과 결과가 얼마나 자연스럽게 이어지는지를 실제 화면에서 검토한다.

조회·작성일: 2026-11-22. 외부 원문은 설계 근거이며, 사용자 명시 요구와 `AGENTS.md`, [반응형 설계 기준](responsive-design.md)이 우선한다. 특정 화면에서 채택한 구성을 업계 전체의 절대 규칙으로 표현하지 않는다.

## 1. 근거와 적용 범위를 구분한다

### 외부 원문에서 확인한 일반 원칙

| 근거 | 확인한 핵심 | 여기서 단정하지 않는 것 |
|---|---|---|
| [NN/G, Progressive Disclosure](https://www.nngroup.com/articles/progressive-disclosure/) | 자주 필요한 핵심은 먼저 보여주고, 덜 필요한 세부 기능은 분명한 진입점에서 요청할 때 공개한다. 무엇을 뒤로 미룰지는 과제로 판단한다. | 모든 목록을 무조건 접거나, 기본 부옵을 반드시1개만 보여줘야 한다는 규칙이 아니다. |

### 사용자가 이 화면에 명시한 선호

다음은 위 원문에서 끌어낸 보편 법칙이 아니라, 이번 작업에서 직접 확인한 요구다.

- 기존 보유 현황과 이어지는 톤앤매너를 유지한다. 요청 밖의 상단 탭·제목·페이지 폭을 바꾸지 않는다.
- 명륜과 비밀계약 이미지는 식별할 수 있게 크게 보여준다. 계약 그림 위에 주옵 속성 아이콘을 새로 합성하지 않는다.
- 추천은 임의의 한 클리어 수치 예시가 아니라 실제 기록의 채용 통계다. 명륜 두 장 조합과 비밀계약의 전체 순위는 독립적으로 보여주고, 옵션은 선택한 두 장비를 함께 사용한 기록에서만 집계한다.
- 기본 화면에서는 명륜과 비밀계약을 동등한 섹션으로 먼저 보여준다. 시즌·구역·위험 등급은 집계 정보 안으로 내리고, ‘융재금구 기록 기반’ 같은 안내 문구를 새로 추가하지 않는다.
- 섹션 제목은 **주옵션**, **부옵션**으로 통일한다. 표시 모드가 달라져도 항목 이름을 바꾸지 않는다.
- 관련 내용을 더 보는 동작은 해당 제목 옆에 둔다. 화면 아래에 분리한 ‘더보기’ 영역으로 보내지 않는다.
- 같은 옵션 요약과 전체 목록을 동시에 반복 표시하지 않는다. 수치 하나를 불필요하게 거대한 장식처럼 강조하지 않는다.

## 2. 프로젝트에서 적용하는 구체적 판정 규칙

### 관련 조작은 해당 정보에 붙인다

‘전체순위’는 주옵션/부옵션 각 제목행 안에서 그 목록을 제어한다. 두 목록을 한꺼번에 바꾸는 페이지 하단 버튼은 쓰지 않는다. 조작 이름만 읽어도 어느 항목에 무슨 내용이 추가되는지 예상할 수 있어야 한다. 파티 필터도 현재 파티 범위와 가까이 둔다.

추천 옵션의 펼침은 제목 바로 옆의 작은 방향 표시로 표현한다. `전체 순위/요약` 문구를 양쪽 먼 끝에서 번갈아 표시하지 않는다. native disclosure의 열림 상태와 접근성 명칭은 유지하고, 실제 클릭 영역은 44px 높이를 확보한다. 옵션 아이콘은 14px 본문과 같은 14px로 두어 이름·비율보다 강해지지 않게 한다. 장비 이미지의 크기와는 별도로 판단한다.

**거부 사례:** 주옵션과 부옵션을 읽고 긴 공백·기준 문구를 지난 뒤 ‘옵션 분포 더보기’를 발견하는 구조. 어느 목록을 여는지 다시 확인해야 한다.

### 점진 노출은 같은 자리의 상세화다

기본 요약은 흔한 판단을 할 만큼 충분해야 한다. 전체순위를 열면 같은 섹션의 요약을 전체 분포로 **대체**한다. 닫으면 그 자리에서 요약으로 돌아온다. 주옵션과 부옵션은 각각 독립적으로 확장한다. 계약·구역·파티 조건을 바꾸거나 페이지의 다른 단계로 이동시키지 않는다.

**거부 사례:** 요약의 최고 옵션과91.5%를 그대로 둔 채 바로 아래 전체 목록 첫 행에 같은 옵션과91.5%를 다시 표시하는 구조. 상세 조작을 여러 단계 안쪽에 중첩하는 것도 피한다.

이 ‘대체’ 방식은 중복 지적을 해결하기 위한 프로젝트 선택이다. NN/G 원문에 특정 DOM 구조나 대체 구현이 직접 규정돼 있다고 주장하지 않는다.

### 제목은 내용 종류, 조작은 표시 범위를 말한다

주옵션/부옵션 제목은 고정한다. ‘1순위’나 ‘전체’는 필요하면 목록 안의 상태·열 이름·조작에서 구별한다. 순위 모드 변경 때 제목 자체가 바뀌어 새 항목처럼 보이지 않게 한다. 기본/펼침/비교에서 같은 통계는 같은 명칭과 단위를 쓴다.

**거부 사례:** 기본은 ‘주옵1순위’, 펼치면 ‘주옵 채용률’, 다른 곳에서는 ‘추천 옵션’이라고 불러 하나의 항목을 여러 개처럼 보이게 하는 경우.

### 강조는 결정에 필요한 차이에 쓴다

목록의 글자·비율은 같은 기본 크기와 숫자 정렬을 유지한다. 최고값·선택 상태는 기존 금색과 적당한 굵기로 구분한다. 순위/빈도 숫자가 섹션 제목이나 장비보다 크게 보이면 그 크기가 실제 과제를 돕는지 다시 판단한다.

**거부 사례:** 부옵91.5%만 거대한 글자로 두어 다른 후보가 없는 것처럼 보이거나, 이 숫자가 장비의 실제 옵션 수치처럼 읽히는 구성. 동률이면 한 후보만 유일한 추천처럼 표현하지 않는다.

### 이미지는 장비를 식별하는 역할을 맡긴다

큰 명륜2장과 계약 원형의 실제 체감 크기·기준선을 함께 본다. frame 높이가 같다는 이유만으로 비율이 균형이라고 판단하지 않는다. 기본 이미지 위에 새 속성 아이콘·뱃지를 합성해 그림의 본래 정보와 경쟁시키지 않는다. 원본 자산 안의 문양/번호와 새 UI 오버레이는 구별한다.

비교에서 두 계약이 같은 명륜 pair를 쓰면 ‘공통 명륜’으로 명시해 두 번 반복하지 않는다. 달라지는 계약 그림과 변화하지 않는 공통 정보의 위계를 구분한다. 아이콘을 쓰더라도 이름을 대신하거나 장식용 버튼처럼 보이게 하지 않는다.

### 수치는 하나의 읽기 축으로 맞춘다

옵션명과 채용률을 연결된 한 행으로 묶고 비율의 오른쪽 끝을 맞춘다. 숫자는 tabular 숫자 폭을 사용한다. 수치 열의 CSS 선언만 보지 말고 실제 열 너비와 긴 한글의 줄바꿈을 확인한다. 두 계약의 비교 열에는 실제 계약 이름이 있어야 한다.

**거부 사례:** 숫자를 문장처럼 자유 배치해 매 행에서 이름과 숫자의 대응을 다시 찾는 경우. 넓은 비율 열 때문에 옵션명이 한 글자씩 세로로 쌓이는 경우. ‘세팅1/2’를 기억해야만 비교 대상을 알 수 있는 경우.

### 맥락 정보는 필요할 때 찾을 수 있게 한 곳에 둔다

집계 기준일·출처·완성도 조건·비율의 분모는 사라져서는 안 된다. 그러나 장비 그림·주옵션·부옵션 사이마다 반복하지 않는다. 출처·수집 시각은 ‘집계 정보’, 옵션 완성도 조건·계약별 표본수·비율의 분모는 확장 목록 아래의 공유 기준 문구 한곳처럼 내용에 맞는 가까운 위치에서 확인하게 한다. 서로 다른 범위의 메타데이터를 무조건 한 DOM에 합치라는 뜻은 아니다. 본문에서는 숫자의 단위를 오해하지 않을 정도의 라벨을 유지한다. ‘현재 브라우저’나 보유 인원처럼 이 판단에 필요 없는 운영 설명을 추천 본문에 노출하지 않는다.

### 좁아지면 관계를 재배치한다

글자나 이미지를 먼저 줄여서 억지로 맞추지 않는다. 옵션명과 두 비율의 가로 관계가 무너지면 옵션명 전폭 행 아래 두 비율로 재흐름한다. 초점과 제목, 전체순위 조작이 서로 멀어지거나 sticky 영역에 가리지 않는지 본다. 기본/펼침/비교의 어느 상태에서도 같은 의미 관계를 유지한다.

구체적인 최소 viewport·확대·경계 검증은 [responsive-design.md](responsive-design.md)를 따른다. 기술 검증에 통과했어도 불필요한 왕복, 과도한 강조, 불편한 줄바꿈이 남으면 별도 시각 문제로 기록한다.

## 3. 추천 세팅 수정 전후의 판정 근거

| 수정 전 관찰/사용자 지적 | 적용할 변경 | 실제로 확인할 근거 |
|---|---|---|
| 계약 그림에 새 속성 아이콘을 겹쳐 본래 문양과 경쟁함 | 이미지 오버레이 제거, 장비 식별용 이미지 유지 |390/1280에서 원형과 번호가 자연스럽게 보이고 새 합성 표식이 없는가 |
| 주옵1순위/부옵1순위 등 명칭이 모드마다 달라짐 | 제목은 주옵션/부옵션으로 유지 |기본·독립 펼침·비교에서 제목이 같은가 |

| 긴 표가 안 깨져도 한글을 한 글자씩 읽어야 함 | 실제 내용 폭 기준 재흐름 |200%에서 말뜻이 있는 단위로 읽히는가 |
| 요소가 존재하고 테스트가 통과했다는 이유로 완료 처리함 | 별도 과제 검토와 시각 검토 |사용자가 느낄 수 있는 불편과 남은 tradeoff를 구체적으로 적었는가 |

### 2026-11-22 추천 세팅 화면에서 실제로 교정한 사례

390px·1280px 화면을 구현자와 다른 검토자가 직접 읽었다. 초기 교정본에도 기본 부옵션 1행 옆의 빈 공간, 펼침 때만 생기는 회색 외곽 박스, 부옵션을 펼치면 주옵션 행까지 늘어나는 문제가 남아 있었다. 상위 3종의 보통 행, 투명한 목록과 분리선, 요약 영역의 높이 채우기 제거로 다시 수정했다.

| 실제 수정 전 | 최종 화면에서 확인한 변화 | 판단과 남은 비용 |
|---|---|---|
| 부옵션 피해 증폭 91.5% 하나만 보여 다음 후보를 판단하려면 펼쳐야 함 | 기본에서 91.5%·88%·77.6%를 같은 행 크기로 비교 | 핵심 판단을 위한 후보가 생겼다. 모바일은 2행만큼 길어지지만 그림·글씨를 줄이지 않는다. 3종은 동시장착 조합이 아닌 채용률 순위다. |
| 부옵션만 펼쳤는데 데스크톱 주옵션 행 간격도 늘어남 | 1280px 주옵션 목록 높이가 펼침 전후 153.08px로 유지됨 | 조작하지 않은 정보의 위치가 유지된다. 두 섹션의 상세 길이를 억지로 맞추지 않는다. |
| 펼친 목록에만 별도 회색 박스가 생김 | 요약과 펼침 모두 투명한 행·분리선 표현 사용 | 같은 항목의 상세라는 관계가 이어진다. 목록이 길어지는 비용 자체를 없앤 것은 아니다. |
| 펼침 진입점이 두 항목 아래로 떨어지고 내용이 중복됨 | 각 제목 우측에서 독립 조작하며 요약을 숨기고 전체 목록으로 대체 | 상세의 소속과 조작 범위를 읽을 수 있다. 부위별 전체 분포는 여전히 길므로 독립 확장이 필요하다. |

별도 Chromium 컨텍스트의 320·390·768·1024·1280px, 844×390 가로, 390px의 200% 글자 확대에서 독립 펼침·양쪽 펼침과 페이지 가로 넘침을 확인했다. 이는 레이아웃과 상호작용 확인이며 사용자 미관 만족의 보증이 아니다. 전후 화면과 계측 기록은 `.generated/principles-review/`에 남겼다.

## 4. 검토 기록은 판정 이유를 남긴다

각 UI 검토에서는 다음을 결과 문장으로 기록한다. 체크 표시만으로 대체하지 않는다.

1. 사용자가 하려는 판단과 실제 화면에서 먼저 보이는 요소를 적는다.
2. 제목·조작·내용의 관계를390/1280 실제 화면으로 읽고, 불편한 위치·크기·줄바꿈을 지목한다.
3. 기본/한쪽 펼침/양쪽 펼침/비교를 각각 실행한다. 펼친 결과가 원래 항목의 상세인지, 다른 단계처럼 보이는지 평가한다.
4. 표본이 적거나 내용이 비어 있을 때도 의미가 유지되는지 확인한다.
5. 기술 검사는 별도로 기록한다. 넘침0, 버튼 존재, 치수 기준 통과만으로 미관을 합격 처리하지 않는다.
6. 작성자 외 검토자는 구체적 불편과 반대 tradeoff를 남긴다. ‘P1/P2없음’을 ‘좋은 디자인’이나 사용자 만족의 증명으로 바꾸지 않는다.
