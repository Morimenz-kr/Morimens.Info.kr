## 검증한 실제 조회

- 게임은 정상 종료했고 Steam 로그인은 유지했다. 강제 종료·세션 복사·로그인 정보 공개는 하지 않았다.
- 요청한 UID의 최근 공개 전투 기록 52건을 직접 게임 서버에서 읽었다. 현재 70기 융재금구에 속하는 기록은 그 범위에 1건이었다.
- 최신 기록: 2026-10-05 14:43:22 KST, 3파 S, 15턴. 최신은 높은 점수가 아니라 기록 시각 기준이다. 전체 과거 시즌 기록을 전수 조회했다는 뜻은 아니다.
- 그 기록의 턴별 합계는 피해 2,636,232 / 회복 5,595 / 방어막 2,130으로 서버 기록 합계와 일치했다.
- 카드별 레벨, 재능별 레벨, 명륜 두 슬롯의 서로 다른 단계, 비밀계약 옵션과 장비 UID·결속 상태의 완전성 여부를 보존했다. 기록을 우리 시뮬레이터에 넣으면 같은 난수·시작 상태·피해가 재현된다고 보장하지 않는다.
- 기록의 기본값과 명시적 장비 옵션을 합친 일부 수치도 대조했다. 예: 크리티컬 확률 12.6%, 크리티컬 피해 75.2%. 조건부 효과를 포함하는 최종 스탯 전체의 검증 완료는 아니다. 누락된 기본값을 0으로 간주하지 않는다.
- 융재금구 70기, 환몽심잠 7기, 열차 7기, 수집 랭킹 각각 1~20위를 실제 게임 서버에서 읽었다. 모드별 시즌 ID는 클라이언트 설정과 호출 근거로 구분했다.
- 이후 52건을 전체 시즌 메타데이터로 재분류해 융재금구 21건을 확인했다. 모드별 시즌 129개, 도전 스테이지 3,185개를 ID/기간으로 연결했다. 환몽심잠은 외부 공개 UID 100997496의 Stage 7742 공유 전투를 직접 조회·합계 대조했다. 열차는 랭킹 상위 3명의 공개 창에서 해당 모드 기록을 찾지 못했다. 열차 기록이 없다는 판정이 아니라 추가 검증이 필요한 상태다.
- PvP 최근 2건을 직접 읽어 양쪽 4인 편성, 장비·은열쇠, 피해·회복·방어막, AI 여부, 공개 공유 코드를 연결했다. 2승/0패는 조회한 페이지의 성적이지 전체 누적 승률이 아니다. PvP 수집 ID는 PVPCollect → Item.SpParam → AwakerConfig를 통해 한국어 이름에 연결한다.
- 3파 S의 공개 클리어 목록 10건을 추가 수집했다. 상세 조회 2건 중 1건은 확인, 1건은 실패로 유지했다. 랭킹 표본을 병합한 뒤 재개 가능한 수집기로 21위의 공개 기록 8건을 추가해 현재 인덱스는 44건이며 전역 표본이 아니다. 순위는 플레이어의 시즌 랭킹이지 개별 전투의 랭킹 인정 여부가 아니다.
- 본인 전시 각성체 4명의 상세 응답을 모두 직접 확인했고, 과거 빌드와 동일한 상세 처리기를 연결했다. 일부 전시 응답에 명륜/계약이 0개인 상태도 그대로 유지한다.
- 기존 파티 시뮬레이터의 클립보드 형식으로 최신 기록을 내보내는 어댑터를 구현했다. 본인 명륜 8개 ID를 모두 연결했다. 기존 편성 코드가 지원하지 않는 개별 카드/재능/계약은 별도 역사적 빌드 JSON으로 보존하며, 코드에 포함됐다고 가장하지 않는다.
- 재능의 서버 lv는 원본 `AwakerTalentExtModel.GetTalentCfg`의 행 번호다. 해금 요구값 `TalentLevel`로 행을 고르지 않는다. 카드 수치는 원본 BattleApi 계수식과 개별 카드 레벨을 사용하고 미확정 전투 문맥은 미확정으로 유지한다.
- 공개 공유 응답에서 누락되던 `teamAttrs`, 돌파 스킬 해금, 결속 계약, 카드 기록 비용/사용 횟수, 옵션 인덱스를 안전한 필드 허용 목록으로 추가했다. 최신 기록의 영역 숙련 최종값 42, 피해 증폭 157%, 검은 인장 드롭율 3%, 죽음 저항 254%는 서버 기록값이다. 모든 턴의 조건별 스탯 이력으로 해석하지 않는다.

## 로컬 API 계약

`node private-tools/record-feature-api.mjs`로 실행하면 `127.0.0.1:8768`에서만 동작한다. 게임 조회에는 Steam이 켜져 있고 Morimens는 종료되어 있어야 한다. API는 게임을 자동 종료하지 않는다.

- `GET /api/profile/:uid` 및 `/history`, `/challenges`, `/latest-dzone`, `/matches?page=1`, `/awakener/:tid`
- `GET /api/dzone/stage/:tid/clears?page=1`
- `GET /api/replay/:code`, `/analysis`, `/party`, `/build?awakener=:tid`
- `GET /api/leaderboard?mode=dzone|pdive|railway|collection&season=...&offset=0&limit=20`
- `GET /api/seasons?mode=...`
- `GET /api/clears`, `/api/meta`: 수집된 인덱스 범위만. 전역 표본 여부를 별도로 반환한다.
- `GET /api/events?category=current|all|task|trial|attendance|banner&status=current|upcoming|ended|all`, `/api/events/:id`
- `GET /api/library/relics`(기존 범위), `/relic-variants`(651개 ID별), `/relics-full`(418개 참조 묶음), `/relics/:variantId?level=65`
- `GET /api/replay/:code/party-code`: 기존 파티 시뮬레이터 클립보드 형식. 미매핑/중복 식별자는 코드 대신 진단 반환.
- `GET /api/library/sources/Skill|State/:id`: 원천의 설정 설명·변형·명령 참조. 실제 전투 효과값으로 가장하지 않음.
- `GET /api/library/stages?q=...&offset=0&limit=20`: 일반 스테이지와 도전 스테이지의 ID/이름 검색.
- `GET /api/library/profile-cosmetics?kind=avatars|frames&q=...&offset=0&limit=20`: Item ID 기반 정적 정보. 보유/현재 획득 가능 목록이 아님.
- `GET /api/events/time-rules?type=...&offset=0&limit=20`: 상대 일정/트리거 조건. 개인별 실제 날짜를 만들어 내지 않음.
- `GET /api/replay/:code/original-build?awakener=:tid&actorLayers={...}&playerLayers={...}`: 기존 원본 Lua 엔진의 빌드 수치와 개별 카드 값. 상태 중첩은 명시적인 사용자 입력이며 기록의 특정 턴으로 가장하지 않음.

### Steam 없이 조회되는 정적 기능

`js/record-catalog-client.js`는 `RecordCatalogClient.create()`로 유물 검색/상세/수치, 이벤트/상대 일정 규칙, 아바타/테두리 검색, 시즌 목록을 읽는다. `data/relic_library.json`(418묶음/651ID), `event_library.json`, `profile_cosmetic_library.json`, `record_seasons.json`은 검증된 설정 결과만 포함한다. 계정 인증과 UID 전투 기록은 포함하지 않는다. 기존 수집실 범위의 `relic_catalog.json`과 기존 HTML은 변경하지 않았다.

모든 HTTP 쓰기를 거부한다. 다른 호스트/Origin의 요청을 거부하고, 조회 직렬화·2초 간격·시간당 60회·60초 캐시·출력 크기/시간 상한을 둔다. 전송 오류 원문이나 자격 증명을 HTTP 응답에 담지 않는다. 접근 불가/미확인/미수집을 실제 기록 없음과 혼동하지 않는다.

## 배포 경계와 다음 구현 순서

Cloudflare에 Steam 로그인·게임 프로토콜·개인 기록 테스트 파일을 올리지 않는다. 별도 공개 GET 중계 `workers/record-query-worker.mjs`와 Durable Object 속도 제한, 사설 원점 인증 및 설정을 구현했다. 배포/운영 연결은 하지 않았으며, 미구성 시 HTTP 503으로 실패한다. 운영 경계는 `record-query-relay.md`에 정리했다. 개인 Steam을 상시 공개 조회 서비스로 전환하지 않았다.

남은 핵심은 전역 기록 인덱스 운영, 열차 공유 기록 실표본, 전투 중 조건부 최종 스탯의 전수 검증, Eremora와의 비밀계약 평가·전체 유물 실행 의미 대조다. 열차 7기의 세 스테이지 129163/129164/129165 공개 클리어 목록도 직접 조회했으나 모두 0건이었다. 이는 열차 전체 기록 부재를 증명하지 않는다. 공개 실시간 게임 조회는 별도 Windows·Steam 조회 호스트의 운영 구성이 필요하다. 개인 Steam을 외부 공개 서비스로 노출하거나 임의로 상시 운영하지 않았다. 그 뒤 UI와 반응형 검증 및 공개 서비스 배포를 한다.
