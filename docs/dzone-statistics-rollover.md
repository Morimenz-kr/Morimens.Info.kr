# 융재금구 통계 기수 전환

- 수집 대상은 서버 `AbyssChallenge.OnOpen` 응답의 `activityTid`로 결정한다. 사이트의 `dzone_current.json`이나 가장 큰 미래 기수 번호를 사용하지 않는다.
- 실행 중인 게임에서 읽은 원본 Activity/Stage/StageGroup의 시작·종료 시각, 5개 구역과 35개 스테이지 ID를 대조한다. 클라이언트 설정 파일이 바뀌면 감시기가 메타데이터를 다시 읽는다.
- 기수별 체크포인트와 전체 기록 원본을 분리한다. 전체 기록 감사 후 서버 기수를 재확인한다. 도중에 기수가 변경되면 게시하지 않고 새 기수로 재시도한다.
- 게시기는 서버 확인 시각, 기수·시작 시각·35개 ID, 감사 결과와 스냅샷 SHA256을 검증한다. 종료 직전 게시와 이전 기수로의 역행을 거부한다.
- Windows `Morimens DZone Sync`는 한국 시간 매일 00·03·06·09·12·15·18·21시에 실행한다. 실패 시 5분 간격으로 3회 재시도하며, 실행 시각을 놓치면 재개한다. 게임 실행 중 중복 로그인하지 않고, 감시기가 게임 종료를 확인하면 수집을 요청한다. 컴퓨터가 꺼져 있거나 로그인하지 않은 동안의 실행은 지원하지 않는다.
- 화면은 1분마다 원본 일정과 공개 집계를 확인한다. 새 기수의 전투 정보가 아직 없으면 해당 기수의 35개 통계 구간만 제공한다. 이전 몬스터 정보를 새 기수에 붙이지 않는다. 사용자가 선택한 과거 기수는 유지한다.

공개 저장소에는 일정·스테이지 메타데이터와 집계만 게시한다. 수집기·인증 정보·원본 클리어 상세는 비공개 환경에 둔다.

검증: 73→74→75 일정 경계, 미래 99기 제외, 이전 기수/변경된 집계 게시 거부, 74기 전투 정보 누락과 73기 보관본 선택, 320·390·768·1024·1280px 및 글자 200% 확대.
