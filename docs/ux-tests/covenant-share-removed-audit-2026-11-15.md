# 공유 제거 후 독립 레드팀·UI 점검 — 2026-11-15

## 환경과 범위

codex/shared-covenant-editor 작업본. 소스8766과 생성사이트4185를 설치된 Chrome의 별도 테스트 프로필에서 확인했다. 레드팀과 UI 에이전트는 독립 브라우저에서 점검했다. 기존 사용자 프로필이나 공개 사이트를 변경하지 않았다. 모바일은 데스크톱 Chrome의 모바일 viewport·터치 context이며 실제 모바일 기기는 아니다.

## 레드팀

소스/산출물 × 320/390px의 4조건 모두 통과했다.

- 프리셋 A 저장(주옵12) → 목표에 먼저 불러오기 → 전사에도 불러오기.
- 전사 주옵6, 목표 부옵7·목표조건6으로 각각 수정.
- 원본 프리셋을 주옵3으로 덮어쓴 뒤 삭제해도 이미 불러온 두 탭 값은 유지.
- 목록 미선택 상태에서 불러오기를 눌러도 기존 값 불변.
- 새로고침 후 값 유지, 각 탭 순차 초기화 후에도 다른 두 탭과 원본 상태 불변.
- 공유 버튼·코드 입력·미리보기 및 구형 hash 자동 진입 없음. 페이지 실행 예외 없음.

증거: `.generated/scarecrow/redteam-v26-removed-share/results.json` 및 같은 폴더의 사이트/폭별 화면.

## UI

소스와 산출물에서 각각 세 탭 × 11조건, 총66조건 통과했다. 320/390/768/1024/1280px, 1101/1102/1103px, 가로844×390, 320/1280px 글자200%를 확인했다. DOM 경계와 스크린샷으로 넘침·능력치 잘림·버튼 겹침·도형 크기·결과 위치를 검사했다.

공유 진입점이나 비어 있는 전송 mount가 남지 않았다. 전사 편집창에서도 같은 결과다. 프리셋 저장·목록 불러오기·수치와 귀속 변경·각 탭 새로고침 후 원본12 / 편집9 / 전사7(귀속 켜짐) / 목표12(귀속 꺼짐, 부옵4)가 UI와 저장소에서 일치했다.

증거: `.generated/scarecrow/removed-share-ui/results.json` 및 세 탭·전사 편집창·저장실패 화면. 반응형 결과는 `simulator-layout-proof-8766/results.json`, `simulator-layout-proof-4185/results.json`.

## 발견과 보완

긴 교차 흐름 후 320×640에서 저장실패 안내 하단이 viewport를 약0.39px 넘는 정밀 경계가 있었다. 글자 자체는 읽혔으나 화면 끝에 밀착되어, v27에서 안내에 `scroll-margin-block: .5rem`을 추가했다. 일반 상태의 배치나 데이터는 바꾸지 않는다. UI 에이전트의 v27 소스 별도 저장실패 검사는 통과했다. 기존 공유 설명은 현재 기능과 혼동하지 않도록 제거 전 기록으로 표시했다.

모델·목표 단위 검사14개 통과. v27 소스와 산출물 모두 `tools/test-covenant-isolation.mjs`의 엄격한 화면 경계 검사를 수정하지 않은 채 최종 통과했다. 저장실패 안내, 저장 복구, 모달 닫기 포커스, 원본·타 탭 불변 및 새로고침까지 확인했다.

중간 소스 실행 한 차례에서 전사 버튼 대기 타임아웃이 있었으나, 당시 활성 탭·오버레이 증거가 없어 원인은 미확정이다. 완료된 빌드 상태에서 최종 재실행과 독립 교차검사는 통과했으며 제품 결함으로 재현되지 않았다.
