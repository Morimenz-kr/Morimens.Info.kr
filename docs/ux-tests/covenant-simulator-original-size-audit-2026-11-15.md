# 기존 비밀계약 크기를 유지한 세 탭 독립 점검

기능 레드팀과 UI 에이전트를 분리해 세팅·프리셋, 전사, 목표 화면을 점검했다. 기존 크기는 실제 육각형 최대 320px이며, 입력·결과와 아이콘·이름·수치 표의 공통 구조를 유지한다. 사용자 Chrome 저장소 대신 독립 모바일 터치 저장소를 사용했다.

## 발견과 수정

1. 전사·목표의 기본 능력치 표에서 아래 네 속성이 가려졌다. 결과 영역의 128px flex 기준이 본문을 83px로 줄이고, 그 안의 별도 스크롤이 실제 218px 내용을 숨겼다. 결과를 자연 높이로 계산하고 본문을 블록으로 배치하며 자식의 중첩 스크롤을 제거했다. 긴 실행 결과만 바깥 결과 본문 한 곳에서 스크롤한다.
2. 글자 200%에서는 `22rem` 이미지 프레임이 커졌다. 프레임 상한을 원래 기본 크기인 352px로 고정해 글자 확대와 이미지 크기를 분리했다. 모바일에서는 컨테이너에 맞게 줄어든다.
3. 왼쪽 프레임이 오른쪽 내용 높이에 맞춰 늘어나며 모드마다 불필요한 세로 여백이 달랐다. 그림 프레임을 자신의 내용 높이로 상단 정렬했다. 1280px에서 세 모드 모두 프레임 435.5px, 이미지 320px, 프레임 안의 상대 상단 위치가 같다.

## 검증

`tools/test-covenant-simulator-layout.mjs`는 세 모드 × 11개 조건, 총 33조건을 검사한다. 320·390·768·1024·1280×900, 844×390, 64rem 전환의 1101·1102·1103px, 320px와 1280px 글자 200%다. 모든 속성 행의 실제 경계를 부모 스크롤/클리핑 경계와 비교해 여덟 행 전체가 보이는 것을 확인한다. 세 모드의 이미지 크기를 대조하고 1280px에서는 글자 확대 여부와 관계없이 320px인지 검사한다.

소스와 산출물 모두 같은 기능·반응형 33조건을 통과했다. 세팅 입력·목표값·전사 교체·프리셋·재접속, 오류의 모드별 보존과 실제 가중치 계산도 검사했다. 실행 로그는 `D:/MorimensCodexTemp/v8-audit-{source,artifact}.log`, 화면과 DOM 결과는 `.generated/scarecrow/simulator-layout-proof-{8766,4185}/`에 있다.

UI 에이전트는 기본 세 모드의 프레임과 이미지 일치, 능력치 여덟 개의 완전한 표시, 중첩 스크롤 제거를 독립 측정했다. 강화 7 입력 후 전체 보기·부위 편집 왕복과 1280·390·320px 전환에서도 값을 유지했다. 스타일에 `overflow:auto`가 있다는 이유만으로 실패시키던 최초 검사 가정은 실제 스크롤 높이 검사로 고쳤으며 제품 오류와 구분했다.

최종 UI 독립 검사에서는 소스 33조건에 양 서버 12조건을 추가 대조했다. 증거는 `D:/MorimensCodexTemp/ui-audit-v8-{proof,overview-proof,cross-final}.json`이다. 실제 사용자 Chrome에도 갱신했으며 화면은 `D:/MorimensCodexTemp/v8-audit-user.png`다.

기능 레드팀은 최종 v8 소스 320px·산출물 390px에서 세팅의 실제 VI 주옵·강화 변경, 두 잠금과 가중치 전사·교체, 재접속·프리셋·저장 실패 시 원본 보존을 확인했다. 목표의 범위·현재/목표값·오류·모드별 결과 유지, 실제 터치 중단도 통과했다. 모두 장착한 6부위의 목표는 총 6회·금권 45,000·인장 18로 일치했고, 긴 결과의 마지막 VI 카드도 완전히 스크롤해 볼 수 있었다. 두 서버 모두 데스크톱 전환 후 아트 폭 320px를 유지했다. 실행 예외와 추가 확정 문제는 없었다(`D:/MorimensCodexTemp/redteam-v8-mobile-proof.json`). 최초 긴 결과 검사의 미장착 차단은 시험 자료에 빈 부위가 있었기 때문이므로, 모두 장착하는 실제 UI 절차를 거친 뒤 다시 검사했다.

검증은 확인한 화면·조작 범위에 한정한다. 배포와 비공개 게임 데이터는 변경하지 않는다.
