# 전사·목표 새 배치의 모바일·UI 독립 점검

기능 레드팀과 UI 감사 에이전트를 분리해 점검했다. 사용자 Chrome 저장소를 사용하지 않고, 독립 모바일 터치 컨텍스트에서 실제 화면과 입력·결과·저장을 확인했다. 원칙은 조작 패널의 폭을 줄여 결과를 옆에 두되, 비밀계약의 높이 안에서 조작 가능하게 하는 것이다.

## 기능 레드팀

미장착 전사 차단, Ⅵ 부위의 두 잠금 보존, 실제 가중치 전사와 교체, 즉시 새로고침, 일반 프리셋 복원과 덮어쓰기 실패 시 기존 데이터 보존을 확인했다. 목표에서는 부위별 현재값·목표값·계산 범위와 보기 탭을 바꾸며 저장을 확인했다. 실제 1회 전사의 금권 7,500·천면 인장 3, 결과 아이콘, 모드별 결과 유지와 결과 패널의 단일 배치를 대조했다. 실행 진입을 확인한 후 중단·다른 화면 이동을 해도 늦은 결과가 되살아나지 않았다.

수정 후 320·390px에서 목표 입력 오류와 프리셋 저장 실패가 모드 왕복 후 복원되고 전사 화면에는 섞이지 않는 것을 독립 재검증했다. 보기 탭 변경은 안내를 유지하고, 입력 수정·저장 재시도 성공은 안내를 해제한다. 브라우저 실행 예외는 없었다.

기능 증거는 `D:/MorimensCodexTemp/redteam-v4-mobile-proof.json`, `redteam-v5-status-proof.json`과 대응 로그·화면이다. 재현 스크립트는 `.generated/scarecrow/redteam-v4-mobile.mjs`, `redteam-v5-status.mjs`다.

## UI와 반응형 검증

UI 에이전트는 원본 글꼴의 최장 옵션명이 390px의 한 줄 입력에 들어가는 것을 실제로 측정했다. 320px·글자 200%는 자동으로 두 줄로 복귀한다. 프리셋을 펼친 뒤 이름·저장·불러오기·삭제를 내부 스크롤로 모두 노출할 수 있고, 실제 중심점이 해당 조작에 닿는 것을 확인했다.

공용 재현 스크립트 `tools/test-covenant-simulator-layout.mjs`에는 오류의 모드별 보존·입력 수정 후 해제·실제 가중치 계산 성공을 추가했다. 320·390·768·1024·1280×900, 844×390, 320×900 글자 200%, 48rem 전환 845·846·847px, 70rem 전환 1197·1198·1199px, 입력 분기 369·370·371px를 두 모드에서 검사한다. 나란히 배치된 조작·결과의 높이, 프리셋 접기의 기본 노출, 가로 넘침, 44px 터치 영역과 이미지 표시를 확인한다.

소스 결과는 `D:/MorimensCodexTemp/vertical-v5-source.log`, UI 독립 측정은 `ui-audit-v5-proof.json`, 열린 프리셋은 `ui-audit-v5-preset-proof.json`에 있다. 이 점검은 실제 테스트한 화면과 조작 범위에 대한 결과다. 배포나 공개 게임 데이터는 변경하지 않는다.
