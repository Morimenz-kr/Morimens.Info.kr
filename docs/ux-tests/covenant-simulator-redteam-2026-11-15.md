# 비밀계약 시뮬레이터 레드팀 점검 — 2026-11-15

## 범위와 방법

세팅·프리셋, 전사, 목표 시뮬레이션을 독립 Chrome 저장소에서 점검했다. 주 작업은 세팅·저장·프리셋과 전체 모드 반응형을, 독립 레드팀은 전사·목표 계산·중단·비동기 경합을 담당했다. 사용자의 실제 파티와 프리셋을 시험 데이터로 사용하지 않았다.

정상 순서뿐 아니라 주옵션 미설정, 빈 부옵션, 동일 옵션 중복, 혼합 계약, 미장착 부위, 가져오기 직후 재접속, 실행 도중 초기화·모드 변경·목표 수정, 저장 차단·용량 부족, 느린 로딩과 요청 실패를 재현했다.

## 발견 및 수정

| 문제 | 수정 |

| 이름을 비운 프리셋 저장에서 `partIndex is not defined` 발생 | 세팅과 목표 프리셋 모두 실제 계약 구성으로 기본 이름을 만든다. 혼합·미장착도 구분한다. |
| 저장 실패 시 메모리의 프리셋은 이미 변경되고 성공 문구가 표시될 수 있음 | 저장 성공 후 목록을 교체한다. 실패한 저장·덮어쓰기·삭제는 기존 프리셋을 유지하며 실패를 알린다. 저장이 차단된 브라우저에서도 앱을 사용할 수 있다. |

| 빈 부옵션에 잠금이 남아 전사 비용과 결과에 영향 | 초기화·가져오기·구형 저장 정규화에서 빈 옵션과 미장착 부위의 잠금을 제거한다. 전사도 유효 옵션의 잠금만 계산한다. |
| 같은 옵션의 서로 다른 최소 레벨 목표를 순서대로 잘못 매칭 | 최대 매칭으로 별도 행을 배정하고 엄격한 목표를 보존한다. 이미 달성한 목표에는 0회·0비용을 표시한다. |
| 목표 확률을 더하고 목표를 강제로 주입하며 8단계 후 무료 완성 | 실제 행별 추첨을 반복한다. 강제 달성을 제거하고 각 전사의 실제 잠금 비용을 누적한다. |
| 미장착 부위에 목표 전사 실행 | 해당 부위의 비밀계약 장착을 안내하며 실행을 차단한다. |
| 실행 중 초기화·목표 변경 뒤 늦은 결과가 되살아남 | 실행 스냅샷과 취소 토큰을 사용한다. 중단 버튼을 제공하고, 초기화·설정 변경 시 이전 실행을 취소한다. |
| 목표 화면의 계약 이름과 결과 수치가 편집 세팅을 따라 바뀜 | 목표 데이터로 이름을 표시하고 결과의 계약·귀속 정보를 실행 시점에 고정한다. |
| 빈 주옵·부옵이 드롭다운의 첫 옵션으로 보임 | 미설정·없음 선택지를 표시하고 빈 부옵 레벨을 비활성화한다. 목표 프리셋도 미설정 주옵을 보존한다. |
| 미장착 부위에 보존된 옵션이 전사 완성도에 포함됨 | 명시적인 미장착 부위를 완성도에서 제외한다. 구형 기본 계약 저장값은 유지한다. |
| 시뮬레이션 초기화 후 잠금 비용 선택이 남음 | 전사·목표의 비용 설정도 기본값으로 복원하고 재접속 후 유지한다. |

프리셋 이름과 목표 입력에는 구분 가능한 접근성 이름을 부여했다. 74기·유물 세트 효과·공개 게임 데이터는 변경하지 않았다.

## 검증 결과

- 후속 실제 가중치 반영까지 전체 단위 테스트 512건 통과. 목표 모델 7건에는 여섯 부위의 800개 가중 추첨 구간 전수 확인, 중복 목표 매칭, 독립 기하분포·Markov 기대 횟수 대조, 비용과 확률 자료 누락 시 차단 검사가 포함된다.
- 세 모드 × 7개 화면 조건, 총 21개 조건 통과: 320·390·768·1024·1280×900, 844×390, 320×900 글자 200%. 모바일 터치, 가로 넘침·잘림, 탭과 주 조작을 확인했다. 전사·목표는 독립 레드팀도 화면과 DOM을 별도로 검증했다.
- 기존 공용 편집기 왕복·저장·프리셋·전사·손상 입력 회귀와 반응형 18개 조건이 최종 빌드에서 통과했다. ScareCrow 빌드와 자바스크립트 문법 검사도 통과했다.
- 전사 잠금 1개의 잔본 20/깃펜 1, 잠금 2개의 깃펜 10, 세 번째 잠금 거부, 잠금 값 보존, 교체·복사·재접속을 검증했다.
- 목표의 중복 Lv.8 달성, 회당 금권 7,500·천면 인장 3 누적, 중단·초기화·목표 변경 후 이전 실행 폐기, 편집 귀속을 바꿔도 완료 결과가 보존되는 것을 확인했다.
- 이름 없는 프리셋, 특수문자 이름, 저장·덮어쓰기·삭제 실패 시 기존 데이터 보존, 브라우저 저장 차단, 자동 저장과 이전 프리셋 복원을 확인했다.
- 지연 응답 중 폼 컨트롤 23개 비활성화, 준비 후 기본 프리셋 이름 복원, 로딩 실패 안내, 성공·실패 경로의 브라우저 예외 0건을 확인했다.

## 확률 모델의 한계

이 최초 점검에서는 기존 균등 모형 안의 오류만 검증했다. 후속 요청으로 실제 설치 클라이언트의 번들과 상수를 대조했고, 레벨의 균등 가정이 잘못됐음을 확인했다. 현재는 옵션별 가중치와 Lv.1~8의 23·20·17·14·11·8·5·2 가중치를 [검증된 추출 자료](../covenant-roll-rates.md)에서 읽는다. 전사와 목표 계산의 균등 대체 경로를 제거했다. 검증 대상은 클라이언트 설정이며 서버 내부 코드를 확인했다는 의미는 아니다.

## 로컬 증거와 재현

### 전사·목표의 비밀계약 시각화 후속 검증

전사는 실제 부위 이미지의 육각형에서 한 부위를 선택하고, 목표는 같은 육각형에서 여러 부위를 선택한다. 두 모드의 원래 설정·프리셋·선택 범위 저장 형식은 유지한다. 동일 계약의 중앙 문양, 혼합 계약의 부위별 이미지, 미장착의 빈 면을 확인했다. 목표 마지막 부위를 해제하려는 경우 안내는 육각형 바로 아래에 표시한다.

소스와 빌드 산출물에서 각각 두 모드 × 7개 조건(320·390·768·1024·1280×900, 844×390, 320×900 글자 200%)을 검증했다. 이미지 6개 로딩, 비율 유지, 각 숫자 버튼 44px 이상, 버튼 겹침 없음, 실제 중심점 터치 가능, 가로 넘침 없음을 대조했다. 전사 6부위 전환·재접속, 같은 부위 재선택 시 전사 결과 보존, 목표 다중 선택·최소 하나 유지·Space 조작·재접속, 필터 전환 후 목표값 보존을 확인했다. 빈 장비에서는 전사·목표 실행을 계속 차단한다.

단위 테스트 512건, 기존 공용 편집기 회귀·반응형 18개 조건, 가중 전사·목표 계산 검사가 통과했다. `.generated/scarecrow/visual-contract-proof/`, `visual-contract-artifact-proof/`에 화면과 DOM 결과를 남긴다. 재현 스크립트는 `.generated/scarecrow/test-visual-contract{,-artifact,-edges}.mjs`, 로그는 `D:/MorimensCodexTemp/covenant-visual-{proof,artifact,edges,shared,unit,build,weighted}.log`다.

열려 있던 기존 Chrome 탭에서는 구버전 스타일과 부위 선택 모듈이 재사용되어 새 화면과 섞이는 사례를 발견했다. 페이지 리소스 버전을 `covenant-visual-20261115-1`로 갱신하고 직접 불러오는 ESM에도 같은 페이지·자산 버전을 붙였다. 계약·편집·확률 JSON은 재검증해서 읽는다. 같은 기존 탭을 다시 로드한 뒤 목표의 여섯 선택 표시와 오른쪽 조작부 배치가 정상인 것을 확인했다.

### 새 육각형 UI 독립 레드팀 재점검

새 UI 적용 후 독립 레드팀이 모바일 Chrome 터치 컨텍스트에서 소스(8766)와 빌드 산출물(4185)을 각각 검사했다. 혼합 계약·귀속·미장착 부위를 포함한 별도 자료로 숫자 여섯 개와 실제 그림 영역을 직접 터치했다. 한 부위만 선택됨, 미장착 전사 차단, 같은 부위 재선택 시 미리보기 유지, 다른 부위 선택 시 미리보기 폐기, 잠금 후 전사·교체와 즉시 새로고침 복원을 확인했다.

목표에서는 그림과 숫자의 다중 선택, 마지막 대상 해제 거부 및 가까운 안내, 선택에서 제외했다 다시 넣은 부위의 목표값 보존, 목표 프리셋을 불러온 뒤 대상 범위·옵션·레벨과 새로고침 복원을 확인했다. 두 서버에서 브라우저 실행 예외는 없었다. 이번 재점검에서 확정한 새 제품 결함은 없다.

독립 레드팀은 각 서버에서 전사·목표 × 7개 화면 조건을 점검했다. 주 작업에서도 소스·빌드의 같은 28개 조건, 전체 동일 계약의 문양, 빈 장비의 실행 차단, 저장 실패 시 프리셋 보존, 저장 차단 안내와 목표 모델 7개 테스트를 다시 통과했다. 화면은 320·390·768·1024·1280×900, 가로 844×390, 320×900 글자 200%다. DOM 측정과 화면을 대조해 가로 넘침, 숫자 겹침, 44px 터치 영역, 이미지 비율과 선택 표시를 확인했다.

계산 취소는 각 경로마다 장착 자료와 미달성 목표를 다시 불러온 뒤 실제 실행 상태(`run.disabled`, 중단 버튼 표시)를 먼저 확인했다. 육각형 대상 변경·목표 프리셋 로드·초기화·모드 이탈의 네 경로가 양 서버에서 모두 실행을 해제하고, 기다린 뒤에도 이전 결과를 표시하지 않았다. 추가로 전사·교체한 Ⅴ 부위의 부옵 세 행이 세팅 복사에 그대로 포함되며, 일반 프리셋 저장→초기화→불러오기→새로고침 후에도 같은 수치와 선택 부위를 보존하는 것을 양 서버에서 확인했다(`redteam-hex-copy.mjs`, `D:/MorimensCodexTemp/redteam-hex-copy.log`).

재현 자료: `.generated/scarecrow/redteam-hex-ui.mjs`, `redteam-hex-cancel.mjs`, `D:/MorimensCodexTemp/redteam-hex-ui.log`, `redteam-hex-proof.json`, `redteam-hex-cancel-proof.json`. 검사 준비 단계에서는 숨겨진 편집기 DOM을 보이기까지 기다리는 테스트 오류가 있었다. 준비 기준을 DOM 존재·로딩 완료·실제 활성 모드로 고쳐 재실행했으며, 이를 제품 결함이나 통과 결과에 섞지 않았다. 취소 검사는 실행 진입을 입증하지 않은 첫 결과를 채택하지 않고 위 조건으로 보강했다.

이 증거는 검사한 상태 전환과 입력 범위에 대한 결과이며, 모든 브라우저·저장 형식·조작 조합의 무결함을 보장하지는 않는다.
