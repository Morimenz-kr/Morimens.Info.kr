# 전사·목표 UI 배치 점검 — 2026-11-15

## 독립 감사에서 확인한 문제

- 전사는 현재 옵션과 전사를 각각 카드로 쌓아, 1280px에서 왼쪽 472.7px에 비해 오른쪽이 630.3px이었다. 1024px에서는 오른쪽이 719.3px으로 늘었다. 부옵 세 개의 2+1 배치와 중복 제목·테두리·패딩이 원인이었다.
- 모바일의 기존 `#manual-result` 최소 높이 규칙 때문에 비어 있는 결과도 크게 자리를 차지했다.
- 목표 화면은 왼쪽 비밀계약 옆에 비용과 프리셋만 두고, 실제 현재값·목표 입력과 실행을 전폭으로 아래에 나열했다. 390px에서 여섯 현재값 카드와 여섯 목표 카드가 각각 약 1382px·1700px이었다.
- 선택된 번호에 원형 배경과 테두리가 생겼다. 고정 버그 제보 버튼은 오른쪽 입력을 일부 가렸다.

## 적용한 배치

선택 번호의 원형 배경·테두리를 없앴다. 선택은 글자색·밑줄로, 키보드 포커스는 별도 윤곽선으로 구분한다. 터치 영역은 44px 이상을 유지한다.

전사는 한 패널에서 현재 부옵과 결과를 비교한다. 중복 카드와 전사 제목, 큰 빈 결과 영역을 제거했다. 완성도·비용·잠금 비용을 이어 배치하며 전사·교체 버튼은 아래에 둔다.

목표의 육각형은 계산 대상의 다중 선택을 유지한다. 오른쪽은 대상 중 편집할 부위를 Ⅰ~Ⅵ 순서로 고르고, 현재 부옵·목표 조건 탭에서 한 부위씩 편집한다. 제외하거나 화면에서 숨긴 부위의 입력값을 지우지 않는다. 목표 프리셋은 접을 수 있으며 비용·실행·중단은 아래에 유지한다. 편집 부위와 현재/목표 탭은 자동 저장·재접속에서 복원한다.

44rem 이상 컨테이너에서는 왼쪽 비밀계약이 행 높이를 결정한다. 오른쪽의 내용을 크기 계산에서 제외하고 같은 높이로 배치한다. 내용이 더 길 때 오른쪽 본문만 스크롤하고 실행 버튼은 그대로 노출한다. 1280·1024px에서 두 모드의 좌우 패널 높이는 모두 약 433.47px이다. 작은 화면에서는 한 열과 자연스러운 높이로 전환하고, 24rem 이하 입력 영역에서는 옵션·레벨을 세로로 풀어 좁아지는 드롭다운을 방지한다. 버그 제보는 상단 초기화 옆의 일반 버튼으로 옮겨 입력을 가리지 않는다.

## 검증과 재현

`tools/test-covenant-simulator-layout.mjs`는 독립 Chrome 터치 저장소로 전사·교체·즉시 재접속, 여섯 부위의 서로 다른 목표값, 현재/목표 전환, 대상 제외와 복원, 프리셋 저장·불러오기, 편집 부위·현재값 복원, Home/End 조작을 검증한다. 소스 8766과 빌드 산출물 4185 양쪽에서 통과했다.

각 서버에서 두 모드 × 13개 화면 조건을 확인했다. 기본 320·390·768·1024·1280×900, 844×390, 320×900 글자 200%에 44rem 경계의 781·782·783px와 입력 재배치 경계의 859·860·861px를 추가했다. DOM으로 좌우 높이·가로 넘침·44px 터치 영역·선택 배경 투명을 측정하고 화면을 함께 확인했다. 나란히 배치된 모든 조건에서 오른쪽은 왼쪽 높이를 넘지 않았다.

독립 에이전트는 가장 좁은 두 열 배치인 782px에서도 양 서버의 여섯 부위 현재값·목표값 보존, 전사 잠금·가중 추첨·교체, 목표 1회 달성과 금권 7,500·천면 인장 3, 프리셋 불러오기·재접속을 별도로 확인했다. 프리셋을 펼쳐 본문이 길어져도 내부 스크롤로 입력 전체와 저장·불러오기에 접근할 수 있고, 실행 버튼은 패널 안에 유지됐다. 실제 실행 진입을 확인한 후 계산 대상 변경·프리셋 불러오기에서 실행 취소와 늦은 결과 폐기를 양 서버에서 검증했다. 입력 영역의 24rem 경계도 별도로 확인해 859·860px에서는 옵션을 한 줄 전체에, 861px에서는 옵션·레벨·체크를 나란히 배치함을 확인했다. 실제 사용자 Chrome도 다시 로드해 원형 제거와 좌우 정렬을 확인했다.

결과와 화면은 `.generated/scarecrow/simulator-layout-proof-{8766,4185}/`에, 실행 로그는 `D:/MorimensCodexTemp/covenant-layout-{source,artifact}.log`에 있다. 이전 배치의 독립 측정과 화면은 `D:/MorimensCodexTemp/spacing-before-proof.json`, `spacing-before-*.png`에 남겼다. 공용 편집기 왕복·저장·프리셋·전사와 반응형 18개 회귀 조건, 전체 단위 테스트 512건도 통과했다. 실제 사용자 Chrome의 최종 화면은 `D:/MorimensCodexTemp/covenant-layout-user.png`다.

## 오른쪽 결과와 중복 안내 정리

후속 요청에서 사용자가 제거를 원한 텍스트는 선택 상태에서 이미 알 수 있는 설명으로 범위를 명확히 했다. 육각형 아래의 `계산 대상: Ⅰ·Ⅱ…`, 중복 계약명, 전사/목표의 조작 안내, 프리셋의 자명한 설명을 제거했다. 실제 옵션명·수치·소모량과 오류/저장 실패 안내는 유지한다.

64rem 이상에서는 비밀계약·조작·결과의 세 열로 배치한다. 1280px에서 조작 패널은 이전 약 838px에서 413px로 줄었으며 같은 폭의 결과를 바로 옆에 둔다. 세 패널 모두 비밀계약의 약 397.47px 높이에 맞는다. 중간 폭에서는 결과를 아래로, 작은 화면에서는 전체를 한 열로 전환한다. 현재 부옵과 겹치던 별도 미리보기 칸 대신 옆 결과 패널에서 선택 부위의 전사 결과를 확인하고 교체한다.

결과의 부옵과 전체 합계에는 기존 공용 편집기의 원본 속성 아이콘 8개를 사용한다. 대체 텍스트와 아이콘 이름을 유지하고 빌드에도 자산을 명시적으로 포함한다. 전사는 해당 부위만, 목표는 실제 계산한 부위만 펼쳐 표시한다. 전체 합계는 결과 아래에서 접어 둘 수 있다. 실행 결과와 소모량은 여전히 동일한 데이터에서 계산한다.
