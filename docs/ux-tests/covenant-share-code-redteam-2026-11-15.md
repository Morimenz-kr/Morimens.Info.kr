## 범위

작업본 codex/shared-covenant-editor, 소스8766/생성사이트4185, MR1-72자 공유 코드. 두 독립 에이전트가 정상 UI 교차 사례와 별도 fixture를 점검했다. 실제 사용자 크롬과 OS 클립보드는 테스트에 사용하지 않았다. 복사 성공/거부/지연은 격리 브라우저의 합성 navigator.clipboard API로 검증했다.

## 발견 및 수정

1. 복사 응답 지연 중 창을 닫고 다시 열거나 받은 코드를 입력하면 이전 응답이 안내와 포커스를 덮었다. 현재 연결된 창과 feedback revision이 일치할 때만 응답을 반영한다. 새 입력/포커스/코드 검증은 이전 응답을 무효화한다.
2. 가로844×390에서 복사 거부 안내가 y386–409로 메뉴/화면 밖에 있었다. 단일 안내 노드를 복사는 복사 버튼 뒤, 코드 검증은 받은 입력 뒤에 배치한다. 수정 후 y257–280으로 완전히 표시된다.
3. 공유 코드 가져오기 중 상태 저장이 실패하면 미리보기는 남는데 메모리 세팅은 바뀌었다. applyImportedEquipment를 후보 스냅샷 선저장 후 commit 방식으로 바꿨다. 실패 시 현재 탭/세 은행/pending/결과를 유지하고, 같은 미리보기에서 저장 복구 후 재시도한다. 프리셋 목록 불러오기도 같은 방식이며 실패 때 거짓 성공 문구를 표시하지 않는다.

## 후속 검증: 실제 Chrome 클립보드

사용자 요청에 따라 위 합성 클립보드 검사와 별도로 Windows에 설치된 Chrome 157.0.8103.51을 실제 창으로 실행했다. 기존 사용자 프로필을 보호하기 위해 격리된 테스트 프로필을 사용했다. 소스8766과 생성사이트4185 모두 통과했다.

- 실제 UI의 공유 코드 복사 버튼 → 네이티브 Clipboard.writeText → 받은 코드 입력란 클릭 → Control+V를 수행했다. API 대체, 클립보드 권한 강제 설정, 입력란에 코드 직접 주입을 사용하지 않았다.
- 각 사이트에서 복사 2회, 실제 붙여넣기 3회를 확인했다. 붙여넣기 이벤트는 isTrusted=true이며 OS 클립보드에서 전달된 72자가 원본 코드와 일치했다.
- 1280px에서 미리보기·취소가 원본과 세 탭 데이터를 변경하지 않는지 확인했다. 390×844px에서는 전사와 목표 각각 실제 붙여넣기 → 미리보기 → 가져오기 → 새로고침을 확인했다. 모바일 너비의 데스크톱 Chrome 검사이며 실제 모바일 기기 검사는 아니다.
- 전사로 가져와도 프리셋 편집값·목표값·저장된 원본 프리셋은 유지됐다. 목표로 가져와도 전사값·프리셋 편집값·목표 조건·저장된 원본은 유지됐다.
- 가져온 전사 값을 다시 수정하고 귀속을 해제한 뒤 새로고침했다. 최종 주옵 레벨은 저장된 원본12 / 프리셋 편집9 / 전사7 / 목표12, 귀속은 편집 켜짐 / 전사 꺼짐 / 목표 켜짐으로 양쪽 사이트 모두 독립적으로 복원됐다.
- 두 실행 모두 페이지 실행 예외는 없었다. 이 검증에서 새 제품 결함은 발견되지 않았으며 앱 코드는 변경하지 않았다.
