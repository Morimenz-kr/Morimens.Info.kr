# 세팅·프리셋 / 전사 / 목표 분리 · v14

사용자 지정: 세 모드는 배치와 데이터가 모두 독립이다. 저장된 장비 프리셋을 전사/목표에서 명시적으로 불러오는 것은 허용한다.

## 동작

- 프리셋: editorParts/editorBound. 저장 프리셋에는 이 장비와 귀속만 포함한다.
- 전사: parts/contractBound, 선택 부위, 자체 세팅 편집 대화상자, 잠금·비용, 미리보기·교체·결과.
- 목표: targetSimParts/targetBound, 현재 옵션·목표·대상 부위·비용·결과. 자체 계약 선택도 지원한다.
- 불러오기는 장비 세팅의 깊은 복사다. 이후 변경은 원본 프리셋이나 다른 모드에 반영하지 않는다. 목표 조건은 유지한다.
- 각 모드의 상단 초기화 버튼은 현재 모드만 초기화한다.
- 상태 version 3은 세 모드를 저장하며 전사 미리보기/결과/비용과 목표 완료 결과도 새로고침 후 복구한다. 구형 공유 상태는 프리셋/전사로 독립 복사하고 기존 목표 값을 유지한다.
- 구형 장비 프리셋의 다른 모드 상태는 불러오지 않는다. 목표 프리셋 version 2에는 목표 자체의 장비/현재값/조건/귀속을 저장한다.

## 배치

기존 두 열과 그림 최대 320px를 유지한다. 프리셋 그림은 기존 상단 정렬이다. 전사와 목표의 세로 중앙 정렬은 각 패널에 따로 선언한다. 입력과 결과는 오른쪽에 유지한다. 좁은 화면은 기존 세로 흐름을 유지한다. 전사 자체 편집창도 320px와 글자 200%에서 넘치지 않도록 버튼 최소 폭을 해제한다.

## v15 레드팀 후속 수정

전사 자체 편집창에서 귀속만 바꿔도 미리보기가 지워지는 문제를 재현했다. 장비 모델이 lastTouched를 true로 쓰는 것을 옵션 변경으로 오인한 원인이었다. 세트/주옵/레벨/부옵의 실질 변경만 비교하고 귀속 단독 변경에서는 lastTouched와 미리보기·결과를 보존한다.

자체 편집창에서 다른 부위를 고를 때는 이전 부위의 미리보기와 결과를 폐기하여 다른 부위로 잘못 교체하는 일을 막는다. `tools/test-covenant-isolation.mjs`에 최초 미수정 장비에서 귀속 변경 후 미리보기/교체 유지, 다른 부위 선택 후 교체 비활성, 다른 두 모드 원본 보존, 새로고침 후 선택 부위/비활성 유지를 회귀로 추가했다.

## v16–v17 독립 에이전트 발견과 수정

- 레드팀: 혼합 계약의 Ⅵ 부위 선택창이 Ⅰ 계약을 선택 표시했다. 현재 편집 부위의 계약 ID로 선택 표시를 복구했다.
- UI 에이전트: 중첩 선택창에서 계약을 고르면 편집기 재생성으로 키보드 포커스가 BODY로 빠졌다. 재생성 후 원래 전체/부위 변경 버튼으로 복귀시킨다. ESC와 닫기는 기존 복귀를 유지한다.
- UI 에이전트: 전사 편집창의 margin:auto 누락으로 왼쪽 위에 붙고 닫기 글자가 검정색으로 표시됐다. 중앙 정렬과 기존 계약 선택창의 닫기 색/배경/테두리/포커스 스타일을 적용했다.
- 레드팀: v14가 만들 수 있는 ‘결과 부위와 선택 부위가 다른’ 저장값을 복원하면 잘못된 부위로 교체할 수 있었다. 로드 시 어긋난 미리보기/결과를 폐기하고 교체 실행에도 부위 검증을 추가했다. 장착 옵션과 다른 두 모드는 보존한다.

상기 재현을 `tools/test-covenant-isolation.mjs`에 추가했다. 에이전트 증거는 D:/MorimensCodexTemp의 redteam-v14-*와 ui-v14-* 기록에 있으며 이름은 최초 점검 버전 기준이다.

## v18 저장 실패 안내와 그림 바깥 카드

UI 에이전트는 320×640에서 전사 중 저장 실패 안내가 화면 위쪽 바깥에 남는 것을 확인했다. 단일 live-region인 storage-status를 현재 조작 중인 전사/목표 footer(자체 편집창이 열려 있으면 해당 dialog)로 이동하고, 실패 안내가 화면 밖이면 nearest scroll로 보이게 한다. 프리셋 탭에서는 프리셋 controls 바로 아래에 둔다. 중복 live-region은 생성하지 않는다. 320×640의 실제 전사·저장 실패, 저장 원본 보존, 안내 화면 내 위치를 durable isolation 테스트로 확인한다.

후속 사용자 요청으로 메인 세 탭의 비밀계약 그림 바깥 카드 테두리/배경만 투명화했다. 패딩과 1px 레이아웃 경계를 유지해 아트 크기·정렬 및 오른쪽 UI 배치를 바꾸지 않는다.

## v19 저장 오류 상태에서 닫기 재검증

UI 에이전트가 숫자 입력의 blur 재저장 실패가 자동 스크롤을 반복해 닫기 첫 클릭을 놓치는 문제를 추가 재현했다. 자동 스크롤은 첫 실패 또는 안내 화면(editor/manual/target/manual-dialog)이 바뀔 때만 수행한다. 같은 화면의 반복 실패는 포커스와 클릭을 이동시키지 않는다. Durable isolation 테스트에 강제 quota 실패 → 자체 편집 숫자 수정 → 경고 노출 → 닫기 첫 탭 → 목표 탭 이동, 기존 저장 원본 유지 검증을 추가했다.

## 최종 독립 점검 결과

레드팀 v17 정상 UI 교차 검사와 v19 수정 후 루트 회귀, UI 에이전트 v19 재검증을 완료했다. 검사 범위에서 남은 확정 문제는 없다.

- 긴 프리셋을 저장·두 모드에 불러온 상태: 소스/산출물 세 탭 × 11조건 = 66조건 통과. 최대 아트 320px와 각 탭 정렬, 사각 카드 제거, 7/9/7로 서로 다른 수치와 귀속, 탭/새로고침 보존.
- 소스/산출물의 일반 편집기/전사 편집기 전체/부위 선택 8개 포커스 경로, 모바일/글자 확대 모달 6조건 통과.
- 저장 실패 안내 manual/target/dialog × 두 서버 = 6조건 통과. 단일 live-region, 최초 노출, 실패 후 Tab/닫기 첫 탭과 안내 footer 복귀 정상.
- 원본 프리셋 덮어쓰기/삭제 뒤 복사본·pending·이력·비용 불변, 선택 없는 불러오기 무변경, 각 모드 초기화 독립, 목표 프리셋 quota 실패 원본 보존.
- v14가 만들 수 있었던 잘못된 부위 pending fixture의 폐기와 교체 비활성, 장착 원본 보존.
