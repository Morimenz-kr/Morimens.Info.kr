## 관찰과 해석

**관찰:** 이전의 ‘구역 통계→개별 스킬→사용현황→조건 재입력→미수집 첫 카드’ 경로가 ‘파티 세팅 보기→공개 기록→구역에 담기→편성기’로 줄었다. 장비와 계약 원본이 편성기에 연결되고, 기존 PAGE 1을 보존하며, 새로고침해도 담은 다섯 파티가 남았다. 충돌 명륜을 이름과 구역으로 표시하고 담기를 막는다.

**해석:** 사용자 작업의 주요 병목이던 기억·재입력 부담은 크게 줄었다. 특히 어떤 기록이 미수집인지 열기 전에 확인할 수 있고, 3돌 이하 사례가 없다는 것도 즉시 드러난다. 아직 ‘사용자3돌 조건으로 최고 난이도5구역을 완성했다’고 결론 낼 수 없다. 최고 난이도1위파티에선 해당 조건 기록이0건이었고, 다른 파티/난이도 전체 탐색과 명륜 돌파 확인은 수행하지 않았다.

**추가 개선 후보:** 구역별 복귀 시 파티 탭 유지, 세팅 필터 유지, 재로딩 중 임시 TEAM I 빈 상태를 로딩 표시로 구별. 명륜 돌파·은열쇠 미수집은 숨기지 말고 현재처럼 사실대로 표현하되 수집 확장 여부는 별도 결정이 필요하다.

위 35단계는 UX 에이전트의 독립 관찰이다. 이후 구현 담당이 다음을 수정하고 별도 브라우저 시험으로 확인했다. 에이전트가 직접 재확인한 결과와 구분한다.

- 편성기 데이터 로딩 중 기본 TEAM I 빈 화면 대신 로딩 문구를 표시한다. 로딩이 끝난 뒤 저장된 팀을 보여준다.
- 저장한 원본 기록이 잠재력·중복 제외 필터에 가려지면 해당 화면에서 필터를 해제하고 원본 기록을 펼친다. 저장된 기본 필터 자체는 덮어쓰지 않으며 화면에 이유를 표시한다.
- 정제된 실제 데이터로 5구역 담기→기존 편성 보존→20명·40명륜 전달→계약 옵션 보존→새로고침→원본 복귀→파티 탭 복귀→필터 유지 경로를 자동 시험했다. 사용자 전원3돌의 실제 클리어 가능 판정은 수행하지 않았다.
- 320·390·768·1024·1280px, 관련 경계 479/480/481·767/768/769px와 200% 글자 확대를 점검했다. 페이지 가로 넘침 없이 기존 장비 팝업과 선택기 열기·Escape 닫기가 동작했다. 시각 증거는 `.generated/qa/party-plan/`, 세부 결과는 같은 경로의 `result.json`과 `.generated/qa/full-season/verification.json`이다.
- 기존 편성기와 사용 현황은 `js/character-usage-view.mjs`의 동일 장비·옵션 렌더러를 사용한다. 새 선택기는 만들지 않았다. 기존 페이지·팀·명륜 선택 코드를 유지했다.
