# 비밀계약 시뮬레이터 세 모드 UI 통일

사용자는 같은 시뮬레이터에서 세팅·프리셋, 전사, 목표의 배치와 능력치 표현이 서로 다른 점을 지적했다. 세 열 대신 비밀계약을 왼쪽 절반에 크게 두고 나머지 입력과 결과를 오른쪽에 모으는 방향으로 변경했다. 이전 세 열 UI 검증 문서는 수정 경위이며 현재 기준은 이 문서다.

## 공통 구조

- 64rem 이상 컨테이너에서는 좌우 절반씩 배치한다. 사용자의 후속 크기 지정에 따라 비밀계약 자체는 확대 전 프리셋의 352px 프레임·16px 안쪽 여백을 유지한다. 실제 육각형은 최대 320px이며 세 모드가 같다. 글자 200%에서도 이미지 크기 상한은 변하지 않는다. 패널 절반을 이미지가 가득 채우도록 확대하지 않는다.
- 능력치 표·입력·결과는 오른쪽에 유지한다. 왼쪽 여백을 채우기 위해 표를 옮겼던 변경은 v11에서 되돌렸다. 전사와 목표의 오른쪽은 `.simulator-side-panel` 하나에 입력·동작·실제 실행 결과와 능력치 표를 배치한다. 실행 전에는 빈 결과 칸을 만들지 않는다. 오른쪽 내용을 그림 높이에 억지로 압축하지 않고 긴 결과만 스크롤하며, 비밀계약 이미지는 자신의 크기를 유지한다.
- 능력치는 공용 `contract-attribute-totals` 클래스와 같은 페이지 스타일로 표시한다. 원본 아이콘·이름·수치를 모두 제공하고 글꼴 14/16px, 색상, 숫자 굵기와 간격도 세 모드가 같다. 결과 부옵과 주옵도 이름을 함께 표시한다.
- 세팅의 부위 선택·옵션 편집과 전사·목표의 기존 저장·계산·오류 안내 상태는 유지한다. 결과 패널은 활성 모드의 오른쪽 안으로 이동한다.
- 좁은 화면에서는 동일한 순서로 한 열로 바꾼다. 외부 프레임과 내부 프레임에 패딩을 중첩하지 않고, 작은 화면의 내부 여백은 8px로 유지한다. 확대 시 여백까지 커져 옵션명이 한두 글자씩 줄바꿈되던 문제를 피한다.

## 검증

소스와 최종 빌드에서 실제 전사·교체, 목표 설정·실행·결과 아이콘과 수치, 프리셋·재접속, 입력 오류의 모드별 보존을 확인했다. `tools/test-covenant-simulator-layout.mjs`는 320·390·768·1024·1280px, 844×390, 320px 글자 200%와 64rem 경계 1101·1102·1103px의 두 모드 20조건을 검사한다. 좌우 폭이 같고 결과가 오른쪽 안에 머무르며 가로 넘침과 버튼 가림이 없는지 측정한다.

`.generated/scarecrow/check-unified.mjs`는 세 모드의 육각형 크기·표 글꼴·아이콘 크기가 같은 것, 세팅 부위의 강화 입력과 전체 보기 왕복 보존, 가중치 전사·교체, 목표 1회 달성과 결과를 별도로 검증했다. UI 에이전트는 1280px의 일관성과 320·390px/글자 200%, 실제 세팅 부위 편집을 독립 검토했다. 모바일의 이중 패딩과 기존 규칙의 중복을 발견해 제거했다.

증거: `D:/MorimensCodexTemp/unified-v6-{proof.json,source-final.log,artifact.log,identical-artifact.log,build.log}` 및 `.generated/scarecrow/simulator-layout-proof-{8766,4185}/`. 작업 브랜치에서 검증했으며 비공개 게임 데이터와 배포 상태는 변경하지 않는다.

공용 편집기 왕복·저장·프리셋·전사와 반응형 18조건도 통과했다(`unified-v6-shared.log`). 확대안을 검증할 당시 UI 에이전트는 양 서버에서 세 모드 육각형이 1280px의 520px, 390px의 284.63px, 320px와 글자 200%의 218.81px로 동일한 것을 확인했다(`ui-audit-v6-consistency-final.json`). 이 확대안 화면은 `D:/MorimensCodexTemp/unified-v6-user.png`에 남아 있다.
