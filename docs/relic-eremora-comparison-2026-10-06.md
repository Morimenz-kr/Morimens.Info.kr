# 유물 도감과 Eremora 비교

2026-10-06. 비교 대상: [Eremora 유물 도감](https://eremora.com/library), 현재 `data/relic_catalog.json`, 로컬 클라이언트 결과 테이블과 한국어 원문.

## 개수

| 대상 | 묶인 유물 수 | ID별 변형 수 | 범위 |
|---|---:|---:|---|
| 현재 우리 도감 | 182 | 481 | 인게임 수집실 중심 |
| Eremora 화면 | 418 | 651 | 테스트·이벤트 항목도 포함 |
| 로컬 클라이언트 원본 전체 | 묶기 규칙 미확정 | 651 | 테스트·이벤트 포함 전체 변형 |

Eremora 공개 페이지의 직렬화 데이터에서 418개 묶음과 651개 변형 ID를 읽고 클라이언트 ID 전체와 대조했다. 원격 JavaScript를 실행하지 않고 데이터 리터럴만 파싱했다. **ID별 누락 0, 중복 0으로 전체 ID 집합은 일치한다. 설명·실행 의미까지 일치한다는 뜻은 아니다.**

418개 묶음은 Eremora의 공개 ID별 묶음 관계를 출처와 함께 유지하는 별도 로컬 카탈로그로 제공한다. 아이콘이나 한국어 이름으로 추정하지 않았다. 설명·수식은 우리 한국어 클라이언트 원문을 사용하며 Eremora의 설명 전문을 복제하지 않는다. 기존 공개 도감 182개는 변경하지 않았다.

2026-10-08: `records.html?view=relics`에 별도 전체 도감을 연결했다. 출처·등급·작동 원리·변형별 설명/수치를 조회할 수 있고, 미입력 전투 문맥을 0으로 채우지 않는다. 개수/ID 일치와 설명 실행 의미의 일치 검증은 계속 구분한다.

우리 변형과 Eremora 변형의 차이는 170개다. 하지만 이것을 모두 실제 수집 가능한 누락 유물로 세면 안 된다. Eremora에는 Test Relic, Invincible Test Relic, Collection Test Relic, Mission Relic Test, Simulation Relic 등이 노출된다. 실제 수집 가능 여부와 테스트/임시/이벤트 여부를 ID와 설정 참조로 구분해야 한다.

170개를 Eremora의 출처 분류로 나누면 유산 5, 융재금구 24, PvP 12, 이벤트 56, 별의 정위 73이다. 이 분류는 도감 검색용이며 실제 현재 획득 가능성을 증명하지 않는다.

클라이언트의 651개 전체에 대해 유물 → 초기 State → TriggerCmd → 상태 추가/제거 참조를 추적했다. 2026-10-07 원본 TriggerPara의 개별 인자를 전달해 상태 ID 참조 57건을 해석했다. 검사 범위 내 누락 참조와 미해석 동적 ID 참조는 모두 0개다. 이는 모든 명령 종류·수치·실행 조건을 해석한 전투 시뮬레이션 검사가 아니다.

전체 418묶음/651ID는 별도 공개용 `data/relic_library.json`과 화면 독립적인 정적 조회 모듈에도 연결했다. 현재 게임 자산에서 묶음 406개에 해당하는 아이콘을 확인/추출했다. 현재 manifest에 없는 12개 중 8개는 동일한 원본 아이콘의 기존 파일이 있어 재사용했고, 나머지 4개는 image=null로 유지한다. 한국어 원문이 없는 이벤트 항목 151981·152074는 원문 대체 사용 여부를 명시했다. 기존 수집실 UI와 `relic_catalog.json`은 변경하지 않았다.

## 설명과 수치 표본 비교

계정 레벨 65, Archive Mark 0, 관련 중첩 0 조건에서 확인했다.

추가 원본 확인: 83509 → State 83273(AllAwaker) → Cmd 84428 → State 84434 → Cmd 84429에서 `UpperTarget.School==4`인 각 대상마다 PlayerRole에 State 58147을 1중첩 추가한다. 또 Cmd 84428 자체가 58147을 1중첩 추가한다. 44662 → State 44756 → Cmd 44758 → State 45139 → Cmd 45135는 `BEDispelState` 인자 `0,1,0`이며, `BattleConst`에서 0은 Debuff/Random이다. 두 사례는 파티원마다 적용·무작위 디버프 1종 해제라는 제한을 뒷받침한다. 13749의 대상 State 35539는 `be_damage_per3=100`을 부여하며, 능동/촉수 수식의 해당 속성 참조를 확인했다. 이런 근거를 모으는 중이며 아직 공개 설명을 재생성하지 않았다.

우리 문구가 임의 번역 때문에 달라졌는지 확인했는데, 위 차이 사례는 현재 한국어 클라이언트 원문과도 같은 차이가 있다. 따라서 Eremora 문장을 그대로 덮어쓰지 않았다.

Archive Mark 50에서는 여정의 유골 첫 수치가 804로 관찰됐다. 이 슬라이더를 단순한 영혼 계수나 모든 모드의 은열쇠 조건과 동일시하지 않는다. 현재 수식 계산에서 확인되지 않은 런타임 인자는 미치환 목록으로 반환한다.

## 아직 완료되지 않은 비교

- 전체 651개 변형의 모든 효과 의미 비교. 1:1 ID 대응은 완료했다.
- Eremora의 418개 ID 묶음은 확인했지만, 이를 만드는 원래 알고리즘과 테스트/수집 가능 항목의 정확한 경계는 미확정이다.
- 모든 계정 레벨·중첩·HP·Archive Mark 조건에서의 동적 수치 비교.
- 모든 차이 사례의 Skill/State/Cmd 실제 실행 참조 검증. 위 3개는 일부 실제 실행 참조를 추가 확인했다.

효과를 수정할 때는 `docs/dzone-content-pipeline.md`와 `docs/game-keywords.md`를 먼저 따라 원본 참조에서 재생성하고, 진단/경고와 콘텐츠 회귀 검사를 수행해야 한다. 이 비교에서는 생성된 공개 JSON 설명이나 기존 전투 효과를 직접 수정하지 않았다.
