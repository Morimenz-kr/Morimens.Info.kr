# 비밀계약 전사 확률 자료

2026-11-15에 현재 설치된 클라이언트 `Z1G_2026_11_OB`, 리소스 22·빌드 11의 설정과 스크립트 번들을 대조했다. 기존 균등 레벨 가정을 제거하고 [추출 자료](../data/covenant_roll_rates.json)를 전사와 목표 시뮬레이션에서 함께 사용한다.

## 확인한 가중치

`Config.Constant.TrinketSubAttrTypeWeight_1`~`_6`은 부위별 8개 속성 ID와 가중치 쌍이다. 현재 여섯 부위 모두 각 속성의 가중치가 1이므로 옵션별 확률은 12.5%다. 이름으로 대응시키지 않고 안정 속성 ID로 연결한다.

`TrinketSubAttrValueWeight`는 아래 수치 배율과 가중치 쌍이다. `TrinketSubAttrValueLevel`로 배율을 표시 레벨과 연결한다.

| 레벨 | 수치 배율 | 가중치 | 확률 | 해당 레벨 이상 |
| --- | --- | --- | --- | --- |
| 1 | 0.5 | 23 | 23% | 100% |
| 2 | 1 | 20 | 20% | 77% |
| 3 | 1.5 | 17 | 17% | 57% |
| 4 | 2 | 14 | 14% | 40% |
| 5 | 2.5 | 11 | 11% | 26% |
| 6 | 3 | 8 | 8% | 15% |
| 7 | 3.5 | 5 | 5% | 7% |
| 8 | 4 | 2 | 2% | 2% |

따라서 한 줄에서 특정 옵션의 Lv.8이 나올 확률은 12.5% × 2% = **0.25%**다. 기존 8×8 균등 가정의 1/64를 사용하지 않는다. 잠긴 줄은 보존하고, 나머지 줄은 옵션·레벨의 원본 가중치로 각각 추첨한다.

전사 기본 비용과 잠금 비용도 같은 상수 자료에서 읽는다. 기본은 금권 7,500·천면 인장 3, 잠금 하나는 잔본 20 또는 깃펜 1, 잠금 둘은 깃펜 10이다.

## 원본과 참조 검증

- 현재 설치 경로의 `_game_data_/DownLoad/config.ab`, `gamescript.ab`가 추출 기록의 번들 SHA-256과 일치한다.
- 추출된 `Config.Constant.json`의 SHA-256을 테이블 기록과 대조하고, 원본 `Constant.lua` 모듈의 SHA-256도 별도로 대조한다.
- `AwakerTrinketDataUtils.lua`의 원본 모듈 해시는 `9bd6e198d1997b73a7ef0e80b45a400842db3947fe4c569c6f38b1facdc188ce`다. 기존 프로토타입 캡처의 원본과 현재 설치본 추출 모듈이 동일하다. `GetTrinketSubAttrMaxLevel`(원본 430~433행), `GetTrinketSubAttrMaxValue`(435~443행), `GetTrinketSubAttrRefineLevel`(445~453행)이 `TrinketSubAttrValueWeight`와 속성의 `Equivalency`를 참조한다. 표시 레벨 매핑은 `TrinketSubAttrValueLevel`을 사용한다.
- 생성 JSON에는 이 기능에 필요한 가중치·비용·출처 해시만 포함한다. 계정 데이터, 74기, 유물 세트 효과는 포함하지 않는다. 서버 코드를 추출했다는 의미는 아니며, 검증 대상은 설치 클라이언트의 실제 설정이다.

전체 해시와 사용한 상수 키는 생성 JSON의 `source`에 기록한다. 원본 상수 테이블·Lua 모듈·번들이 서로 다르거나 설치본이 바뀌면 생성 도구는 실패한다.

## 재생성

생성 도구는 게임 자료 추출 코드를 저장소에 커밋하지 않는 로컬 훅 정책에 따라 작업 PC에만 보관한다. 아래 생성 명령은 해당 로컬 도구가 있는 작업 환경에서 실행한다. 서비스에는 검증된 확률 JSON만 포함한다.

```text
node tools/generate-covenant-roll-rates.mjs --source <검증된 추출 자료 경로> --installed-bundles <현재 게임의 DownLoad 경로>
node --test js/covenant-target.test.cjs
```

생성은 결정적이며 같은 자료에서 같은 JSON을 만든다. 앱은 확률 자료를 읽고 검증한 뒤 조작을 허용한다. 자료 누락·형식 오류 시 균등 확률로 대체하지 않는다.

## 검증

목표 모델 검사는 여섯 부위 각각의 800개 추첨 구간을 전수 대조한다. 각 옵션·레벨 조합의 빈도가 원본 가중치와 일치해야 한다. 별도로 Lv.8 목표의 기하분포, 중복 Lv.8 목표의 독립 Markov 기대 횟수, 잠금과 비용 보존을 검사한다.

실제 브라우저에서는 같은 난수 0.5가 균등 레벨의 5가 아닌 가중 레벨 3을 생성하는지 전사·목표 양쪽에서 확인했다. 교체·새로고침 후 값 유지와 확률 자료 요청 실패 시 조작 차단도 검사했다.

전체 단위 테스트 512건, 세 모드 반응형 21개 조건, 생성 JSON의 결정적 재생성과 원본·빌드 파일 해시 대조가 통과했다. 배포용 ScareCrow 빌드에서도 전사·목표의 가중치 사용과 자료 누락 시 차단을 확인했다. 독립 레드팀은 원본 상수와 생성 자료 전체 행을 직접 비교했고, 잠금 보존·비용·교체·재접속을 실제 브라우저에서 다시 확인했다.
