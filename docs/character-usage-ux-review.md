# 추천 세팅 독립 UX·시각 검토 (2026-11-22)

이번 검토는 실제 사람을 모집한 UT가 아닌 에이전트 기반 과제 테스트와 시각 리뷰다.
기존 화면 작성자가 아닌 두 검토자를 사용했다. 한 명은 사용자 과제·상태 이해·스크롤과
복귀 동작을, 다른 한 명은 코드나 테스트 성공 수치를 보기 전에 실제 스크린샷의 배치·크기·비례를 검토했다.
검토자는 서비스 코드를 수정하지 않았고, 발견 사항은 구현자가 고친 뒤 다시 검토했다.
사용자의 브라우저 인증과 실제 보유 기록은 검사 데이터로 쓰거나 변경하지 않았다.

## 사용자 과제

1. 각성체의 많이 쓰는 비밀계약을 고르고 주옵·부옵 채용률을 파악한다.
2. 다른 계약과 비교해 어느 옵션 채용률이 다른지 식별한다.
3. 보유 각성체로 가능한 파티를 골라 그 파티의 통계를 보고 전체로 복귀한다.
4. 집계 근거의 개별 클리어를 열고 서로 다른 세팅을 구별한다.

## 발견한 불편과 최종 변경

| 발견한 문제 | 변경·재확인 |
|---|---|
| 38개 계약 목록에 빈도가 없어 비교 후보를 추측해야 함 | 상위 3개를 계약명·세트 수·채용률과 함께 노출. 전체 목록에도 비율 표시 |
| 빠른 선택과 큰 선택 입력이 반복돼 회색 컨트롤이 누적됨 | 상위 3개를 주선택으로 유지. 전체 계약은 보조 팝오버로 내리고 아트에는 현재 계약명만 표시 |
| 비교 선택기 폭이 좁아 선택값이 잘림 | 모바일에서 기준·비교 선택기를 각각 전폭으로 배치. 닫기는 제목 행으로 이동 |
| 공유 명륜과 두 계약을 같은 네 칸에 넣어 그림이 작고 관계가 불명확함 | 두 계약 그림을 같은 기준선에 먼저 배치. 공통 명륜은 별도 보조 묶음으로 분리. 긴 명륜 이름에 폭 확보 |
| 파티가 통계 뒤에 있고 카드 클릭의 의미가 숨겨짐 | 통계 위에 파티 기준 진입. 행위는 ‘이 파티 통계 보기’. 선택한 네 명의 초상·이름을 접힌 상태에도 유지 |
| 파티를 고르면 강제로 화면이 약 1256px 이동함 | 강제 이동 제거. 초점은 파티 기준에 남고 ‘전체 파티 통계’로 복귀 |
| 주옵의 자유로운 인라인 나열 때문에 숫자 열이 흔들림 | 부위별 최대 2열 옵션 묶음과 각 옵션의 이름/오른쪽 수치 열을 고정. 공간 부족·확대 시 재흐름 |
| 비교의 긴 주옵표를 한쪽 좁은 열로 읽고 반대쪽은 비어 있음 | 비교 부옵/주옵을 각각 전폭으로 배치. 본문 14px, 머리글 13px, 행 약 34px 확보 |
| 세팅1/2가 어느 계약인지 기억해야 함 | 표에 실제 계약 이름 표시, 긴 표의 머리글 유지. 단일 6세트의 중복 문구는 생략하고 혼합 구성은 세트 수 유지 |
| CSS 수정 의도와 달리 표가 실제로 3열 균등 분배됨 | colgroup으로 실제 폭 교정. 390px 주옵은 44/152/72/72px, 부옵은 196/72/72px 확인 |
| 200%에서 넘침 없이도 한글이 한 글자씩 세로로 읽힘 | 좁은 통계 영역에서는 이름을 전폭 행으로, 두 계약 비율을 아래 두 열로 재배치 |
| 제보 플로팅 버튼이 채용률을 가림 | 추천 탭에서만 중복 플로팅을 숨김. 기존 하단 제보 버튼 유지 |
| 기록 목록이 동일 구역·등급·횟수라 구별 어려움 | 대상 명륜 이름·계약 완성도·잠재력으로 원본 선택 항목 식별 |

기존 상단 탭·제목·페이지 폭, charcoal/gold 색상과 테두리는 유지했다.
통계의 집계 분모·가중치·정확한 개별 기록과의 구분은 바꾸지 않았다.

## 전후 측정과 해석

융해·돌 73기, 동일 Chrome/데이터/900px 높이에서 측정했다.
문서 높이는 계정·수동 자료·하단 제보까지 포함하며, 실제 사람의 작업 시간이나 만족도 점수가 아니다.

| 화면 | 수정 전 전체 높이 | 최종 전체 높이 |
|---|---:|---:|
| 모바일 390px 기본 | 2549px | 2398px |
| 모바일 390px 비교 | 3552px | 2921px |
| 데스크톱 1280px 기본 | 2265px | 1919px |
| 데스크톱 1280px 비교 | 2543px | 2773px |

모든 화면의 길이가 줄었다고 해석하지 않는다. 데스크톱 비교는 글자·그림 크기와 전폭 표의
읽기 공간을 확보해 약 9% 길어졌다. 이 교환은 검토 결과에 명시했다. 반면 파티 진입은
모바일 문서 y1970에서 y367로 옮겼고, 선택 시 코드가 일으키던 1256px 점프는 0px가 됐다.

시각 검토는 길이 수치를 합격 근거로 삼지 않았다. 선택한 대상의 식별, 그림 비례, 한글 이름의
읽기, 수치 끝선의 정렬, 빈 공간과 표 밀도를 실제 캡처에서 별도로 확인했다.

## 검증 범위와 남는 한계

- 독립 시각 검토: 390/1280 기본·비교. 320/768/1024 보조 확인. 최초 5개와 후속 2개 핵심 문제의 교정을 재확인했다.
- 과제·반응형: 320/390/639/640/641/768/779/780/781/1024/1280, 320/390/1280의 200% 글자 확대, 844×390 가로 화면. 부위별 부옵 상세도 기본/확대에서 확인했다.
- 원본 기록 연결, 파티 범위/복귀, 계약 선택/비교, 키보드 초점, 통계 계산 회귀 검사도 별도로 수행했다.
- 보조 개선 여지는 있다. 데스크톱의 수치 열은 72px라 일부 머리글이 두 줄이고 이름에서 숫자까지 거리가 넓다. 기본 모바일의 긴 주옵 이름 일부도 자연스럽게 두 줄이다. 핵심 독해 문제와 구분해 남겼다.
- 실제 이용자의 첫 방문 이해도·선호·만족도, 실제 휴대폰 터치, iOS/Safari 선택 목록은 이번 검토로 입증하지 않았다. 희귀 혼합 계약과 모든 보유 조합을 시각적으로 전수 검사했다고 주장하지 않는다.

상세 발견 내역과 전후 캡처는 로컬 `.generated/ux-review/independent-review.md`,
`.generated/visual-review/visual-review.md`에 보관한다. 구현 확인에는 저장소의 반응형 지침과
[Web Interface Guidelines](https://github.com/vercel-labs/web-interface-guidelines/blob/main/command.md)도 참고했다.
운영 배포·요금제·로그인/동기화 설정은 변경하지 않았다.
