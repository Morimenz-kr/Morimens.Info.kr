# 비밀계약 공용 편집기

현재 화면은 v25이다. 세팅·프리셋, 전사, 목표 시뮬레이션은 **배치와 데이터가 독립**이다. 원본 비밀계약 그림 최대 320px와 오른쪽 결과 위치는 유지한다. 프리셋 그림은 기존 상단 정렬, 전사·목표 그림은 각 모드의 별도 규칙으로 세로 중앙에 둔다. v12의 열 변경은 철회했으며 세 탭의 세팅값을 자동으로 연결하지 않는다.

후속 지정에 따라 비밀계약 자체는 기존 프리셋의 최대 320px 크기를 유지한다. [기존 크기 유지 독립 점검](ux-tests/covenant-simulator-original-size-audit-2026-11-15.md)에서 세 탭·모바일·글자 200%와 실제 계산·저장 검증, 결과 잘림 수정 내용을 확인할 수 있다.

[귀속 토글과 후속 검증](ux-tests/covenant-simulator-bound-space-2026-11-15.md): 이전의 공유 귀속 검증 기록이다. v14에서는 귀속도 각 모드가 따로 저장한다. 전사의 귀속 변경은 전사 미리보기를 보존한다. 이 기록 중 표를 왼쪽으로 옮겼던 배치는 요청 범위를 벗어난 변경으로 되돌렸다.

[시뮬레이터 전체 레드팀 점검 기록](ux-tests/covenant-simulator-redteam-2026-11-15.md)에는 세팅·프리셋·전사·목표, 저장 실패, 느린 로딩, 모바일, 계산 중단과 확률 모델의 검증 범위를 기록한다.

[전사 확률 자료](covenant-roll-rates.md)는 현재 설치 클라이언트에서 검증한 옵션·레벨 가중치와 비용의 출처 및 재생성 방법을 설명한다. 전사·목표 계산은 같은 추출 자료를 사용한다.

[전사·목표 배치 점검](ux-tests/covenant-simulator-layout-2026-11-15.md)은 선택 배경 제거와 비밀계약 높이를 기준으로 한 오른쪽 조작부의 정렬, 부위별 목표 편집, 좁은 화면의 재배치 검증을 기록한다.

[새 배치 모바일·UI 독립 점검](ux-tests/covenant-simulator-mobile-layout-redteam-2026-11-15.md)은 두 에이전트가 발견한 세로 공간과 오류 안내 소실, 수정 후 모바일 전사·목표·결과·저장 검증을 기록한다.

`js/covenant-editor.mjs`와 `css/covenant-editor.css`는 비밀계약 시뮬레이터와 ScareCrow가 함께 사용하는 6부위 편집기다. 선택·주옵·부옵·강화·귀속·전체 능력치·세트 효과를 렌더링한다. 전사 확률·소모량·파티 전투 상태·저장은 각 호스트가 관리한다.

## 편집 데이터

| 필드 | 의미 |
|---|---|
| `owner.contractSlots` | Ⅰ~Ⅵ의 원본 세트 ID 6개. 0은 미장착 |
| `owner.contractBound` | 계약 전체 귀속 여부 |
| `owner.trinkets` | `position`, `main`, `quality`, `level`, `bound`, `sub`를 가진 부위 배열 |
| `sub` | 원본 속성 ID와 실제 수치의 `{id,value,slot?}` 배열. 빈 줄이 있으면 `slot`에 0~2 입력 위치를 보존. 부옵 최대 3개, 레벨 1~8 |

완성도·주옵·부옵 수치는 `js/covenant-stats.mjs`, 세트 구성·정적 합계는 `js/covenant-equipment.mjs`가 담당한다. ScareCrow의 이전 모듈 경로는 이 공통 모듈을 다시 내보내어 기존 계산 어댑터를 유지한다.

## 호스트 인터페이스

`renderCovenantEditor(parent, options)`는 장착 객체를 편집하고 `{editPart(position),showOverview()}`를 반환한다. `position`은 1~6이다.

| 옵션 | 역할 |
|---|---|
| `owner`, `catalog`, `metadata`, `contracts`, `parts` | 장착값, 세트 효과·옵션 규칙·한국어 설명·부위 이미지 |
| `onChange(owner)` | 변경값 저장 및 호스트 계산 갱신 |
| `onPick(position)` | 호스트의 세트 선택창 열기. null은 전체 6부위 |
| `onReset()` | 전체 초기화 또는 세팅 가져오기 뒤 호스트 재렌더링 |
| `onPartChange(index)` | 선택 부위 동기화. 0~5, -1은 전체 보기 |
| `initialPart` | 초기 선택 부위. 기본 -1 |
| `pickOnPartSelect` | ScareCrow는 클릭 시 선택창, 시뮬레이터는 클릭 시 바로 부위 편집 |
| `allowEmptyOptions` | ScareCrow의 빈 옵션 입력을 허용. 시뮬레이터에서는 기존 3개 부옵 전사 구조 유지 |
| `renderSubstatActions(parent, {position,index,current})` | 부옵 행에 호스트 전용 동작 추가. 기본은 추가 동작 없음 |
| `onPartPanel(panel,index)` | 선택된 부위 패널을 전달. 전체 보기에서는 null과 -1 |

## 시뮬레이터 연결

`js/covenant-simulator-model.mjs`가 기존 문자열 옵션 ID·레벨을 공용 장착 객체와 상호 변환한다. 기존 `morimens_covenant_simulator_state_v1` 및 프리셋 저장소는 유지하며 스냅샷에 부위별 `setId`와 전체 귀속 여부를 추가했다. 이전 스냅샷의 세트는 당시 선택한 계약으로 채운다. 목표·잠금 데이터는 유지한다.

‘세팅·프리셋’ 탭은 공용 편집기와 프리셋 저장·불러오기·삭제를 제공한다. ‘전사’ 탭은 6부위 선택, 현재 옵션 표시, 최대 2개 잠금, 전사와 결과 교체를 제공한다. 세팅·프리셋은 `editorParts/editorBound`, 전사는 `parts/contractBound`, 목표는 `targetSimParts/targetBound`를 사용한다. 전사의 ‘세팅 편집’은 자체 대화상자이며 프리셋 탭을 수정하지 않는다. 전사·목표의 ‘프리셋 불러오기’는 저장된 장비 세팅만 독립 복사한다. 이후 수정은 원본이나 다른 모드에 반영되지 않는다. 목표에 불러올 때 기존 목표 조건을 유지한다.

현재 상태 스냅샷은 version 3으로 세 모드와 전사 미리보기·결과·비용, 목표 완료 결과를 함께 보관한다. 구형 공유 저장값은 프리셋/전사에 각각 복사하고, 기존 목표 상태를 보존한다. 이후 각 모드의 귀속과 초기화도 독립이다. 장비 프리셋에는 프리셋 편집기의 장비와 귀속만 저장하며, 구형 프리셋에 담긴 다른 모드의 값은 복구하지 않는다. 목표 프리셋 version 2는 목표 화면 자체의 장비·현재 옵션·목표·귀속을 저장한다.

[독립 에이전트 후속 점검과 v15–v17 수정](ux-tests/covenant-simulator-isolation-2026-11-15.md)을 포함한 검증은 `tools/test-covenant-isolation.mjs`와 `tools/test-covenant-simulator-layout.mjs`로 수행한다. 전자는 구형 저장 이전, 명시적 불러오기, 원본 불변, 귀속 분리, 전사 자체 편집, 결과/미리보기 새로고침, 모드별 초기화를 검사한다.

전사와 목표 화면도 `renderCovenantParts`의 실제 부위 이미지로 육각형을 보여 준다. 전사는 한 부위를 선택하며 선택된 부위의 이름·옵션·전사 결과를 옆에 배치한다. 이미 선택한 부위를 다시 눌러도 교체 전 결과를 지우지 않는다. 목표는 여러 부위를 켜고 끄며, 마지막 대상 하나는 해제할 수 없다. 제외한 부위는 흐리게 표시하고 계산 대상 번호를 함께 보여 준다. 혼합 계약·미장착 부위는 각 모드의 데이터로 렌더링하며, 완성된 동일 계약만 중앙 문양을 표시한다.

육각형의 시각·터치 스타일은 공통 편집기와 공유하지만 저장값이나 프리셋 형식은 바꾸지 않는다. 모바일에서는 이미지와 조작부가 세로로 배치된다. 숫자 버튼은 키보드로 접근 가능하며, 장식용 부위 이미지는 포커스 순서에서 제외한다.

## 호스트 간 세팅 전달 (공유 기능 제거 전 기록)

이 절은 과거 구현 기록이다. 현재 공유 UI와 호스트 간 코드 전달은 제공하지 않는다. 현재 동작은 아래 공유 기능 보류 절을 따른다.

공용 편집기의 **세팅 복사 → 다른 화면의 세팅 가져오기 → 세팅 적용**으로 6부위 세팅을 옮긴다. ScareCrow에서는 마지막으로 바깥 편집기의 **적용**을 눌러 파티에 저장한다. 다른 도메인에서도 같은 흐름을 사용하며 자동으로 클립보드를 읽지 않는다. 자동 복사가 허용되지 않으면 열린 창에서 전체 선택 후 직접 복사할 수 있다.

`js/covenant-transfer.mjs`는 `morimens.covenant-setting` 버전 1의 JSON에 `contractSlots`, `contractBound`, `trinkets`만 담는다. 각 부위의 주옵션·강화·부옵션 실수치를 보존하며 계정·캐릭터 성장·파티·전사 이력은 포함하지 않는다. 현재 공개된 세트와 황금 등급만 지원한다. 가져오기 전 세트 ID, 부위 중복, 강화 범위, 부옵 Lv.1~8의 실제 수치, 형식·크기를 검증한다. 실패 시 현재 세팅을 유지한다. 시뮬레이터의 목표·잠금과 다른 파티 정보도 유지한다.

전송 창은 native dialog를 사용하며 Escape로 닫은 뒤 시작 버튼에 포커스를 돌려준다. ScareCrow의 바깥 편집기는 함께 닫히지 않는다. `images/covenant-parts/sources.json`은 기존 검증 리소스에서 복원한 162개 부위 이미지의 Item.Icon 매핑과 SHA-256을 기록한다. 빌드는 설정된 부위 이미지가 하나라도 빠지면 실패한다.

잠금/해제 이미지는 설치된 게임의 공통 이미지 아틀라스에서 추출한 `UI_Common_D_Image_Unlock06` / `Unlock05`다. 실제 전사 프리팹 `ui_awaker_item_trinket_refinement`의 `Image_Lock_Icon` / `Image_Unlock_Icon` 참조와 대조했다. `images/covenant-ui/sources.json`에 원본 Sprite ID·아틀라스·참조 노드·해시를 기록한다. 원본 78×42 비율을 유지하며 버튼의 터치 영역은 44×44px이다.

`data/covenant_editor.json`은 기존 ScareCrow의 공개 res160 장비 메타데이터에서 세트·옵션 규칙·안정 ID만 분리한 자료다. 게임 최신 버전의 전투 공식을 갱신하거나 최신화 검증한 작업은 아니다. 데이터 갱신 시 공용 모듈과 양쪽 호스트의 수치·저장 호환성을 함께 확인해야 한다.

## 확인 범위

새 브랜치 `codex/shared-covenant-editor`에서 작업했다. 기존 ScareCrow 로컬 변경을 이어받았으며 운영 main에 병합하거나 커밋·푸시하지 않았다. Node 테스트 399개, 기존 ScareCrow 계약 검사 9개와 로컬 빌드·데이터 검증을 통과했다. 실제 브라우저에서 편집·잠금 전사·교체·혼합 세트 저장·새로고침·프리셋 복원·목표 계산·초기화·선택창 Escape/포커스 복귀를 확인했다.

## 브랜치 보존 점검 (2026-11-14)

위 확인 범위는 최초 작업 시점의 기록이다. 이번에는 공용 편집기와 함께 남아 있던 ScareCrow 후속 작업을 `codex/shared-covenant-editor` 브랜치의 개발 체크포인트로 묶어 보존한다. 카드 연속 적용·되돌리기, 효과 표시, 전투 화면·글꼴, 관련 빌드와 검사 파일을 함께 포함한다. 이들 변경이 서로 참조하므로 공용 편집기만 별도로 가져갈 때 의존성을 다시 확인해야 한다.

- 재실행: 기본 테스트 399개, 계약·연속 적용·효과 테스트 12개 통과, `npm run scarecrow:build` 성공.
- 빌드 기준은 res160이다. 번역 카드 설명 연결 누락 경고 84건이 남아 있다. 비비안, `wheel_imago_clinic`·비비안 SSR/SR 명륜, `key_GOgier`·비비안 은열쇠는 빌드의 미지원 목록에 있다. 최신 게임 전체 지원 완료를 뜻하지 않는다.
- 이번 브랜치 보존에서는 브라우저 반응형 검사와 실제 게임 피해 대조를 새로 수행하지 않았다. 최초 작업의 브라우저 기록과 이번 테스트 실행은 구분한다.
- main 병합과 공개 배포는 별도 마일스톤 작업으로 남긴다.

## 프리셋 목록과 공유 코드 (v23–v25 기록)

이 절의 공유 코드·미리보기·링크 동작은 v26에서 제거했다. 로컬 프리셋 목록은 유지한다. 아래 설명과 공유 관련 브라우저 도구는 제거 전 검증 기록이다. 현재 회귀 도구는 `tools/test-covenant-isolation.mjs`와 `tools/test-covenant-simulator-layout.mjs`다.

현재 기본 공유 방식은 MR1-로 시작하는 72자의 영문·숫자 공유 코드다. 링크나 JSON을 일반 흐름에 노출하지 않는다. 프리셋은 목록에서 바로 선택해 불러오며 전사/목표의 목록을 접어 두지 않는다. 공유·백업은 각 화면의 버튼 하나로 열고, 내 코드 복사와 받은 코드 입력을 한 대화상자에서 처리한다. 중첩 접기·펼치기 메뉴는 제거했다. 귀속 스위치와 목표의 현재/목표 탐색은 기능상 필요한 상태 조작으로 유지한다.

코드는 서버 참조 없이 장비 스냅샷을 복원한다. 대소문자/공백/하이픈을 허용하며 CRC32로 오타를 검출한다. version MR1은 귀속 1bit와 부위별 세트 ID16/main4/강화4/부옵별 속성4+레벨3bits를 담는다. 숫자 속성은 게임의 공용 covenantSubValue로 복원한다. 미장착, 미설정, 빈 부옵 위치, 혼합 계약과 Lv를 보존하며 공개 계약 검증을 통과해야 한다. 계정/성장/목표/전사 잠금/소모량/실행 이력은 포함하지 않는다.

받은 코드의 ‘세팅 확인’은 읽기 전용 미리보기다. 프리셋에 저장하면 새 프리셋만 추가하고 현재 세 탭은 바꾸지 않는다. 전사/목표로 가져오면 해당 모드에만 독립 복사하며 목표 조건은 유지한다. 이후 원본 수정이나 다른 탭 변경과 연동되지 않는다. 구형 JSON 백업은 같은 입력창에서 읽어 미리보기 후 현재 편집기에 적용할 수 있다. 기존에 발급된 #covenant 링크도 읽기 호환만 유지한다.

검증은 `js/covenant-transfer.test.cjs`, `tools/test-covenant-share-code.mjs`, `tools/test-covenant-isolation.mjs`, `tools/test-shared-covenant.mjs`에서 수행한다. 오타/모든 레벨/빈 위치/대소문자/미리보기 취소/프리셋 목록/두 모드 독립 가져오기/원본 수정 후 코드 불변/귀속/목표/새로고침/저장 실패/파티 편집기 왕복을 확인한다. 반응형은 320/390/768/1024/1280, 가로844×390, 320/1280 글자200%를 포함한다.


[공유 코드 독립 레드팀·UI 검증](ux-tests/covenant-share-code-redteam-2026-11-15.md)에서 v24–v25의 수정과 최종 검증 범위를 확인한다. 가져오기는 후보 스냅샷 저장에 성공한 뒤에만 대상 은행과 화면을 바꾼다. 저장 실패 시 기존 세팅·현재 탭·pending을 유지하고 미리보기에서 재시도한다. 복사 피드백은 창 재오픈/새 입력/검증 이후의 이전 비동기 응답을 무시하며 단일 안내 영역을 해당 동작 근처에 배치한다.

## 옵션 아이콘·조작 간격·비용 선택 (v30–v32)

전사 주옵·부옵·미리보기 결과에 프리셋과 같은 게임 옵션 아이콘을 표시한다. 목표의 주옵·현재 부옵·목표 부옵은 옵션 이름 드롭다운 대신 프리셋과 같은 아이콘 버튼으로 선택한다. 선택된 이름과 테두리를 표시하며 모든 버튼은 접근 가능한 이름·툴팁·키보드 포커스를 제공한다. 주옵·현재 부옵은 같은 아이콘을 다시 눌러 미설정으로 지울 수 있고, 목표 부옵은 항상 유효한 옵션을 유지한다. 레벨 선택은 기존 방식이다. 선택값은 기존 모델과 저장 형식을 그대로 사용한다.

전사 세팅 편집과 목록 불러오기 사이에 .75rem 여백을 둔다. 전사와 목표의 잔본/깃펜 우선은 두 선택지를 누르는 스위치 모양으로 통일한다. 네이티브 라디오 키보드 조작을 지원하고 각 모드의 비용 설정을 독립 저장하며 초기화·목표 프리셋·새로고침에 맞춰 선택 표시를 동기화한다.

`tools/test-covenant-option-controls.mjs`에서 소스/산출물의 모바일 터치로 여섯 부위 주옵·현재 부옵·목표 부옵 아이콘 선택, 지우기/재선택, 레벨 변경, 원본과 전사 값 불변, 새로고침, 실제 이미지 로딩 및 비용 스위치·키보드·비용 반영을 확인한다. 옵션별 아이콘 파일을 프리셋의 실제 버튼과 대조한다. 증거는 `.generated/scarecrow/option-controls-proof/`다.

비용 우선순위는 목표 프리셋 저장·불러오기 후에도 선택 표시를 복원하며 전사 비용 설정과 독립이다. 프리셋과 목표의 옵션 이름별 실제 아이콘 파일을 브라우저에서 대조해 일치를 확인한다.


## 비용 스위치 형태와 목표 조작 간격 수정 (v33)

v31–v32의 두 버튼 방식은 사용자 의도와 달라 제거했다. 현재는 `잔본 [손잡이 스위치] 깃펜`이다. 가운데 버튼을 반복 클릭하면 좌우로 전환되며 Space/Enter로도 조작한다. `role=switch`, `aria-checked`는 깃펜 우선 여부를 나타낸다. 전사의 기존 비용 값과 목표의 기존 저장값을 유지하고, 렌더링·프리셋 복원·초기화 시 표시도 동기화한다.

목표 옵션의 아이콘·레벨·잠금은 간격 .75rem으로 붙여 같은 행 배경 안에 묶었다. 주옵은 부위 이름 아래에 정렬한다. 좁은 영역에서는 아이콘과 잠금을 첫 줄, 최소 레벨을 다음 줄에 배치한다. 실제 컨테이너 내용 너비351/352/353px에서22rem 분기의 양쪽 배치와 넘침 없음을 확인했다.

소스/산출물의 33조건 반응형 검사 각각 통과: 320/390/768/1024/1280px, 기존 분기1101/1102/1103, 가로844×390, 320/1280px 글자200%. 옵션 조작 회귀와 탭별 비용 선택·새로고침도 양쪽 통과했다. 스위치 연속6회 클릭과 Space 전환을 확인했으며 증거는 `.generated/scarecrow/option-controls-proof/`에 남긴다.


## 목표 옵션 행 정렬 재정리 (v34)

v33의 반복되는 검은 카드와4×2 고정 아이콘을 제거했다. 옵션별 이름·레벨·잠금을 같은 윗줄에 정렬하고, 그 아래 여덟 옵션 아이콘을 한 줄로 배치한다. 영역은 얇은 구분선만 사용한다. 주옵도 같은 왼쪽 시작선에 맞춘다. 실제 내용 너비288px 이하에서는 아이콘을4×2로 유지하고 레벨·잠금을 다음 줄에 배치해 이미지 크기를 줄이지 않는다. 287/288/289px에서 줄 전환과 가로 넘침 없음을 확인했다.

### v37: 아이콘 옆 레벨·잠금과 부위 이름 아래 여백

옵션 이름은 윗줄, 아이콘·레벨·잠금은 같은 아랫줄에서 수직 중앙을 맞춘다. 28rem 이하에서는 아이콘4×2, 19rem 이하에서는 조작부를 다음 줄에 배치한다. 내용 너비303/304/305px 및447/448/449px에서 분기 양쪽의 넘침과 정렬을 확인했다. 부위 이름과 주옵 행 간격만12px로 늘렸으며, 주옵 이름과 아이콘 사이는 기존4px다. Chrome1280/390px에서 레벨·잠금과 아이콘 중심 차이가0px임을 확인했다. `.generated/scarecrow/target-strip-proof/aligned-1280-v37.png`, `aligned-390-v37.png`에 화면을 남겼다.


### v38: 오른쪽 조작부와 간격 기준

레벨·잠금 조작부는 행 오른쪽 끝에 정렬하고 아이콘과 수직 중앙을 유지한다. 부위 이름 아래에 구분선을 두며 작은 간격8px, 영역 사이12px 기준으로 주옵·부옵의 중복 간격을 정리했다. 1280/390px에서 잠금 오른쪽 끝 차이0px, 레벨·잠금 사이8px, 아이콘과 중심 차이0px을 확인했다. 320px는 넘침 없이 다음 줄 조작부의 오른쪽 정렬을 유지한다. 소스33조건 반응형 검사를 통과했고 빌드 산출물 CSS 해시 일치를 확인했다. 화면 증거는 `.generated/scarecrow/target-strip-proof/right-aligned-1280-v38.png` 및390/320px 파일이다.


## v40: 목표 화면 상단에 두 프리셋 병렬 배치

목표 화면의 프리셋을 ‘장비 프리셋’과 ‘목표 프리셋’으로 명확히 구분하고, 부위 탐색 위에 나란히 배치했다. 장비 프리셋은 세팅·프리셋 탭에 저장한 장비·옵션을 가져오며, 목표 프리셋은 현재 목표 화면의 장비·목표 조건·비용 설정을 함께 저장·불러온다. 각 제목 아래에 차이를 설명한다. 하단 목표 프리셋 접기는 제거하고 이름·저장·삭제 조작도 상단 목표 프리셋에 모았다. 저장 형식이나 탭별 복사 규칙은 바꾸지 않는다.

좁은 화면이나 글자 확대에서는 두 영역을 위아래로 배치한다. 320/390/768/1024/1280px, 가로844×390, 320/1280px 글자200%, 기존 분기1101/1102/1103의33조건을 통과했다. 소스의 장비 목록 불러오기·목표 프리셋 저장/불러오기·다른 탭 불변·새로고침 회귀를 통과했다. `.generated/scarecrow/preset-toolbar-proof/1280.png`, `390.png`, `320.png`에 표시와 배치를 기록했다.


## v41: 목표 프리셋 제거, 비밀계약 세팅 불러오기

목표 프리셋 UI와 전용 저장·불러오기·삭제 경로를 제거했다. 과거 목표 프리셋의 localStorage 값은 삭제하지 않는다. 목표 화면에서 입력한 장비·옵션·목표 조건·대상 부위·비용 선택의 자동 저장은 그대로 유지한다. 별도의 목표 프리셋은 제공하지 않는다.

전사와 목표에서 장비 프리셋 영역의 이름을 ‘비밀계약 세팅 불러오기’로 통일했다. 세팅·프리셋 탭에서 저장한 세팅을 복사해 불러오는 동작과 원본·각 탭 데이터 분리는 유지한다. 목표의 두 칸짜리 영역은 제거하고 하나의 불러오기 영역만 상단에 둔다. 튜토리얼도 목표 프리셋 설명을 삭제하고 자동 저장과 세팅 불러오기를 안내한다.

소스33조건 반응형 검사(320/390/768/1024/1280px, 가로844×390, 320/1280px 글자200%, 기존1101/1102/1103)와 목표 프리셋 DOM 부재·새 명칭을 확인했다. 목표 프리셋 회귀는 목표 조건·귀속·비용 설정 자동 저장/새로고침과 타 탭 불변 검사로 바꿨다. 화면은 `.generated/scarecrow/preset-toolbar-proof/setting-import-v41.png`다.


## v42: 프리셋 완료 안내를 스낵바로 이동

비밀계약 세팅 불러오기 완료 안내를 본문에 남기지 않고4초 후 사라지는 스낵바로 표시한다. 세팅·프리셋 탭의 저장/불러오기/삭제 완료도 같은 방식이다. 연속 작업은 단일 안내를 갱신하고 타이머를 다시 시작한다. `role=status`, `aria-live=polite`로 안내하며 포커스를 이동하지 않는다. 포커스된 조작부와 겹칠 경우 상단으로 위치를 바꾼다. 새로고침에는 완료 안내를 복원하지 않는다. 선택 누락·저장 실패 오류와 실제 계산 결과는 기존 위치에 유지한다.

실제 Chrome에서 네이티브4초 타이머의 자동 종료/갱신, 본문 성공 문구 없음·불러오기 영역 높이 불변, 선택 누락 오류, 중복 스낵바 없음, 포커스 유지/조작부 겹침 없음, 새로고침을 확인했다. 320/390/768/1024/1280px, 가로844×390, 320/1280px 글자200%의8조건을 검사했다. 증거는 `.generated/scarecrow/snackbar-proof/`와 `.generated/test-snackbar.mjs`다. 기존 세 탭 독립·자동 저장·새로고침 회귀도 소스에서 통과했다.


## v43: 기존 토스트 공통 재사용

v42의 독립 스낵바 DOM·타이머·CSS를 제거했다. 보유현황의 기존 토스트를 [공통 토스트](toast.md)로 추출해 보유현황·파티 편성·비밀계약 시뮬레이터에서 함께 사용한다. 시뮬레이터의 프리셋 완료 안내도 공통 `MorimensToast.show`를 호출하며 기본2.6초 후 사라진다. 원본·타 탭 불변, 목표 자동 저장·새로고침 회귀 통과. 공유 기능과 목표 프리셋은 계속 제공하지 않는다.


## v44: 현재 UI 기준 튜토리얼 정리

안내를10단계로 정리했다: 세 탭 독립 → 비밀계약 편집·귀속 → 세팅 저장·덮어쓰기 → ‘비밀계약 세팅 불러오기’ → 잠금·전사 → 잔본/깃펜 스위치 → 교체 → 목표 옵션 아이콘·최소 레벨 → 결과·비용 → 자동 저장·공통 토스트·다시 보기.

제거한 목표 프리셋·공유 기능은 안내하지 않는다. 목표 옵션 단계는 실제 활성 부위의 아이콘을 강조하기 위해 ‘목표’ 보기를 열며, 종료/건너뛰기/Escape 후 원래 탭·현재/목표 보기·스크롤·포커스를 복원한다. 비밀계약 값·전사 미리보기·계산 결과는 바꾸지 않는다. 기존 완료 기록은 유지하고 `?`로 갱신된 안내를 다시 볼 수 있다.

검증 도구는 단계 수를 진행 표시에서 읽는다. 320/390/768/1024/1280px, 가로844×390, 320/1280px 글자200%에서10단계의 대상 노출·카드 경계·가로 넘침·대상과 겹침을 검사한다. ‘현재’ 보기와 전사 탭에서 시작해 전체 안내 후 상태 스냅샷이 같음을 확인하며 이전/Escape/재실행도 점검한다. 증거는 `.generated/scarecrow/covenant-onboarding-proof/`의 step6 비용 스위치와 step8 목표 아이콘 화면을 포함한다.


## v45–v47: 튜토리얼 독립 QA와 배경 스크롤 잠금

[레드팀·UI 검증 기록](ux-tests/covenant-tutorial-redteam-2026-11-15.md)에 발견과 수정·검사 범위를 정리했다. 전체 보기에서 직전 부위 기억이 사라지는 문제와 가로 화면에서 카드 내부 스크롤이 되돌아가 다음 버튼을 누를 수 없는 문제를 수정했다. 튜토리얼 중에는 배경 스크롤을 잠그고 긴 설명은 카드 안에서만 스크롤한다. 닫으면 기존 스타일·원래 탭·현재/목표 보기·스크롤·포커스를 복원한다. 확대 제스처는 차단하지 않는다. 저장 형식과 장비·전사·목표 값은 바꾸지 않는다.
