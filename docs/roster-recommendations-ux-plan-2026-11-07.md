# 보유 현황·성장 관리·추천 조합 UX 설계

작성: 2026-11-07. 이번 범위는 실제 조작을 바탕으로 한 분석과 설계다. 제품 코드 수정·배포는 포함하지 않는다.

## 1. 제품 방향

사용자의 질문은 두 가지다. “내 계정을 적은 노력으로 등록하려면?”과 “이 계정으로 어떤 조합을 참고하면 좋은가?”

등록의 기본 흐름은 **여러 캐릭터 선택 → 공통 성장 프리셋 적용 → 다른 캐릭터만 수정 → 내 조건으로 조합 탐색**이다. 모든 성장값을 입력해야 추천을 볼 수 있게 만들지 않는다.

시각 언어는 기존 사이트의 어두운 표면, 절제된 강조색, 초상화, 공통 필터·Dialog를 유지한다. 참고 사이트에서 가져오는 것은 작업 흐름과 정보 위계다.

## 2. 조사 방법과 근거

- [리버스 1999 캐릭터 메모장](https://www.reverse1999-simulator.com/ko/roster): 빈 상태, 개별 등록 Dialog, 저장, 두 캐릭터 일괄 스펙 적용, 내 가방, 팀 추천을 실제 조작했다. 모바일 백업 관리 펼치기와 JSON 다운로드를 실행했다. 다운로드한 테스트 파일을 불러올 때 교체 확인·되돌리기 안내까지 확인했다. 브라우저 도구의 파일 선택 상태가 남아, 복원 완료와 되돌리기 실행은 검증하지 못했다.
- [Eremora 클리어 검색](https://eremora.com/meta/dzone/clears): 골리아 포함·미리암 제외를 설정하고, 결과 갱신·URL 반영·추가 필터를 확인했다. 초기 4,933기록/1,854조합에서 해당 조건 25기록/24조합으로 좁혀졌고 Small sample 표시가 나타났다. 조사 시점 표본이며 현재값을 고정해 제품에 넣지 않는다.
- [Eremora 채용 통계](https://eremora.com/meta/dzone): 시즌·파·난이도, 상위 표본의 범위, 갱신 시점, 캐릭터·명륜 탐색 구성을 확인했다.
- 현재 로컬 `inventory_checker.html`: 전체 62명 선택 → 라모나 검색(2명) → 모두 해제를 조작하니 보유 수가 62→60으로 바뀌었다. 실제로는 현재 필터 결과만 해제한다.
- 외부 두 사이트의 추천/검색 화면을 320·390·768·1024·1280px에서 측정했으며 페이지 가로 넘침은 관찰되지 않았다. 리버스 추천 390px, Eremora 검색 390px과 데스크톱, 현재 사이트 1280px 스크린샷을 시각 확인했다. 전체 사이트의 접근성·반응형 인증은 아니다.
- 현재 사이트도 같은 다섯 너비에서 페이지 가로 넘침이 없음을 측정하고 390px을 시각 확인했다. 다만 390×844에서 첫 캐릭터 카드가 약 570px 아래에 시작한다. 제목·카운터·공유·필터가 목록보다 많은 첫 화면 공간을 차지하고, 떠 있는 제보 버튼이 우측 카드의 돌파 조작부 위에 겹쳐 보인다. 가로 넘침 없음이 조작 편의성을 보장하지 않는 사례다.

목록은 62명이나 현재 성장 데이터는 61명이다. 비비안의 성장 항목이 없다. 미등록 캐릭터를 숨기거나 다른 캐릭터의 상한으로 채우지 않고 “성장 데이터 준비 중”으로 둔다. 구현 전 원본 기반 보완이 필요하다.

## 3. 실제 조작에서 얻은 UX 판단

### 리버스: 적은 입력으로 등록하기

| 단계 | 관찰 | 장점 | 우리 사이트에 적용할 개선 |
|---|---|---|---|
| 첫 진입 | 등록/내 가방/팀 추천 탭, 빠른 등록 안내 | 등록의 목적과 다음 행동이 연결됨 | `각성체·명륜·추천 조합`으로 시작. 프리셋·백업은 보조 작업으로 배치 |
| 개별 편집 | 레벨·공명의 자주 쓰는 수치 버튼, 세부 입력, 저장 후 다음으로 | 반복 입력과 목록 왕복을 줄임 | 주요 단계 바로가기+정확한 숫자 입력, 저장 후 다음 캐릭터 |
| 기본값 | 처음 연 편집기에 레벨60·통찰III·공명15가 선택되어 있었음 | 숙련 유저는 빠르게 등록 | 실제 입력으로 오인하지 않도록 첫 등록에 프리셋 선택을 명시. 보유만 등록도 제공 |
| 다중 편집 | 2명 선택 후 스펙 적용 Dialog, 성급별 호환 범위 안내 | 적용 대상과 제한을 설명 | 필드별 변경 여부, 기존 값 유지, 미입력만 채우기, 적용 전 변경 요약 |
| 내 가방 | 보유율과 육성 요약·공유를 분리 | 편집과 감상/공유 목적이 명료 | 초기 버전은 보유/성장 등록 진행도만. 큰 통계판은 후순위 |
| 팀 추천 | 완성 가능/부분 가능, 부족한 메인, 대체 후보, 보유 캐릭터 필터 | 결과가 없어도 다음 육성 목표를 찾음 | 부족한 캐릭터·성장·장비와 연결. 검증된 대체만 표시 |
| 모바일 백업 | 닉네임·백업 관리 안으로 접힘 | 목록 면적 확보 | `백업·불러오기`로 명명. 닉네임 입력이 선행 조건처럼 보이지 않게 함 |
| 파일 작업 | 날짜가 있는 JSON 다운로드, 교체 확인과 되돌리기 안내 | 휴대성과 실수 복구를 지원 | 병합/교체 선택, 변경 미리보기와 이전 상태 복구 |

모바일 첫 관찰에서는 푸시 알림 배너와 하단 내비게이션이 함께 화면을 차지했다. 닫은 뒤 본 작업을 계속할 수 있었지만, 우리 보유 등록 첫 화면에서는 작업과 무관한 고정 배너를 추가하지 않는다.

### Eremora: 조건을 바꾸며 근거 탐색하기

| 단계 | 관찰 | 장점 | 우리 사이트에 적용할 개선 |
|---|---|---|---|
| 기본 필터 | 파·난이도는 바로 노출, 지원·추가 기록·랭크는 More filters | 자주 쓰는 조건부터 보임 | 시즌/파/난이도/내 보유 조건을 우선. 세부 조건은 활성 개수와 함께 접기 |
| 포함·제외 | Require/Exclude 모드 후 캐릭터 클릭, 선택칩과 URL 갱신 | 특정 캐릭터 조합 탐색이 쉬움 | `반드시 포함`·`제외`를 분리해 표시. 클릭 모드를 색상과 문구로 지속 표시 |
| 결과 묶기 | 같은 4인 조합을 묶고 대표 클리어 제시 | 중복 기록을 훑는 부담 감소 | 조합→실제 빌드→내 성장 비교 순서로 펼치기 |
| 표본 맥락 | 시즌/갱신 시점/수집 범위, 적은 결과에는 Small sample | 숫자의 범위를 이해 가능 | 필터 분모·기록 수·고유 유저 수·수집 시점 명시 |
| 모바일 | 난이도는 select, 캐릭터 선택기는 접힘 | 가로 넘침 없이 기능 보존 | 선택은 칩으로 요약, 필터 열기와 결과 이동 제공 |
| 모바일 슬롯 | 포함 캐릭터 1명이어도 빈 3슬롯이 세로 공간을 차지 | 4인 팀이라는 모델은 명확 | 미선택 슬롯은 작은 추가 버튼으로 압축, 결과를 더 빨리 보이게 함 |
| 비동기 갱신 | 선택 직후 이전 결과가 잠깐 보이다 갱신됨 | 조작을 막지 않음 | 갱신 중 상태 명시, 새 조건/이전 결과 혼동 방지, 최신 요청 결과만 적용 |

상위권에서 많이 쓰인 조합은 투자 효율이나 내 계정의 클리어를 보장하지 않는다. 채용률과 맞춤 적합도를 별도 값으로 표시한다.

## 4. 정보 구조와 화면 설계

### 상단 공통

```text
보유 현황                         [백업·불러오기]
각성체 48/62 · 성장 입력 31/48 · 이 기기에 저장됨
[각성체] [명륜] [추천 조합]
```

작업 종류를 탭으로 나누고 탭 안의 필터는 별도 행에 둔다. 장비 추가 시에만 명륜·비밀계약을 묶은 장비 관리로 확장한다. 초기에 탭을 과도하게 늘리지 않는다.

### 각성체 목록

```text
[이름 검색                           ]
[전체/보유/미보유] [영역] [역할] [획득 분류] [성장 미입력]
[일괄 편집] [성장 프리셋]

초상화 · 이름 · 보유 · 돌파
Lv.60 · 특성 10/12/5 · 카드 입력 6/6
[성장 편집]
```

- 보유 체크와 성장 편집은 서로 다른 동작이다. 카드 전체 클릭으로 보유를 해제하면서 편집 버튼도 함께 넣는 충돌을 피한다.
- 모바일 카드 요약에서는 특성 축을 아이콘만으로 구분하지 않는다. 전체 라벨과 수치는 성장 편집에서 읽을 수 있게 한다.
- `등록 완료`는 필요한 성장 항목이 실제 입력된 상태다. 보유 체크만 했으면 `성장 미입력`으로 표시한다.
- 기본 정렬은 기존 순서를 유지하되 영역/이름/돌파/입력 상태 정렬을 제공한다.
- 검색·필터는 편집 후 유지하고, 닫을 때 목록 위치와 포커스를 복구한다.
- 모바일 첫 화면은 제목/진행도→탭→검색/핵심 필터→목록 순서로 압축한다. 이미지 공유·초기화는 보조 메뉴로 옮기고, 상세 필터는 활성 조건 수를 표시하며 접는다. 떠 있는 제보 버튼은 카드·바텀시트·작업 표시의 터치 영역과 겹치지 않도록 배치한다.

### 일괄 편집

일괄 편집을 시작하면 일반 보유 체크가 편집 대상 선택으로 바뀐다는 안내와 체크 스타일을 제공한다. `현재 검색 결과 18명 선택`, `보유 48명 선택`, `선택 해제`처럼 범위를 이름에 넣는다. 보유 여부와 편집 대상 여부를 별도 상태로 둔다.

하단 작업 표시: `12명 선택 · 성장값 적용 · 보유 등록 · 취소`. 모든 페이지에 항상 고정하지 않고 이 모드에서만 표시하며 모바일 safe area·키보드·본문 마지막 항목을 가리지 않는다.

```text
12명 성장값 변경
성장 프리셋 [직접 설정 ▾]
돌파         [변경 안 함 ▾]
캐릭터 레벨  [변경 안 함 ▾]
영혼 단련    [직접 입력    ]
광기의 징조  [변경 안 함 ▾]
내재 영격    [변경 안 함 ▾]
스킬         [각 스킬 최대 ▾] [개별 슬롯 설정]

적용 방식 [미입력 항목만 채우기 / 지정 필드 덮어쓰기]
변경 요약: 12명 · 기존 값 변경 0건 · 빈 항목 입력 48건
[취소] [12명에게 적용]
```

- 숫자 0과 변경 안 함을 구분한다. 특성 0은 실제 미육성일 수 있다.
- 각 스킬 최대는 캐릭터·슬롯별 상한을 해석한다. 모든 카드에 같은 숫자를 복사하지 않는다.
- 상한 초과·해금 미충족·자료 누락은 대상별 요약 후 명시적으로 제외한다. 몰래 숫자를 낮추지 않는다.
- 목록 필터 변경으로 화면에서 사라진 선택이 있으면 선택 수와 숨은 대상 수를 표시한다.
- 적용 직후 되돌리기와 변경 전 스냅샷을 제공한다. 전체 초기화는 이 작업과 떨어진 보조 메뉴로 옮긴다.

### 개별 성장 편집

데스크톱 Dialog, 모바일 바텀시트에 동일한 순서와 기능을 제공한다.

1. 초상화·이름·보유 상태.
2. 레벨, 한계 돌파/해금 단계, 계령(유저 표시 돌파) 등 서로 다른 성장축.
3. 영혼 단련·광기의 징조·내재 영격 각각의 단계.
4. 실제 스킬 이름과 슬롯별 레벨. `전체 카드 같은 단계`, `슬롯별 최대` 빠른 입력.
5. 저장·취소·저장 후 다음으로. 변경 사항이 있으면 실수로 닫을 때 보존/폐기를 선택.

입력 범위는 원본 데이터로 산출한다. 라모나 샘플은 특성 최대가 각각 10/12/5이고 기본 타격·방어 최대는 6으로 확인했지만, 이 숫자를 모든 캐릭터 규칙으로 하드코딩하지 않는다.

## 5. 프리셋과 계정 데이터

### 성장 프리셋

숫자 묶음과 “변경 안 함/최대” 규칙이다. 예: `카드만 최대`, `주력 특성`, `내 기본 육성`. 생성·이름 변경·복제·삭제를 지원한다. 적용 전 대상과 실제 해석된 값 요약을 보여준다.

기본 제공은 `보유만 등록`, `카드만 최대`, `선택한 성장축 최대`. 근거 없는 “표준 육성” 수치나 보유 캐릭터 전원 풀돌을 기본값으로 정하지 않는다. 돌파와 보유는 프리셋 적용 시 기본적으로 유지한다.

### 계정 백업

전체 보유·성장·명륜·사용자 프리셋을 저장하는 JSON이다. 이미지 공유와 다른 행동으로 이름을 붙인다. 파일명에 날짜를 넣고, 불러오기에서 대상 수·변경 수·미지원 항목을 먼저 보여준다.

- 병합: 충돌 없는 항목 추가, 기존 값 유지 또는 선택 필드 덮어쓰기.
- 교체: 적용 전 자동 백업, 교체 범위 확인, 되돌리기.
- 오류: 잘못된 버전/형식/상한이면 기존 데이터 유지. 알 수 없는 ID는 조용히 삭제하지 않고 보류 목록으로 보고한다.
- 첫 버전은 활성 계정 1개와 여러 성장 프리셋. 다중 계정·클라우드 동기화는 다음 단계로 둔다.
- 미래 육성 목표는 실제 보유와 분리한다. 목표 프리셋을 적용한 시뮬레이션은 가상 설정임을 표시한다.

## 6. 추천 조합

### 기본 탐색 화면

```text
[추천 조합] [채용 통계]
[시즌 ▾] [파 ▾] [난이도 ▾] [내 보유 적용]
반드시 포함 [캐릭터 추가]   제외 [캐릭터 추가]
[지원 1명 허용] [성장 비교] [상세 필터 · 2]
적용 조건 칩… [초기화]

내 보유 48명 적용 · 성장 미입력 17명
24개 조합 / 76개 기록 · 수집 시점 …

4인 초상화 + 이름
캐릭터 4/4 보유 · 성장 비교: 1명 정보 부족
이 시즌·파의 클리어 N건 · 고유 유저 M명 · 턴 범위
부족/미확인 요약
[실제 빌드 보기] [내 성장과 비교] [ScareCrow로 열기]
```

추천 조합 안에서 `실전 기록`과 `운영자 추천`의 출처를 명시적으로 전환한다. 합성 데모에는 데모 배지를 유지하고 실제 통계·기록 수에 합산하지 않는다. 운영자 추천의 대체 후보를 실전 검증처럼 표시하지 않는다.

### 내 계정과의 비교

판정은 분리해서 전달한다.

| 비교축 | 표시 예 |
|---|---|
| 캐릭터 | 전원 보유 / 지원 1명 필요 / 2명 미보유 |
| 성장 | 선택 기록보다 낮은 항목 2개 / 동일 이상 / 정보 부족 |
| 장비 | 명륜 1개 미보유 / 강화·수량 정보 미입력 / 계약 비교 미지원 |
| 근거 | 실제 기록 N건 / 운영자 추천 / 데모 |

실전 빌드의 성장값은 관측값이다. 해당 캐릭터의 필수 최저 성장 요구치로 간주하지 않는다. `성장 조건 충족`보다 `이 기록과 성장 비교`라는 문구를 사용한다. 성장 미입력 유저는 캐릭터 보유 기준으로 탐색을 계속할 수 있다.

지원 허용은 명확한 1개 슬롯으로 판정한다. 여러 미보유 캐릭터·장비를 한 지원 캐릭터로 동시에 해결한다고 처리하지 않는다. 명륜 소유 여부만 알고 수량/동시 장착 규칙을 모르면 장비 완비를 확정하지 않는다.

기본 정렬은 계정과의 일치도·부족 항목 수를 먼저, 동일 그룹 안에서 해당 조건의 고유 유저/클리어 근거를 제시한다. 임의의 0~100 적합도나 클리어 확률을 만들지 않는다. 계정 미등록 상태는 인기 조합과 등록 유도, 기록이 없는 상태는 미수집/조회 실패와 구분한다.

결과 0건에서는 현재 조건을 보존하고 `성장 비교 완화`, `지원 1명 허용`, `파 전체로 확대`의 예상 결과를 제안한다. 조건을 자동으로 바꾸지 않는다.

### ScareCrow 연결

`기록 빌드로 열기`와 `내 성장으로 바꿔 열기`를 선택 가능하게 한다. 변경 요약과 누락된 장비/성장을 보여주고 시뮬레이터에서 확인 후 적용한다. 기존 계정을 기록값으로 덮어쓰지 않는다.

본 사이트와 ScareCrow는 다른 Origin이므로 localStorage를 공유한다고 가정하지 않는다. 버전 있는 JSON 또는 URL fragment의 검증 가능한 전달 어댑터를 사용한다. 필수 입력 누락을 임의 최대값으로 채우지 않는다.

## 7. 데이터와 구현 경계

- 공통 보유 모델을 별도 모듈로 두고 보유 현황·추천·기록·ScareCrow 어댑터가 같은 계약을 사용한다. UI마다 저장값을 독자 해석하지 않는다.
- 기존 `morimens_inventory_checker_v2`를 읽어 보유와 돌파를 보존한다. 신규 필드는 null(미입력)로 마이그레이션하고 구버전 읽기·복구를 테스트한다.
- 캐릭터 사이트 ID/원본 ID, 특성 원본 ID와 타입, 카드 슬롯·스킬 ID로 연결한다. 한국어 이름만으로 매칭하지 않는다.
- 특성의 서버 행 번호, UI 단계, 해금 요구값을 분리해 변환한다. 그대로 복사해서 레벨이라고 해석하지 않는다.
- 필드별 출처(직접 입력/프리셋/가져오기)와 수정 시점을 보존한다. 과거 전투 기록을 현재 계정 성장으로 자동 적용하지 않는다.
- 보유 해제 시 성장 기록은 보존하고 다음 등록 때 복구한다. 실제 데이터 삭제는 별도 작업으로 둔다.
- 공유 URL은 검색 조건 중심으로 구성한다. 전체 계정 성장은 사용자가 내보내기를 선택한 경로로 전달한다.

## 8. 단계별 구현과 완료 조건

1. **보유 관리 기반**: v2 마이그레이션, 특성·카드 단계/상한, 개별 편집, 다중 편집, 프리셋, 백업·복원. 기존 보유·돌파·명륜 손실 없음과 되돌리기 검증.
2. **맞춤 조합 탐색**: 두 브랜치의 역할을 구분해 재사용, 포함/제외·지원·보유 조건, 조합 그룹과 근거, 부족/미입력 비교. 실제 데이터와 데모 격리 검증.
3. **ScareCrow 연결**: 성장값·카드 슬롯 정확한 전달, 기록/내 성장 전환, 누락값 처리, 확인 후 적용.
4. **후속**: 검증된 대체 캐릭터, 다중 계정, 장비 세부·육성 목표, 선택적 동기화.

실사용 검증 시나리오:

- 62명 보유자는 전체 선택 후 프리셋 1회, 예외 3명만 개별 편집할 수 있다. “필요한 조작 수”를 실제 UI로 측정한다.
- 초보자는 보유만 등록해 조합을 보고, 성장 미입력 때문에 결과 전체가 사라지지 않는다.
- 기존 사용자 값은 “변경 안 함/빈칸만”으로 보존된다. 필터 결과/전체 보유 선택 범위가 구분된다.
- 계정 파일의 병합·교체·오류·되돌리기와 구버전 마이그레이션을 검증한다.
- 특성·스킬 상한, 원본 ID 매핑, 지원 1명, 동일 장비 수량, 결측 데이터 판정을 검증한다.
- 320·390·768·1024·1280px 및 실제 변경 breakpoint ±1px, 가로 화면, 200% 텍스트 확대에서 조작·포커스·Dialog·고정 작업 표시를 확인한다. 구현 전 설계만으로 통과를 선언하지 않는다.

## 9. 설계 결론

우선 구현할 핵심은 기능 수가 아니라 **등록 비용을 줄이는 일괄 성장 편집**과 **추천 이유·부족 항목을 설명하는 결과**다. 프리셋으로 입력량을 줄이고, 미입력 상태를 정직하게 보존하며, 실제 기록을 내 계정에 맞춰 비교하는 흐름을 하나로 연결한다.
