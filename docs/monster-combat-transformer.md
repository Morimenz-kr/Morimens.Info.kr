# 몬스터 전투 데이터 변환기

이 문서는 일반·엘리트·보스 몬스터가 함께 사용하는 전투 데이터 변환 규칙과 출력 구조를 정의한다. 첫 회귀 표본은 융재금구 5파 보스 `MonsterConfig 148007`, `「혼을 거두는 자」`다.

## 변환 원칙

- `MonsterConfig`의 TID를 몬스터 템플릿의 식별자로 사용한다. 같은 TID는 출전 장소가 달라도 같은 패턴·스킬·상태 그래프를 공유한다.
- 스테이지나 경계도에 따라 달라지는 `StandardHp`, `StandardAtk`, `StandardDef`, `StandardTurn`은 전투 컨텍스트로 분리한다.
- 이름과 설명은 `Text_KR`의 인게임 문구를 그대로 사용한다. 문장 종결 변경, 안내문 추가, 의미 요약을 하지 않는다.
- `Arg1`, `BattleAtkForce`, `CmdCaster.max_hp`처럼 계산 가능한 값은 전투 컨텍스트의 실제 수치로 치환한다.
- 현재 HP, 상태 스택처럼 실행 중에 달라지는 값은 임의로 확정하지 않는다. 기본 사례의 계산값과 함께 `dynamic: true`, `dependencies`를 남긴다.
- `1페이즈`, `조건부 행동`, `전투 시작` 같은 분류명은 출력 데이터의 구조를 탐색하는 라벨이다. 인게임 설명문 안에 삽입하지 않는다.
- 모든 결과는 원본 테이블명과 ID를 `source` 또는 `evidence`로 보존한다.
- 해석할 수 없는 수식은 문구를 만들어 대체하지 않고 `diagnostics`에 기록한다.
- 몬스터 조건식을 판정하기 전에 `StageGroup.StageChapterState → State → Cmd`를 따라 단계 컨텍스트를 합성한다. 화면에 숨겨진 단계 상태 자체는 노출하지 않지만, 그 상태 때문에 확정되는 실제 스킬과 발동 시점은 표시한다.
- 단계 컨텍스트로 거짓이 된 대체 분기는 표시하지 않는다. 이 판정은 파동 번호·몬스터명·한국어 효과명을 하드코딩하지 않고 상태 ID 참조와 조건식으로 수행한다.

## 처리 흐름

```text
MonsterConfig TID
  ├─ 패턴: InitSkillList, CycleSkillListN
  ├─ 초기 상태: ExistState
  └─ 능력치 계수
        │
        ▼
Skill → Cmd → State/Skill 참조 그래프
        │
        ├─ 몬스터 템플릿: 장소와 무관한 원본 규칙
        └─ 전투 컨텍스트: 스테이지 표준 능력치와 런타임 값
                    │
                    ▼
             실제 수치가 포함된 전투 결과
```

단계에 따라 조건부 행동이 바뀌는 경우에는 다음 참조를 추가로 결합한다.

```text
StageGroup.StageChapterState
  → 숨은 State의 즉시 TriggerCmd
  → 전투 시작 시 부여되는 State
  → 몬스터 State의 Judgement/Cond 판정
  → 현재 단계에서 실제로 가능한 의도만 출력
```

## 공개 함수

### `buildMonsterTemplate({ monsterId, tables })`

다음 원본 테이블을 받아 장소와 무관한 몬스터 템플릿을 만든다.

- `MonsterConfig`
- `Skill`
- `Cmd`
- `State`
- `Text_KR.Text_MonsterConfig`
- `Text_KR.Text_Skill`
- `Text_KR.Text_State`

출력에는 패턴 목록, 참조된 스킬과 상태, 체력바 전환, 조건부 의도 교체, 참조 근거가 포함된다.

### `calculateEncounterStats(template, standard)`

스테이지 표준 능력치와 몬스터 계수를 결합해 HP·공격·방어의 실제 수치를 계산한다. 계산에 사용한 원본 표준 수치와 공식도 함께 반환한다.

### `buildStageContext({ stageGroupId, tables })`

`StageGroup`의 단계 상태에서 전투 시작과 동시에 부여되는 상태를 명령 그래프로 추적한다. 숨은 상태도 조건 판정용 `stateLayers`에 포함하되, 표시용 설명으로 만들지는 않는다.

### `resolveContextualActions(template, { stageContext, tables })`

단계 컨텍스트를 몬스터의 조건부 의도 교체식에 대입한다. 활성 분기의 최초 발동 턴과 지속 여부를 계산하며, 남은 조건을 해석할 수 없으면 임의 문구 대신 진단을 반환한다.

### `resolveMonsterEncounter(template, context)`

템플릿에 전투 컨텍스트를 적용한다. 주요 출력은 다음과 같다.

| 필드 | 의미 |
|---|---|
| `stats` | 해당 전투의 HP·공격·방어 |
| `hpPhases` | 체력바별 최대 HP |
| `effectiveHp` | 모든 체력바의 합 |
| `skills` | 첫 체력바 기준 치환 결과 |
| `phaseSkills` | 체력바별 최대 HP를 반영한 치환 결과 |
| `transitions` | 부활·최대 HP 변경·스킬 목록 변경 등의 전환 |
| `conditionalActions` | 조건을 만족할 때 발생하는 의도 교체 |
| `diagnostics` | 변환하지 못한 식과 원인 |

## 조건부 의도 교체 표시 규칙

기본 순환 행동이 특정 조건에서 다른 의도로 교체되는 경우에는 다음 규칙을 공통으로 적용한다.

1. 의도 변경 명령의 조건식에서 현재 의도 또는 원본 스킬 ID를 추출해 `sourceSkillId`로 보존한다. 교체 대상은 `skillId`로 보존한다. 몬스터 ID, 파동 번호, 스킬 이름 또는 번역문으로 두 스킬의 관계를 판정하지 않는다.
2. 원본 행동에는 교체 조건과 교체 결과를 남긴다. 예를 들어 특정 상태 스택을 보유하면 다른 의도로 교체되고, 그렇지 않으면 상태를 얻는다는 분기는 원본 행동의 설명에 포함한다.
3. 교체 대상 행동의 피해·상태·회복 효과는 원본 행동 설명에 다시 펼치지 않는다. 같은 효과가 원본 행동과 교체 행동에 중복되면 참조 그래프를 기준으로 원본 행동의 내장 효과 절만 제거한다.
4. 교체 대상 행동은 관련 페이즈의 기본 행동 목록 뒤에 한 번만 출력한다. 여러 원본 행동이나 조건이 같은 교체 스킬을 가리키면 스킬 ID와 조건 참조를 기준으로 중복을 제거한다.
5. 교체 대상은 기본 순환의 다음 순번이 아니므로 순번을 부여하지 않는다. 화면에서는 `조건부 의도`처럼 구조를 설명하는 별도 구역에 일반 행동과 같은 아이콘·이름·설명 형식으로 표시한다.
6. 조건부 의도 행을 기본 행동의 순번 열에 억지로 맞추지 않는다. 빈 순번 자리, 연결 화살표 또는 별도의 강조 상자를 만들지 않고 아이콘과 설명이 사용 가능한 영역에서 자연스럽게 시작하게 한다.
7. 교체 조건을 현재 전투 컨텍스트로 확정할 수 없더라도 행동 자체를 누락하지 않는다. 해석 가능한 조건은 실제 수치로 표시하고, 해석 불가능한 부분은 `diagnostics`에 근거와 함께 남긴다.

이 규칙은 특정 보스 전용 예외가 아니다. `현재 의도 판정 → 조건 확인 → 다른 스킬로 교체` 관계가 명령 그래프에서 확인되는 일반·엘리트·보스 몬스터에 동일하게 적용한다.

## 패턴 개입 상태 표시 규칙

기본 순환 도중 즉시 행동을 발생시키는 상태도 별도의 해설 카드로 분리하지 않는다.

1. 초기 상태의 `TriggerCmd`와 `TriggerPara`에서 시작해 숨은 상태와 공용 명령의 `ArgN` 전달을 계속 추적한다.
2. 즉시 행동을 발생시키는 상태에는 그 상태를 생성한 표시 상태의 ID를 `sourceStateIds`로 보존한다.
3. 화면에서는 개입 상태를 `sourceStateIds`가 가리키는 특수 규칙 바로 다음에 같은 세로 규칙 형식으로 출력한다. 원본 상태를 확정할 수 없는 경우에만 특수 규칙 목록의 마지막에 둔다.
4. `패턴 개입`, `기본 순환에 끼어듦` 같은 변환기 해설 문구는 표시하지 않는다. 상태 이름과 인게임 설명만 사용한다.
5. 별도 강조 상자나 독립 구역을 만들지 않는다. 원인이 되는 상태와 결과 상태의 관계는 목록 순서로만 표현한다.

이 규칙 역시 상태명이나 번역문을 대조하지 않고 상태·명령 ID의 참조 관계로 적용한다.

## 148007 회귀 기준

이 표본에서 변환기는 다음 내용을 반드시 보존하거나 계산해야 한다.

- 1번 순환: `148362 → 148361 → 148362 → 148365`
- 2번 순환: `148362 → 148360 → 148362 → 148365`
- 첫 체력바 소진 시 최대 HP가 기본값의 1.5배가 되는 두 번째 체력바
- 전환 직후 의도 `148393`, 스킬 목록 2번, 상태 `148020`
- `Arg1==148362 and UpperTarget.GetStateLayer(148383)==4`일 때 스킬 `148364`로 교체
- 상태 `148395`의 인게임 이름 `영혼을 거두리-피에 굶주린 철구`
- `피에 굶주린 철구`의 출혈 스택 의존 피해와 현재 손실 HP 의존 회복량

경계도 4의 표준 수치를 적용하면 HP는 `18,185,348`, 공격은 `3,005`, 방어는 `63,117`이다. 두 번째 체력바는 `27,278,022`, 유효 총 HP는 `45,463,370`이다.

## 명령행 사용

템플릿만 생성할 때:

```powershell
node tools/generate-monster-combat.mjs --raw <추출-데이터-디렉터리> --monster 148007 --out .generated/monster-148007.json
```

전투 수치까지 계산할 때 `--standard`에 JSON 문자열 또는 JSON 파일 경로를 준다.

```powershell
node tools/generate-monster-combat.mjs --raw <추출-데이터-디렉터리> --monster 148007 --encounter wave-5-alert-4 --standard '{"StandardHp":30308911.67,"StandardAtk":3338.4,"StandardDef":631172.67,"StandardTurn":12}' --out .generated/monster-148007-alert-4.json
```

`--runtime`에는 선택적으로 현재 HP, 플레이어 HP, 상태 스택 같은 실행 중 값을 JSON으로 전달할 수 있다. 전달하지 않은 동적 값은 의존성이 표시된 기본 사례로 남는다.

## 현재 적용 범위

공용 변환 모듈과 대표 표본 회귀 테스트까지 구현되어 있다. 기존 융재금구 및 스토리 화면은 아직 이 모듈로 교체하지 않았다. 화면 교체는 각 페이지의 기존 출력과 공용 결과를 비교한 뒤 별도 단계로 진행한다.
