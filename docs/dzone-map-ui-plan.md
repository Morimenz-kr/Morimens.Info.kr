# 융재금구 노드 지도 UI 구현 계획

## 목표

진행 중인 융재금구 정보 페이지에서 선택한 파의 실제 노드 배치를 먼저 살펴보고, 전투 노드를 선택해 해당 전투 정보를 바로 확인할 수 있게 한다. 지도는 패치 데이터의 육각 격자 좌표와 노드 효과를 사용하며, 게임 화면처럼 살짝 눕혀 보이는 타일 보드로 표현한다.

## 사용자 흐름

1. 사용자가 파와 난이도를 선택한다.
2. 선택한 파의 노드 지도가 전투 정보 위에 표시된다.
3. 모든 노드는 추출한 석재 타일과 실제 노드 문양으로 종류를 구분한다.
4. 전투·엘리트·최종전 노드는 버튼으로 동작한다. 선택하면 대응하는 전투 상세가 열리고 화면이 그 카드로 이동한다.
5. 나머지 노드는 지도 구조를 이해하기 위한 비활성 타일로 표시한다.
6. 긴 전투 정보를 읽은 뒤 우측 하단의 `맨 위로` 버튼으로 페이지 시작점에 돌아간다.
7. 실전 편성 통계는 제목 행에서 필요할 때 접거나 다시 펼친다.

## 데이터 설계

- 지도 원본: `Config.Map`의 현재 시즌 `mapId`별 `data_list`
- 노드 원본: `Config.MapNode`
- 5파의 시작 왼쪽 경로는 화면 검증 결과에 따라 `시작 → 전투 → 불안정한 바닥 → 일반 노드 → 녹슨 열쇠` 순서로 표시한다. `Config.Map`에서 빠진 일반 노드 한 칸은 지도 보정 데이터로 생성한다.
- 독가스 바닥은 추출한 보라색 그리드 텍스처를 사용하고 아이콘을 겹치지 않는다. 불안정한 바닥은 별도 평면 텍스처가 없어 추출한 돌 바닥과 균열 문양을 합성한 바닥 이미지를 사용한다.
- 좌표: 행 번호와 `OddXaxis`·`EvenXaxis` 열 번호를 보존한다.
- 전투 연결: 전투 계열 노드의 `Effect[1]` 전투 ID를 `dzone_current.json`의 `encounters[].battleId`와 연결한다.
- 지도 표시 데이터는 공개 사이트에 필요한 필드만 `data/dzone_maps.json`에 둔다.
  - 파, 맵 ID
  - 행·열 좌표
  - 노드 ID, 표시 이름, 아이콘, 유형
  - 전투 노드의 전투 ID
- 원본 패치 파일 경로나 추출 도구 정보는 공개 데이터에 넣지 않는다.

## 시각 구현

- 바닥은 추출한 `munit_grid_m0015` 텍스처를 웹용 이미지로 정리해 사용한다.
- 노드 문양은 추출한 `munit_event_*` 이미지를 필요한 종류만 복사한다.
- 육각 타일은 인접 좌표끼리 모서리가 맞닿도록 절대 좌표로 배치한다.
- 타일 표면은 세로축을 줄여 원근감 있게 눕히되, 지도 전체를 회전시키지 않는다.
- 아이콘과 한글 이름은 타일보다 덜 눕혀 가독성을 유지한다.
- 선택 가능한 전투 노드에는 청록색 테두리, hover·focus·selected 상태를 제공한다.
- 최종전은 붉은 문양으로 구분한다.
- 시작 노드는 인게임 표시처럼 별도 문양 없이 타일과 이름만 표시한다.

## 반응형 동작

- 지도는 고유 크기를 유지하고 지도 컴포넌트 안에서만 가로 스크롤을 허용한다.
- 모바일에서는 선택된 노드가 보이도록 지도 내부 스크롤 위치를 조정한다.
- 페이지 자체에는 가로 스크롤이 생기지 않게 한다.
- 전투 노드 버튼과 맨 위로 버튼은 최소 44×44px 터치 영역을 확보한다.
- 200% 텍스트 확대에서도 노드 이름과 조작 기능을 잃지 않게 한다.
- `prefers-reduced-motion`에서는 자동 이동을 즉시 수행한다.

## 접근성

- 지도는 설명이 있는 `section`과 노드 목록 의미를 갖는다.
- 전투 노드는 실제 `button`으로 구현하고 전투 종류와 순서를 접근 가능한 이름에 포함한다.
- 비전투 노드는 버튼처럼 보이거나 포커스를 받지 않는다.
- 선택된 전투 노드는 `aria-pressed`로 상태를 알린다.
- 지도 선택 뒤 전투 상세 제목에 포커스를 옮겨 키보드 사용자가 위치를 잃지 않게 한다.
- 맨 위로 버튼은 스크롤이 내려갔을 때만 표시하며 명확한 접근 가능한 이름을 제공한다.
- 실전 편성 통계는 네이티브 `details`와 `summary`를 사용해 키보드와 보조기기에서 상태를 전달한다.

## 구현 순서

1. 현재 시즌 1~5파의 공개 지도 데이터 생성
2. 추출 타일과 노드 문양을 배포용 이미지로 변환·배치
3. 지도 렌더링과 전투 ID 연결 구현
4. 지도·선택·스크롤·맨 위로 버튼 스타일 구현
5. 실전 편성 통계를 접을 수 있는 공개 영역으로 변경
6. 전투 카드 앵커와 선택 상태 연결
7. 데이터 관계 및 DOM 동작 테스트 추가
8. 브라우저에서 모바일·태블릿·데스크톱 및 200% 확대 검증

## 완료 기준

- 1~5파에서 패치 데이터의 벽 제외 노드 수와 화면의 노드 수가 일치한다.
- 인접한 좌표의 타일이 끊어진 선 없이 육각 보드처럼 맞닿는다.
- 모든 전투 계열 노드가 정확한 `battleId`의 전투 카드를 열고 이동한다.
- 비전투 노드는 클릭 동작을 갖지 않는다.
- 파 변경 시 지도와 전투 상세가 함께 갱신된다.
- 맨 위로 버튼이 우측 하단에서 동작하고 기존 제보 버튼을 가리지 않는다.
- 실전 편성 통계를 제목 행으로 접고 펼칠 수 있으며 내부 탭과 링크가 그대로 동작한다.
- 320, 360 또는 390, 768, 1024, 1280px에서 기능·가독성·오버플로를 확인한다.
- 노드는 108×81px 크기를 데스크톱과 모바일에서 공통으로 유지한다. 모바일에서는 지도 영역만 좌우로 스크롤하여 54px 아이콘의 식별성과 전투 노드의 터치 영역을 보존한다.
- 변경된 경계값의 바로 아래와 위, 200% 텍스트 확대, 키보드 포커스를 확인한다.
